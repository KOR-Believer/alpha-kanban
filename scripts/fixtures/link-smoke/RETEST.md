# Windows 재검사

이 ZIP만 새 폴더에 풀면 된다. Git branch를 push/pull하거나 Alpha Kanban 소스·pnpm을 설치할 필요는 없다. Node.js 24 이상·Git·Chrome은 필요하다. 기존 결과와 연결을 보존하려면 이전 검증 폴더를 덮어쓰지 않는다.

1. 압축을 푼 폴더에서 `node native-cli.mjs`를 실행한다. **10/10 통과**가 기대 결과다. 결과 파일은 `native-cli-win32.json`이며, 중단 후 이어 하기·되돌리기도 포함한다.
2. `README.md`의 전용 Chrome 프로필과 서버로 앱을 열어 `fixtures`를 연결한다. Mac 동료 링크를 `renamed-product`에 연결한 뒤, **로컬 폴더 → 링크 연결 → 연결 변경**을 연다. 후보에는 실제 대상 폴더 이름/상대경로가 보여야 하고, 대상 후보에 원본 프로젝트 이름인 `remote-docs`가 표시되면 실패다. 저장 후 연결 목록의 원본 프로젝트는 계속 `remote-docs`여야 한다. `second-checkout`으로 바꾸는 경우도 같은 기준으로 확인하고 올바른 연결로 복원한다.
3. 아직 저장하지 않은 연결 창에서 원래 폴더·대상 폴더·검색어를 선택해 둔다. 같은 테스트 프로필의 두 번째 앱 탭에서 언어와 테마를 바꾼다. 첫 탭으로 돌아왔을 때 선택과 검색어가 남아 있어야 한다. 취소하면 연결은 저장되지 않아야 한다.
4. Chrome이 폴더별 접근 해제 UI를 제공하면 테스트 대상 폴더 **한 개만** 해제한다. 해당 링크가 다른 checkout으로 바뀌지 않고 재승인/재선택을 요청하는지 확인한다. 폴더별 해제가 제공되지 않으면 미검증으로 적는다. 사이트 전체 파일 편집 권한 해제와 구분한다.
5. `node verify.mjs`를 실행해 **32/32 보존**을 확인한다. CLI 결과·보존 결과와 2~4번 관찰 결과를 전달한다.

기존에 통과한 A/B 4개·Git 경계 8개·업데이트·재시작 전체 흐름을 이번 수정만으로 다시 실행할 필요는 없다. 모든 조작은 테스트 프로필과 테스트 사이트에서만 수행한다.
