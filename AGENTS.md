# Agent Notes

## Browser Smoke

- Prefer the Chrome plugin first for visual smoke checks, layout review, and cursor/mouse feedback.
- Use the in-app browser only when Chrome is unavailable, blocked, or the task specifically targets the Codex in-app browser.
- Use Playwright CLI when a repeatable browser flow, DOM assertion, or scripted interaction is needed.
- Keep Playwright snapshots short. Avoid dumping large accessibility snapshots when the page has long project or ticket lists.
- For visual-only checks, use a screenshot or browser inspection summary instead of raw snapshot output.

## Implementation Ledger Markdown

- Use the bundled `skills/implementation-ledger` skill as the operating protocol for creating or updating plan, ticket, and inventory documents.
- Prefer the repo-local `pnpm ticket-md` helper when changing ticket status, progress, `Completed at`, `사용자 지시`, or `진행 메모`.
- Use `pnpm ticket-md show <file> <ticket-id>` before editing an existing ticket so the exact ticket range is known.
- Use `pnpm ticket-md status`, `pnpm ticket-md append-user`, and `pnpm ticket-md append-note` for canonical ticket mutations. These commands update only the located ticket body and top-level `현재 진행률`.
- Run `pnpm ticket-md check <file>` after ticket document edits.
- Run `node skills/implementation-ledger/scripts/check-ledger.mjs <file>` when creating a new canonical ticket document or validating strict Alpha Kanban compatibility.
- Manual `apply_patch` edits are acceptable for non-canonical prose or checkbox changes, but keep them inside the inspected ticket range and re-run `pnpm ticket-md check`.
- Do not resurrect legacy Progress Board sections. Ticket body fields are the canonical source of truth.

## Document-First Workflow

- The product is a browser-only Markdown workspace. Do not restore backend endpoints, embedded chat, or agent runners. Existing ignored on-disk history is not application source and must not be deleted during code cleanup.
- The visible UI edits Markdown, not agent sessions. Ticket directions and status-change reasons append to `사용자 지시`; saving them must not launch Codex or write agent-authored `진행 메모`.
- Keep status/progress/completion-time/count changes and their reason in one guarded file update. Preserve previous checklist evidence and notes on reopen, and retain stale-file protection.
- Status changes with an empty reason use the shared user-authored default message. Free text uses `[수동지시]`; do not restore the record-type selector. Drag/drop requests confirmation and saves before moving a card, using the same status form and captured file guard.
- Interpret structured user records using the bundled skill's `references/ledger-format.md`. For an assigned ticket, read the latest directions instead of assuming an earlier DONE result still applies.
- Update the bundled skill for this workflow; do not overwrite the user's separately installed skill as part of application changes.

## UI Localization

- Korean is the default UI language; English remains selectable through the shared `LanguageSelector`. Persist only this display preference in `alpha-kanban.locale`, independently of workspace selection and document state.
- Keep UI copy in `apps/web/src/i18n/messages.ts` and use `useTranslation` in React components. English source strings are keys; translate complete sentences with interpolation instead of concatenating fragments. Translate accessibility labels, tooltips, empty/loading/error states, and format dates/numbers with the selected locale too.
- Translate status/type labels only at display boundaries. Keep API values, Markdown canonical fields, ticket IDs, document content, user input, paths, commands, and provider output unchanged. Shared default status-change reasons are document content and remain the exact text the writer will append.
- Do not translate at module initialization or store localized text as identifiers. Language switching must not remount forms, discard drafts, change routes, or write Markdown. Add both language entries and extend localization tests for new UI copy.

## Browser-Only Application

- `pnpm dev`, `pnpm build`, and `pnpm preview` run/build/serve the browser app. The `:browser` names remain aliases. Keep dev port 5187, preview port 4187 and `apps/web/dist-browser` stable; changing origins separates users from their saved folder connections/settings. Node is build/development tooling, not an application API server.
- Use `apps/web/src/browser/repository.ts`, not API endpoints, health polling, SSE, or Codex runner calls. The shared Markdown parser and writer live in `packages/shared/src/ticketMarkdown.ts`, with parser and mutation tests in `packages/shared/test`. Keep document compatibility and preservation coverage independent of filesystem adapters.
- Persist directory handles and opaque document IDs in IndexedDB. Do not synthesize absolute paths or infer physical identity from names. URLs carry opaque document IDs, and reconnect must retain the requested route.
- Keep the hash/mtime guard, per-document Web Lock, durable recovery preimage, close/readback verification and stale-order check. Never retry an uncertain append automatically. Web Locks do not exclude external editors.
- Keep document identity lookup indexed by path; resolve existing handles once per scan for moves/overlapping connections instead of comparing every new file to every stored document. The all-projects board reads ticket bodies only, rechecks known tickets between discovery scans, and publishes partial loading results without replacing a completed board during background refresh. Cached listings are never write guards.
- Open a selected document by its persisted ID without waiting for sidebar discovery. Observe that document independently; sidebar queries recheck known file metadata and discover new paths at most once per minute (or after explicit refresh/connection changes), not on every document observation. Sidebar loading or failure must not hide an already available document.
- Permission prompts belong to explicit user actions. Browser-local tests using fake handles or OPFS do not establish real OS folder permission/restart behavior.
- Markdown relative resources resolve only under a granted project. External images require explicit consent, local SVG/HTML must not execute, and resource Blob URLs must be revoked.
- Keep the versioned skill ZIP complete and install instructions non-destructive. Do not install or overwrite the user's global skill while building browser assets.

## PWA Lifecycle

- Register `/sw.js` only from production builds. Never register on `pnpm dev` (including its `dev:browser` alias). Use a separate localhost origin and Chrome profile for PWA smoke, not the user's connected workspace profile.
- Keep manifest `id`, `scope`, `start_url`, and the worker URL stable. The intended production origin is `https://kanban.giveit2.me`; local implementation does not authorize DNS or deployment.
- Use the Workbox precache manifest and integrity checks for a complete release, including all font subsets and one versioned skill archive. Never cache local Markdown or folder paths as network resources. Keep release metadata, repair assets and `/sw.js` outside the SPA fallback/cache.
- A page holds a shared PWA session Web Lock before mounting the app. Updates prepare every app window, freeze its UI, and obtain an exclusive lease before activation. Do not add unconditional `skipWaiting`, `clients.claim`, or controller-change reloads. New document-editing forms must register drafts with `usePwaDraft`; filesystem writes must remain inside `appActivity.run` through close/readback verification.
- App assets use `alpha-kanban-app-v1-*` CacheStorage entries. IndexedDB `alpha-kanban.browser.v1`, localStorage preferences, handles, stable IDs and unresolved recovery records are not app caches. Never reset them during update/repair/retirement or bump schema versions without an actual tested migration.
- Build recovery/retirement with the same `/sw.js` URL; keep tombstones available for returning clients. Do not clean other applications' registrations/caches or use `Clear-Site-Data`. Follow `docs/pwa_operations.md` for controlled repair and retirement.
- `PwaMenu` uses the existing shadcn wrappers and translation catalog. The small independent `/repair.html` cannot rely on a potentially broken React/CSS bundle; its native semantic controls and colocated Korean/English recovery strings are a deliberate exception, not a second app design system.
- `pnpm test:pwa` uses isolated Chrome profiles and OPFS handles. Report that separately from native install-dialog, real OS folder permission and deployed Cloudflare checks; never mark those passed from an OPFS test.
