# 파일 탐색과 미리보기 스모크

Document-ID: ac9d9b63-3c61-404e-bfe3-7e91959d0cb6

## 메모

파일 탐색 기능의 실제 PC 브라우저 회귀 기준이다. 개인 프로젝트 대신 Markdown 500개 이상과 코드·이미지·다중 페이지 PDF·HTML·바이너리로 구성한 합성 프로젝트를 연결한다. `.ak.config`의 작업 폴더는 `contexts`로 두고 `contexts-old`와 작업 폴더 밖 Markdown도 준비한다.

폴더 선택은 시험 폴더만 대상으로 한다. 스킬 설치·업데이트, 원본 이동·문서 저장·배포는 수행하지 않는다. 권한 검사는 시험용 origin과 연결에만 적용한다. 파일 소실 사례는 합성 파일을 잠시 다른 이름으로 바꿨다가 원래 바이트로 복구한다. 읽기 검증 전후 파일 해시를 대조한다.

자동 검사 결과와 실제 조작 결과를 구분한다. 브라우저·운영체제가 달라지면 새 회차로 기록한다. PDF 화면은 브라우저 내장 뷰어를 직접 확인하고, HTML은 통제된 외부 리소스만 사용한다. 성능 수치는 계측한 조건과 함께 기록하며 측정하지 않은 변경 전 수치를 추정하지 않는다.

## Test Cases

### TC-001. 작업 폴더와 탐색 보기 전환

Revision: 1

Lifecycle: ACTIVE

Summary: 작업 폴더의 문서 묶음과 프로젝트 파일 트리를 구분하고 현재 문서를 유지한다.

Change reason: 최초 정의

#### 사전조건

- 합성 프로젝트를 새로 연결한다.

#### 수행 절차

1. 작업 문서 목록과 프로젝트 문서 개수를 확인한다.
2. 티켓 보드를 연 뒤 파일 탐색으로 전환하고 작업 문서로 돌아간다.
3. 파일 탐색에서 작업 폴더 밖 Markdown을 연다.

#### 기대 결과

- 작업 목록에는 `contexts` 아래 묶음만 있고 `contexts-old`는 포함되지 않는다. 프로젝트 전체 문서 개수는 줄지 않는다.
- 탐색 보기만 바꿀 때 기존 보드·문서가 유지된다. 작업 폴더 밖 파일도 열린다.

### TC-002. 파일 트리·검색·위치 확인

Revision: 1

Lifecycle: ACTIVE

Summary: 펼치지 않은 폴더의 파일명과 Markdown 본문을 찾아 트리 위치로 이동한다.

Change reason: 최초 정의

#### 사전조건

- 깊은 폴더의 한글 파일과 Markdown 본문에만 있는 고유 문구를 준비한다.

#### 수행 절차

1. 포인터와 방향키로 폴더를 펼치고 파일을 연다.
2. 깊은 파일명으로 검색하고 트리 위치 보기와 검색 결과 복귀를 사용한다.
3. Markdown 고유 문구, 없는 문구를 검색하고 결과를 연다. 검색 중 취소가 가능할 만큼 진행 중이면 취소 후 재시도한다.

#### 기대 결과

- 펼치지 않았던 파일도 발견하고 위치 이동 시 해당 행에 포커스가 간다.
- Markdown 본문 결과가 열리고 코드·PDF 본문은 검색했다고 표시하지 않는다. 정상 빈 결과와 진행·중단 상태를 구분한다.

### TC-003. 같은 파일의 링크와 주소

Revision: 1

Lifecycle: ACTIVE

Summary: 트리와 본문 링크가 같은 미리보기를 사용하고 새 탭·뒤로 가기·새로고침을 지원한다.

Change reason: 최초 정의

#### 사전조건

- README에 코드·PDF·HTML·다른 Markdown 제목으로 가는 상대 링크가 있다.

#### 수행 절차

1. 본문 링크와 파일 트리에서 같은 PDF를 연다.
2. PDF 링크를 휠 클릭하여 새 탭으로 열고 새로고침한다.
3. 원래 탭으로 돌아가 제목 링크를 열고 뒤로 가기·앞으로 가기를 사용한다.

#### 기대 결과

- 같은 대상 ID와 공통 읽기 화면을 사용한다. 주소에 PC 절대경로가 노출되지 않는다.
- 원래 탭의 선택을 바꾸지 않고 새 탭이 열린다. 새로고침 후 파일이 복원되고 제목 링크는 해당 위치를 보여 준다.

### TC-004. 유형별 읽기와 실패 안내

Revision: 1

Lifecycle: ACTIVE

Summary: 코드·이미지·PDF를 읽고 큰 파일·손상·미지원 유형에서도 다음 행동을 제공한다.

Change reason: 최초 정의

#### 사전조건

- 코드, 긴 한 줄 텍스트, SVG 또는 PNG, 두 페이지 이상 PDF, 손상된 PDF, ZIP을 준비한다.

#### 수행 절차

1. 코드를 열고 줄 번호·복사 도구를 확인한다. 긴 텍스트를 연다.
2. 이미지를 열고 확대·축소·맞춤을 사용한다.
3. PDF를 열어 페이지 이동·검색·확대를 사용한다.
4. 손상된 PDF와 ZIP을 연다.

#### 기대 결과

- 내용과 읽기 도구가 보이고 큰 텍스트의 생략이 안내된다.
- PDF는 브라우저 내장 뷰어로 읽힌다. 손상·미지원 유형에는 다운로드가 있으며 파일 저장이나 쓰기 권한 요청은 없다.

### TC-005. HTML 실행 격리와 상태 유지

Revision: 1

Lifecycle: ACTIVE

Summary: 선택한 HTML의 리소스와 상호작용은 동작하고 부모 앱과 파일 권한은 격리된다.

Change reason: 최초 정의

#### 사전조건

- 버튼 계수, 상대 CSS·JS·이미지, 통제된 외부 스크립트, 부모 DOM·저장소 접근 결과를 표시하는 HTML을 준비한다.
- 별도 HTML은 누락 이미지와 제외 폴더의 스크립트를 참조한다.

#### 수행 절차

1. HTML을 열고 리소스 표시와 버튼 동작을 확인한다.
2. 소스로 전환했다가 돌아오고 패널 고정·해제·크기 변경을 한다.
3. 실패 HTML을 열고 상세 오류와 소스 보기·다운로드를 확인한다.
4. 다른 파일로 이동한다.

#### 기대 결과

- 선택 시 실행되고 소스·배치 전환에서 버튼 상태가 유지된다. 부모 DOM·앱 저장소 접근 시도는 차단된다.
- 읽을 수 없는 리소스가 안내되며 다른 파일로 이동하면 이전 HTML 프레임이 제거된다.

### TC-006. 기존 문서 화면과 안내

Revision: 1

Lifecycle: ACTIVE

Summary: 기존 보드·스모크·문서 정리와 문맥별 투어가 파일 탐색과 함께 동작한다.

Change reason: 최초 정의

#### 사전조건

- 작업 폴더에 티켓과 스모크 문서를 준비한다.

#### 수행 절차

1. 티켓 상세에 저장하지 않을 지시를 입력하고 닫기·계속 작성·버리고 닫기를 사용한다.
2. 스모크를 열어 시트와 Markdown으로 전환한다.
3. 문서 정리의 미리보기만 열었다가 취소한다.
4. 파일 탐색의 도움말에서 투어를 시작하고 종료한다. 공개 안내를 연다.

#### 기대 결과

- 초안은 확인 전까지 남고 버리기는 한 번만 확인한다. 시트·본문 렌더링은 동일하다.
- 문서 정리는 적용하지 않으면 저장하지 않는다. 투어·공개 안내가 권한 요청이나 파일 실행·수정을 일으키지 않는다.

### TC-007. 파일 소실과 읽기 접근 복구

Revision: 1

Lifecycle: ACTIVE

Summary: 파일 소실과 읽기 권한 문제를 다른 파일로 대체하지 않고 복구한다.

Change reason: 최초 정의

#### 사전조건

- 시험 origin과 합성 프로젝트만 사용한다. 열어 둔 파일의 원본 바이트를 별도로 보관한다.

#### 수행 절차

1. 합성 코드 파일을 열고 파일을 잠시 이름 변경한 뒤 다시 읽기를 누른다.
2. 원래 경로와 바이트로 복구하고 파일 목록을 갱신해 선택한다.
3. 시험 origin의 폴더 접근을 해제하고 새로고침한다. 앱의 명시적 접근 허용 또는 재연결로 같은 시험 폴더를 연결한다.

#### 기대 결과

- 소실·권한 오류가 안내되고 다른 파일을 대신 열지 않는다.
- 명시적인 복구 후 파일을 읽을 수 있으며 다른 프로젝트 연결과 원본 내용은 변하지 않는다.

### TC-008. 배치·테마·대용량 응답

Revision: 1

Lifecycle: ACTIVE

Summary: 많은 파일에서도 탐색과 입력이 가능하고 네 방향 패널·플로팅·언어·테마를 유지한다.

Change reason: 최초 정의

#### 사전조건

- Markdown 500개 이상을 준비한다. 성능 측정은 시험 페이지에만 설치한 계측기로 수행한다.

#### 수행 절차

1. 처음 연결한 프로젝트의 목록 완성 시간과 파일 읽기·긴 작업을 기록한다.
2. 파일 탐색 전환·폴더 펼침·파일 검색을 반복해 시간과 입력 지연을 기록한다.
3. 이미지·PDF·HTML·코드를 반복 열고 활성 프레임과 부모 Blob URL 수를 비교한다.
4. 상·하·좌·우 고정과 플로팅, 좁은 창, 한국어·영어, 라이트·다크를 확인한다.

#### 기대 결과

- 파일 목록을 위해 일반 파일 본문을 일괄 읽지 않는다. 입력에 응답하며 중단·생략·오류가 정상 완료로 표시되지 않는다.
- 사용이 끝난 뷰어와 부모 Blob URL이 남지 않는다. 조작 도구가 가려지지 않고 보기 전환에 현재 문서가 유지된다.
