## 결론

스모크 정의는 `_smoke.md`, 실행 기록은 `_smoke_run.md`로 구분한다. 실제 파일별 UUID를 사용하고, 회차는 원본 UUID와 당시 TC·공통 조건을 보존한다. 현재 결과와 추가된 관찰·정정 기록을 함께 읽는다. 원본 기준은 웹에서 편집하지 않고 결과·메모·종료·사용자 정정을 다룬다.

이 문서는 ASM-01의 UI 대응과 예제 해석, ASM-02의 파서·연결 검증, ASM-08의 실제 앱 검증을 구분해 기록한다. `정상 예제`의 앱·문서·UUID·시각·관찰은 합성 데이터이며 실제 앱 검증의 증거가 아니다. 코드 블록은 각각 독립된 가상 파일의 전체 내용이다. 예제 ID를 실제 새 문서에 재사용하지 않는다. 실제 조작과 저장 결과는 아래 ASM-08 기록을 따른다.

## 조사 범위와 근거

- 기준: [플랜](29_alpha_kanban_smoke_plan.md), [ASM-01](30_alpha_kanban_smoke_tickets.md#asm-01-시트-ui를-담는-markdown-규약과-템플릿-확정).
- 규약: [smoke-format.md](../skills/implementation-ledger/references/smoke-format.md).
- 템플릿: [스모크 정의](../skills/implementation-ledger/assets/smoke-template.md), [실행 기록](../skills/implementation-ledger/assets/smoke-run-template.md).
- 시안의 정의·회차·행 상세·공통 조건·회차 비교·Markdown 미리보기와 합성 데이터 구조를 읽기 전용으로 대조했다.
- 시안의 완료 회차 잠금과 결과 수에 따른 자동 완료 계산은 이후 사용자 결정에 맞춰 채택하지 않았다. 규약은 명시적 종료와 종료 후 사용자 정정을 사용한다.
- ASM-01의 확인 범위는 문서 구조와 정보 대응이다. 아래 ASM-02의 자동 검증과 구분하며, 실제 시트 화면·저장은 해당 후속 티켓에서 검증한다.

## 근거 목록

| UI 항목 | 문서의 값 | 해석·저장 규칙 |
| --- | --- | --- |
| 문서 묶음의 스모크 진입 | 원본 파일의 접미사·기존 슬러그 | 플랜 없이도 사용. 기존 묶음 규칙 유지 |
| 스모크 제목·문서 속성 | H1, Document-ID, 선택적 Owner | Owner를 수행자로 쓰지 않음 |
| 스모크 상단 메모 | 원본 `## 메모` | 자유 Markdown. 결과 필드 아님 |
| 정의 표의 ID·제목·개정 | TC 제목, Revision | 원문 순서, 폐기 ID 재사용 금지 |
| 표의 짧은 절차·기대 결과 | Summary | 전체 판정 기준은 하위 절차·기대 결과 |
| 유효·폐기·변경 이유 | Lifecycle, Change reason, 폐기 필드 | 실행 결과와 별도 |
| TC 상세의 사전조건·절차·기대 결과 | 세 `####` 기준 섹션 | 실행 화면에서는 회차에 저장된 당시 본문 |
| 회차 탭의 번호·이름 | Run, 실행 H1 | 번호·이름은 표시값, UUID가 실제 회차 식별자 |
| 회차 날짜·대상·환경 | Created at, Target, Environment | 생성 시각과 실제 수행 시각을 구분 |
| 회차 상단 메모 | 실행 문서 `## 메모` | 기준 보존 섹션과 별개로 편집 |
| 실행 당시 공통 조건 보기 | `## 실행 당시 공통 조건` | 원본 메모 전체를 생성 시 보존 |
| 현재 결과·결과별 집계 | TC의 Result | 메모에서 추정하지 않음. 중복 진행률 표 없음 |
| 행 메모·상세 증거 | 마지막 LOG의 메모·증거 | 이전 기록도 상세에서 읽음 |
| 수행자·수행 방식·실제 관찰 시각 | EXECUTION의 Actor·Method·At | 문서 Owner·회차 생성자와 별개 |
| 사용자 수정 표시·사유 | USER_EDIT의 Actor·At·From·To·수정 사유 | 기본 사용자 수정, 확인된 ID이면 @name 수정 |
| 회차 종료 | Run-State, Closed at, Close reason | 결과를 바꾸지 않으며 종료 후 정정 가능 |
| 두 회차 비교 | 원본 UUID + TC ID, 각자의 보존 기준·결과·기록 | 한쪽 누락·현재 폐기·개정 차이를 구분 |
| 같은 개정 번호에서 다른 내용 | 기준 본문 및 공통 조건의 차이 | 동일 기준이라고 단정하지 않음 |
| 현재 원본에만 있는 새 TC | 비교할 회차의 포함 목록 | 날짜만으로 신규라고 추정하지 않음 |
| 검색·필터·선택·스크롤·테마 | 문서 필드 아님 | 표시 상태이며 TC·결과를 수정하지 않음 |
| 당시 기준의 상대 링크 | Smoke-Path의 부모 | 회차 메모·증거의 링크는 회차 파일 부모 기준 |

- 기존 합성 Markdown 15개 중 의도적으로 개정한 원본 1개만 달라졌다. 나머지 14개는 시작 시 해시와 같았다. 새 실행 기록 3개는 형식 검사를 통과했다. 최초 회차는 원본 개정 이후 바뀌지 않았고, 실패한 저장은 회귀 회차를 바꾸지 않았다. 권한 취소로 거부된 추가 회차 파일도 생성되지 않았다.
- 최종 합성 스모크·실행 파일 13개가 동봉 `check-smoke.mjs`를 통과했다. 원본이 없는 두 회차는 오류로 합치거나 버리지 않고 orphan 관계로 유지했다.
- 공유 패키지 14개 파일·281개 테스트와 최종 웹 66개 파일·789개 테스트, 타입 검사와 카나리 배포용 빌드가 통과했다. 권한 갱신 중 메모·새 회차 입력 보존 회귀를 추가했다. 이 검사들은 위 실제 조작 결과와 별개다.
- 웹 전체 테스트는 정식 채널 고정 예제에 맞춰 정식 채널 패키지를 준비해 실행했다. 카나리 설정으로 실행한 첫 시도의 채널 불일치 실패와 구분하며, 검증 후 동봉 패키지를 카나리로 되돌렸다.
- 쓰기 직후 원본 변경, writer close·readback 실패와 복구 사본 내구성은 파일 핸들 오류를 주입한 통합 검사로 확인했다. 실제 OS 검증은 쓰기 거부·브라우저 권한 취소까지이며, 브라우저 강제 종료나 전원 차단을 수행한 것으로 보고하지 않는다.
