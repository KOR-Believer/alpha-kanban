# AKC-06 공식 문서·릴리즈 시안 검토

검토일: 2026-11-03

설치된 디자인 프로그램의 Local Codex로 만든 독립 시안이다. 문서 탐색·검색과 릴리즈 목록·상세를 실제로 조작하며 디자인을 검토할 수 있다. 제품 페이지 구현, 사용자 디자인 승인, 공개 배포 완료를 뜻하지 않는다. 구현은 시안 검토 뒤 AKC-07·08에서 진행한다.

## 산출물

- [인터랙티브 시안](prototype/index.html): HTML·CSS·JavaScript·로컬 폰트와 라이선스를 함께 유지한다. 별도 패키지 설치나 빌드가 필요하지 않다.
- [디자인 브리프](brief.md): 화면·내용·범위의 기준.
- [내부 컴포넌트 대응](components.md): 기존 래퍼와 공통 본문 표현을 재사용할 지점. 새 shadcn 의존성은 필요하지 않았다.
- [시안 검토 노트](prototype/review-notes.md): 채널별 예시, 제안, 제품 통합 경계.

## 화면과 읽기 흐름

문서는 왼쪽 그룹 탐색, 가운데 본문, 오른쪽 페이지 목차로 구성한다. 시작 문서는 설정 없이 스킬 설치 → 아이디어 토론 → 계획·티켓 검토 → 구현 요청 순서를 안내한다. 소유자 구분과 설정은 별도 문서에서 읽는다. 모바일에서는 그룹 탐색을 메뉴로, 페이지 목차를 접는 목록으로 제공한다.

검색은 제목과 본문 발췌를 보여주고 선택한 문단으로 이동한다. 릴리즈는 날짜순 목록 → 상세 → 관련 가이드로 이어진다. 짧은 기록은 같은 설명을 반복하지 않고, 긴 기록만 변경 내용과 필요한 행동을 나눈다.

상단은 기존 언어·테마 우선 순서와 채널 표현을 따른다. 16px 본문은 공개 문서를 오래 읽는 화면에 한정된 디자인 제안이며 기존 보드·티켓 본문의 크기를 변경하지 않는다. 선택한 탐색 항목은 기존 muted 배경과 세로 표시로 구별한다.

## 직접 확인한 결과

기존 Chrome에서 내보낸 시안을 열어 확인했다. 데스크톱 1360×900과 모바일 390×844를 사용했다.

| 항목 | 확인 결과 |
| --- | --- |
| 레이아웃 | 한국어 라이트 데스크톱, 영어 다크 모바일에서 헤더·본문·코드·탐색의 줄바꿈과 가로 넘침을 확인했다. 검사한 화면에 페이지 가로 넘침이 없었다. |
| 검색 | `ownerFolders`가 카나리에서 문단 결과 5개, 정식에서 결과 0개로 표시됐다. 표 셀과 코드 발췌의 경계를 확인했고 복사 버튼 글자는 발췌에서 제외됐다. |
| 검색 키보드 | 방향키·Enter로 해당 문단에 이동하고 제목으로 초점이 옮겨졌다. 빈 결과의 검색어 지우기와 검색어가 있는 상태에서 Escape 한 번으로 닫기·호출 버튼 초점 복귀를 확인했다. |
| 모바일 메뉴 | 열기·Escape 닫기 후 메뉴 버튼으로 초점이 돌아왔다. |
| 복사 | 공유 설정 예시가 `[documents]`와 `ownerFolders = true` 사이의 줄바꿈을 보존해 클립보드로 복사됐다. |
| 문단 주소 | 검색으로 연 문단 주소를 새로고침해 같은 문서·문단·언어·테마·채널을 유지했다. |
| 릴리즈 탐색 | 정식 목록 → 상세 → 업데이트 가이드, 뒤로가기로 상세 복귀, 앞으로가기로 가이드 복원을 확인했다. 카나리 상세의 관련 로컬 링크 가이드도 열었다. |
| 예외 주소 | 없는 문서·없는 릴리즈·다른 채널 문서는 주소를 유지하며 문서 시작 또는 릴리즈 목록으로 돌아갈 안내를 보여줬다. |
| 채널 예시 | 정식 기본 문서 7개, 카나리 전체 문서 16개를 확인했다. 실제 배포 콘텐츠를 자동 확인한 결과는 아니다. |
| 파일·범위 | 시안 JavaScript 3개 구문 검사와 자산 참조를 확인했다. 작업 전후 앱·패키지·스킬·스크립트 파일 241개의 해시가 같았다. |

시안 검토에서 접근성 이름의 한영 전환, 검색어가 있을 때 Escape 처리, 선택 배경을 보완했다. 본문에 잘못 들어간 보드 표시 제한 안내를 제거했고, 문서 정리를 선택한 파일의 미리보기·명시적 적용으로 바로잡았다. 가장 가까운 `@` 폴더명이 잘못됐을 때 바깥 소유자로 추정하지 않는 규칙도 맞췄다.

스크린리더 낭독, 대비 수치, 글꼴 확대, 클립보드 거부 시 대체 입력, 실제 React/PWA 통합·오프라인·폴더 권한은 이번 시안 검증의 증거가 아니다. 필요한 제품 검증은 AKC-07·08에서 수행한다.

## 다음 구현에 전달할 사항

- 시안 코드를 제품에 그대로 복사하지 않는다. 기존 Button/Input/Dialog/Select/Badge와 언어·테마·채널 컴포넌트를 사용하고, 공개 본문에 필요한 작은 표현 부분만 기존 Markdown 읽기 UI에서 재사용한다.
- 로컬 파일 조회, 폴더 권한, 앱·스킬 업데이트, 읽음 기록은 공개 문서 열람으로 시작하지 않는다. 시안의 채널 선택 도구도 제품 헤더에 추가하지 않는다.
- 채널별 공개 문서 목록과 실제 게시 이력은 AKC-07·08에서 확정한 빌드 콘텐츠를 따른다. 시안의 7/16개 구분을 실제 배포 상태로 간주하지 않는다.
- `apps/web/releases.json`의 로컬 초안 `2026-11-01-document-compatibility`에는 지원하지 않는 문서를 Markdown으로 제한한다는 오래된 안내가 남아 있다. 현재 원칙은 렌더링과 호환성 검사 분리다. 해당 초안은 시안 예시에서 제외했으며 AKC-08에서 공개 여부와 사실관계를 확인해 정리한다. 이번 작업에서는 원본 릴리즈 데이터와 게시 이력을 수정하지 않았다.
- 제품의 Pretendard 동적 서브셋 로딩과 두 글꼴 라이선스를 유지한다. 시안의 전체 폰트 파일을 제품의 로딩 방식으로 대체하지 않는다.
- README는 한 문장 소개 → 공개 예시 한 장 → 스킬 설치 → 첫 대화·계획·티켓 → 선택적 칸반 → docs·릴리즈·업데이트 순서를 제안한다. 실제 한영 README 수정은 AKC-09에서 한다.

## 확인·결정이 필요한 사항

- 새로운 범위 질문은 없다. 화면 배치와 읽기 밀도에 대한 사용자 검토 후 제품 구현으로 넘어간다.


## AKD-18 콘텐츠 보완

승인된 화면 배치를 유지하고 `.ak.config`의 repo 루트 배치, `root = notes` 예시, `docs` 기본값, `ownerFolders`와의 독립성, 항목별 workspace 상속과 외부 worktree 조건을 보강했다. 설정 예시는 파일명으로 안내한다. 문서 정리는 규격 변화에 따라 계속 유지할 문서를 선택적으로 관리하는 기능으로 설명하고 현재 지원하는 ID·Owner·폐기 영역 정리를 별도로 소개한다. 한영 README의 해당 사용 안내도 보완했다. README 전체 개편은 계속 AKC-09 범위다.

보완한 내보내기 시안을 Chrome에서 한국어 라이트 데스크톱과 영어 다크 390px로 확인했다. 설정 표·경로·폴더 예시가 표시되며 페이지 가로 넘침이 없다. 이 검증은 저장소의 `prototype/` 산출물에 해당한다.

2026-11-04에 Local Codex의 기존 시안도 동기화했다. 변경 대상 `content.js`와 `review-notes.md`가 이전 내보내기와 일치함을 확인한 뒤 보강본으로 갱신했고, 다시 읽은 두 파일이 저장소 산출물과 일치했다. Local Codex 미리보기에서 설정 위치·문서 폴더·상속 예시와 선택적인 문서 정리 안내가 표시되는 것을 확인했다.

### 설명을 먼저 읽는 배치

예시를 페이지 맨 위에서 해당 기능 설명 뒤로 옮겼다. 소유자는 경로와 Owner의 의미 뒤, 설정은 기본 항목·문서 폴더 지정 뒤와 상속·worktree 설명 사이에 놓았다. 문서 정리·인수인계·로컬 링크·업데이트·복구는 사용 조건과 변경 범위를 먼저 설명한다. 기존 한영 본문은 유지했다.

Chrome에서 10개 문서의 본문·데스크톱 목차·모바일 목차 순서가 일치함을 확인했다. 영어 다크 390px에서 설명이 먼저 보이고 예시 목차 이동·조작이 작동하며 가로 넘침이 없었다. 한국어 라이트 [설명 뒤의 예시 화면](captures/guide-reading-order-ko.png)도 확인했다. Local Codex의 기존 파일 일치를 확인한 뒤 같은 변경을 동기화했다.

업데이트·문제 해결의 현재 조작 예시는 개념 시안이다. 사용자 검토에 따라 AKC-07에서 실제 화면 캡처를 우선하고 실제 진입점·버튼명·순서·보호 조건과 대조하는 것을 제품 통합 조건으로 남겼다.

### 문서 인계 방법 구분

2026-11-04 추가 검토에 따라 인계 문서의 한영 본문을 수정했다. 먼저 직접 파일 이동 후 문서 정리로 Owner를 맞추는 방법과 CLI로 이동·Owner·링크 보정을 함께 검토하는 방법을 비교한다. 직접 이동 후 문서 정리는 이동에 따른 링크 복구를 포함하지 않는다고 설명하고, 기존 조작 예시는 CLI 방법임을 제목과 안내에 명시했다. 다른 문서의 본문은 유지했다. 브라우저 파일 트리·드래그 이동은 구현하거나 이번 범위에 추가하지 않았다.

Chrome에서 방법 비교→직접 이동 안내→문서 정리 링크, CLI 예시의 변경 계획, 본문·목차 순서를 확인했다. 한국어 라이트 1360px와 영어 다크 390px를 검토했으며 모바일에서 페이지 가로 넘침은 없었다. [두 가지 인계 방법 화면](captures/handoff-methods-ko.png)을 기록했다. 본문 데이터 비교에서 인계 문서만 바뀌고 나머지 15개 문서는 동일하며, JavaScript 구문 검사를 통과했다. Local Codex의 같은 시안 파일을 동기화하고 읽어 일치를 확인했다.
