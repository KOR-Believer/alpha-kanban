# AKC-06 내부 컴포넌트 대응

작성일: 2026-11-03

이 문서는 디자인을 제품 코드로 옮길 때의 기준이다. 독립 시안의 HTML/CSS/JS를 제품 소스에 그대로 이식하거나 새로운 패키지를 설치하는 작업은 포함하지 않는다.

## 우선 재사용할 요소

| 시안의 요소 | 확인한 내부 구현 | 적용 기준 |
| --- | --- | --- |
| 제품 이름·정식/카나리 식별 | `apps/web/src/components/AppBrand.tsx`의 AppBrand, BrandIcon, ChannelBadge | 현재 빌드 채널을 따른다. 카나리는 플라스크와 CANARY, 정식은 기존 로고를 사용한다. 시안의 채널 비교 스위치는 제품에 추가하지 않는다. |
| 언어·테마 | LanguageSelector, ThemeToggle | 기존 설정을 이어 쓰고 언어·테마 뒤에 도구 구분선을 둔다. 전환으로 현재 문서·읽던 위치·검색 입력을 버리지 않는다. |
| 링크·복사·메뉴 버튼 | `components/ui/button.tsx`의 Button, buttonVariants | 탐색은 링크, 조작은 버튼. toolbar `sm`/`iconSm` 28px, 본문 기본 32px. 링크를 Button 안에 중첩하지 않는다. |
| 검색 입력 | `components/ui/input.tsx` | 36px 필드·기존 레이블·포커스 표현을 사용한다. 검색어는 공개 콘텐츠에만 적용한다. |
| 검색 창·좁은 화면 탐색 | `components/ui/dialog.tsx` | DialogHeader/Body/Footer로 정렬하고 본문에만 스크롤을 둔다. Escape·초점 가두기·호출 버튼 복귀는 기존 Radix 동작을 재사용한다. |
| 짧은 분류·상태 | `components/ui/badge.tsx` | 실제 분류나 채널만 표시한다. 발표하지 않은 버전·호환성·개발 진행 뱃지를 만들지 않는다. |
| 언어 선택 등 작은 선택기 | `components/ui/select.tsx` | toolbar에는 `size="sm"`, 입력 옆에는 `size="field"`. 큰 메뉴나 문서 트리를 Select에 억지로 넣지 않는다. |
| 접는 페이지 목차·부가 안내 | native details 또는 기존 Popover+Button | 핵심 탐색을 hover에만 의존시키지 않는다. 문단은 링크로 이동하고 현재 문단을 텍스트/형태로 구별한다. |
| 본문·제목·코드·표 | `MarkdownDocumentReader.tsx`, `styles.css`의 ak-markdown | 같은 본문 위계·토큰·GFM 표현을 재사용한다. 문단 링크·복사 컨트롤은 필요한 작은 확장으로 설계한다. |
| 설치·업데이트 진입 | SkillInstallPanel, SkillInstallDialog, SkillUpdatesButton | 별도 설치기나 다른 요청문을 만들지 않는다. 실제 페이지 구현에서 현재 채널에 고정된 기존 요청과 보호 흐름으로 연결한다. |
| 릴리즈 사실·순서 | 기존 `releases.json`, `releases.canary.json`과 릴리즈 처리 코드 | 실제 ID·날짜·요약을 공유하고 본문만 필요한 만큼 확장한다. 목록 읽기와 PWA 적용/읽음 기록은 별개다. |
| 조작 가능한 사용 예시 | Button, Badge, Checkbox, CodeDiff와 semantic HTML/SVG | 예시 데이터와 화면 상태만 사용한다. 단계·다시 시작·키보드 조작은 실제 파일/업데이트 서비스와 연결하지 않는다. 정리 전후는 제품 통합 시 CodeDiff로 표시하고 그림의 폴더·경로는 DOM 텍스트로 읽을 수 있게 한다. |

## 공개 본문과 로컬 문서 읽기의 경계

현재 MarkdownDocumentReader는 본문뿐 아니라 로컬 파일의 경로·묶음·진행률·연결 링크를 포함한다. 공개 docs에 이 화면 전체를 그대로 끼우면 읽기와 무관한 로컬 정보가 따라온다.

AKC-07에서는 본문·제목·앵커·목차의 공통 표현을 재사용할 수 있도록 작은 표현 컴포넌트로 추출하는 방안을 우선 검토한다. 공개 콘텐츠의 링크는 빌드에 포함된 문서 주소로 연결한다. 로컬 파일 핸들·repository 조회·폴더 권한·자동 문서 재열기는 공개 페이지에서 시작하지 않는다. 기존 일반·연결 Markdown 화면은 같은 렌더러와 동작을 유지한다.

## 새 UI 의존성 판단

현재 확인한 화면은 기존 Dialog, Input, Button, Select, Badge, Popover와 semantic HTML로 표현할 수 있다. 새 shadcn 패키지를 채택할 필요는 아직 없다. 문서 트리는 링크 목록, 릴리즈 목록은 날짜·제목·요약을 가진 목록으로 충분하다.

검색의 키보드 결과 선택은 별도의 구현 확인 대상이다. 단순히 검색 창 모양이 있다는 이유로 combobox/listbox 접근성이 완성됐다고 간주하지 않는다. 기존 Dialog 안에서 입력 포커스·위/아래 선택·Enter 이동·Escape 복귀를 정의하고 검사한다. 추후 내부 조합으로 해결되지 않는 요소가 확인되면 그 요소만 선별 검토한다.

## 구현 검토 항목

- 공통 토큰·폰트의 출처는 `styles.css`다. public docs용 색상·반경 체계를 따로 만들지 않는다.
- 문서 폭, 헤더, 탐색과 목차의 접힘 기준은 시안에서 검토하되 기존 보드·티켓 화면을 바꾸는 전역 규칙으로 넣지 않는다.
- 작은 회색 글씨, 흰 배경의 링크, dark 코드/표/선택 상태는 실제 화면에서 확인한다. 색만으로 선택·상태를 설명하지 않는다.
- 페이지·문단의 주소와 브라우저 뒤로/앞으로가 기본 탐색이다. 한영 전환은 같은 문서의 대응 번역으로 이동하고 식별자를 번역 문자열로 만들지 않는다.
- docs 검색과 릴리즈 목록은 해당 채널에 포함된 공개 콘텐츠만 대상으로 한다. 로컬 Markdown과 내부 플랜/티켓은 목록에 들어가지 않는다.
- 사용 예시에는 실제 조작과 혼동하지 않도록 예시 표시를 둔다. 본문은 그대로 유지하고 목차의 예시 링크로 바로 접근한다. 예시 상태는 페이지 안에서만 유지하며 언어·테마 전환으로 초기화하지 않는다. 새 패키지·자동 재생·폰트/색상 체계를 추가하지 않는다.
- README는 한 문장 소개 → 공개 예시 → 스킬 설치 → 첫 대화 → 선택적 칸반 → docs/릴리즈/업데이트 연결 순서를 기본으로 한다. 실제 수정은 AKC-09에서 진행한다.
