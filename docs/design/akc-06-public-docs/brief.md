# AKC-06 공식 docs·릴리즈 디자인 브리프

작성일: 2026-11-03

## 목표와 범위

설치된 디자인 프로그램의 **Local Codex**로 공식 docs와 릴리즈 페이지를 검토 가능한 독립 시안으로 만든다. 제품 페이지 구현은 디자인 검토 뒤 AKC-07·08에서 진행한다. 제품 소스·설정·실제 문서·개인 스킬·기존 디자인 프로젝트는 변경하지 않는다. 외부 로그인·업로드·배포와 새 패키지 설치도 하지 않는다.

기준은 [계획](../../26_alpha_kanban_canary_channel_plan.md)의 공개 문서 역할 및 [AKC-06](../../27_alpha_kanban_canary_channel_tickets.md)이다. 기존 UI의 컴포넌트·토큰·글꼴을 사용하고, 화려한 새 랜딩 페이지나 카드형 대시보드를 만들지 않는다. 시안의 상태 선택과 검토 메모는 제품 영역 밖에 둔다.

## 사용자와 읽기 순서

처음 온 사용자는 implementation-ledger 설치 → AI와 아이디어 토론 → 계획·티켓 검토 → 구현 요청을 따라간다. 모든 작업을 외부 AI 대화에서 할 수 있고 웹 칸반은 선택적으로 문서·진행을 확인하는 도구다. 사용자 폴더나 설정 파일을 기본 필수 단계로 만들지 않는다.

기존 사용자는 검색과 사이드바로 기능의 정확한 사용법을 찾는다. 릴리즈 독자는 무엇이 바뀌었고 어떤 조작이 필요한지 읽은 뒤 관련 가이드로 간다. 사용 설명과 릴리즈 당시의 변경 사실을 구분한다.

## 대표 화면과 동작

1. **docs 시작하기**: 왼쪽 그룹 탐색, 가운데 읽기 본문, 오른쪽 현재 페이지 목차. 큰 광고용 hero 없이 제목·한 문장 소개·짧은 단계·복사 가능한 요청문으로 시작한다. 다음 문서로 자연스럽게 이어진다.
2. **선택적 소유자 구분 가이드**: 기본 사용과 추가 설정의 관계, 공유/개인 파일의 작은 코드 예시, 관련 설정 명세 링크. 읽기 순서에 맞는 제목·본문·표·코드·주의 안내를 보여준다.
3. **설정 참고**: `.ak.config`와 `.ak.user`의 역할, 기본값·적용 범위·우선순위. 설정 키는 번역하지 않고 설명만 한영으로 바뀐다. 긴 코드와 표는 좁은 폭에서도 전체 페이지를 옆으로 밀지 않는다.
4. **문서 검색**: 기존 Dialog+Input 조합의 검색 화면. 제목·짧은 본문 발췌·소속 그룹을 보여주며 문서/관련 문단으로 이동한다. 검색 전, 결과 있음, 결과 없음, 지운 뒤 다시 검색, Escape·초점 복귀·키보드 선택을 검토한다. 사용자 로컬 문서는 검색 대상이 아니다.
5. **릴리즈 목록**: 날짜순 제목·짧은 요약을 읽는 게시판 형태. 항목마다 커다란 카드를 반복하지 않는다. 실제 기록에 없는 버전 번호나 작성자·조회수·반응 버튼·구독 기능을 발명하지 않는다.
6. **릴리즈 상세**: 날짜·제목·요약 → 달라진 동작 → 기존 사용자의 다음 행동 → 관련 가이드. 상단 목록 복귀와 관련 문서 탐색을 제공한다. 요약만 있는 과거 기록도 간결하게 읽는다. 페이지 열람 자체가 업데이트 적용이나 읽음 동의가 되지 않는다.
7. **모바일**: 왼쪽 탐색은 명시적 메뉴로, 페이지 목차는 별도 접기/펼치기로 접근한다. 검색·메뉴·언어/테마·현재 페이지 위치가 겹치지 않는다. 브라우저 뒤로가기와 직접 문서 주소·앵커가 동작한다.
8. **없는 페이지**: 주소를 유지하고 docs 시작 또는 릴리즈 목록으로 돌아갈 방법을 제공한다. 실제 보드로 강제 이동하지 않는다. 현재 빌드에 없는 릴리즈 상세는 기존 팝업의 요약을 읽는 흐름과 충돌하지 않는다.

전체 목차를 탐색할 수 있게 하되 모든 본문을 완성하는 작업은 아니다. 대표 문서는 충분한 실제 예시로 읽기 밀도를 검토하고, 나머지 항목은 일관된 간단한 가이드로 연결한다. 시안 상태나 미완성 설명을 실제 사용자 안내 문구에 넣지 않는다.

## 내용의 정확성

- 설정 없이 기본 문서를 작성·수정할 수 있다. 홈의 사용자 설정만으로 팀 모드나 사용자 폴더를 자동 생성하지 않는다.
- 소유자별 신규 기본 배치는 `.ak.config`의 `[documents] ownerFolders = true`로 켠다. 개인 사용자 파일은 `.ak.user`의 `[user] id = @alice`이며 Git에서 제외한다.
- 공유 정책은 현재 repo → 지정 workspace → false. 필요한 사용자는 확인된 원래 repo → 지정 workspace → 홈이다. linked worktree는 개인 사용자 설정만 확인된 원래 repo에서 이어받고 공유 정책은 현재 worktree 기준이다.
- 경로 소유자는 문서에서 가장 가까운 `@` 폴더명이 유효할 때 판정한다. 그 이름이 잘못됐으면 바깥 폴더의 소유자로 대신 판정하지 않는다. 문서 상단 `Owner: @alice`는 기록된 값이며 권한·현재 접속자·티켓 실행 허가가 아니다. 기본 사용에는 Owner·ID 발급이 필수가 아니다.
- 브라우저의 로컬 링크 연결은 원본 Markdown을 바꾸지 않는다. 사용자가 직접 문서를 옮긴 뒤 문서 정리로 현재 폴더에 맞는 Owner를 미리보기·적용할 수 있다. 문서 정리는 이동 때문에 달라진 링크를 고치지 않는다. 이동과 링크 보정을 함께 처리하거나 PC 경로를 일괄 보정할 때는 명시적 CLI 작업을 사용한다.
- 릴리즈 데이터는 `apps/web/releases.json` 및 `apps/web/releases.canary.json`의 실제 ID·날짜·요약만 사용한다. 정식에서 미제공 카나리 기능을 사용법으로 섞지 않는다. 시안의 카나리 상세는 검토 예시이며 공개 배포 증거가 아니다. 이 구분은 시안 검토 노트에 기록한다.
- 설정 예시는 실제 `.ak.config`·`.ak.user` 파일명과 섹션·키로 설명한다. 별도 형식명이나 확장자를 안내하지 않는다. 공개 예시는 `reading-journal`, `@alice`, `@bob` 등 일반 명칭을 사용한다. 내부 티켓·검증 기록·개인 프로젝트·실제 PC 경로를 화면이나 검색 결과에 노출하지 않는다.

## 시각 기준과 내부 컴포넌트

제품의 `apps/web/src/styles.css`, `start-pages.css`, `components/ui/*`, `AppBrand`, `LanguageSelector`, `ThemeToggle`, `MarkdownDocumentReader`, `CodeDiff`, `SkillGuide`를 읽기 전용 기준으로 사용한다. 독립 시안은 HTML/CSS/JS로 대응해도 되며 이를 제품 React 통합 완료라고 표현하지 않는다.

- 글꼴은 Raleway Variable → Pretendard Variable → system sans. 저장소의 설치된 폰트 자산을 시안 폴더에 복사하고 해당 라이선스를 함께 둔다. 외부 폰트 CDN을 쓰지 않는다.
- light: background/card/popover 흰색, foreground `oklch(0.153 0.006 107.1)`, muted `oklch(0.966 0.005 106.5)`, muted-foreground `oklch(0.58 0.031 107.3)`, border `oklch(0.93 0.007 106.5)`.
- dark: background `oklch(0.24 0.006 106.6)`, sidebar `oklch(0.265 0.006 106.7)`, card `oklch(0.32 0.006 106.7)`, popover `oklch(0.34 0.006 106.7)`, muted `oklch(0.35 0.005 106.7)`, foreground `oklch(0.955 0.001 106.4)`, muted-foreground `oklch(0.76 0.012 107.1)`.
- 정식 primary는 `oklch(0.841 0.238 128.85)`. 카나리는 light `#7c3aed`/white, dark `#c4a7ff`/`#271342`; 헤더 light `#f6f2ff`, dark `#2b243b`. 플라스크 아이콘과 CANARY 표기를 유지한다. 두 채널의 배치는 같다.
- 간격 4/8/12/16/24/28/32px, 반경 6/8/10/14px, 필드 36px, 일반 버튼 32px, 툴바 버튼 28px를 따른다. 공통 토큰을 재사용한다.
- 한국어 기본, 영어 전환. 상단 조작은 언어·테마를 먼저 두고 구분선 뒤 검색 등의 도구를 배치한다. 기존 탐색과 혼동되는 계정·워크스페이스 설정을 새로 만들지 않는다.
- 본문은 편안한 읽기 폭과 충분한 행간을 갖되 기존 Markdown 위계를 따른다. 문서와 관련 없는 그래픽·큰 배너·과도한 카드·그라데이션·배경 장식은 추가하지 않는다.

## README 방향

별도 검토 노트에 GitHub Markdown 기준의 순서를 제안한다: 한 문장 소개 → 공개용 실제 예시 한 장 → 스킬 설치 → 첫 대화와 계획·티켓 → 선택적 칸반 → docs·릴리즈·업데이트 링크. 한영판은 같은 구조다. 큰 배너·가짜 뱃지·지원되지 않는 수치·불필요한 배지 벽을 피한다. 실제 README 수정은 AKC-09에서 한다.

## 산출물과 검토

### 조작 가능한 사용 예시

2026-11-04 사용자 검토에 따라 기존 한영 본문은 유지하고, 문서 관리·로컬 링크·소유자/설정·업데이트와 문제 해결에 조작 가능한 그림을 덧붙인다. 정지 캡처만으로 전후 관계를 설명하기 어려운 흐름은 예시 데이터의 단계별 화면으로 보여준다. 실제 파일·폴더 선택·권한·업데이트와 구분되는 예시임을 표시한다.

- 문서 정리는 원문·미리보기·명시적 적용 결과를 보여준다. 이동과 인수인계는 직접 이동 후 Owner 정리와 CLI 이동·링크 보정의 범위를 먼저 비교하고, CLI 예시는 경로·Owner·참조 변경과 보존되는 ID를 보여준다. CLI를 인계의 필수 조건으로 안내하지 않는다.
- 로컬 링크는 옛 PC 주소·선택한 repo·보존되는 내부 경로를 나눠 표시하고 최초 연결, 좁은 폴더 선택, 동일 접두사 재사용과 연결 변경·해제를 체험하게 한다. 옛 절대주소만으로 repo를 자동 확정하지 않는다.
- 소유자와 설정은 경로 소유자·기록된 Owner·개인 사용자, 무설정·개인 사용자만 설정·ownerFolders·사용자 지정 root의 차이를 시각화한다.
- 업데이트·문제 해결은 앱과 설치된 스킬의 변경 대상, 백업 복원과 외부 수정 보호, 폴더 접근 허용과 원본 파일 부재를 구분한다.
- 읽기 순서는 기능의 목적·사용 조건·변경 범위 설명 뒤에 예시를 둔다. 소유자는 경로와 Owner의 의미 뒤, 설정은 기본 항목·폴더 지정 뒤와 상속 설명 앞에 놓고, 문서 관리·링크·업데이트·복구는 작업과 저장 범위를 안내한 뒤에 놓는다. 데스크톱·모바일 목차도 본문 순서를 따른다.
- 업데이트·문제 해결의 제품 통합에서는 실제 화면 캡처를 우선하고 조작 예시도 실제 앱의 진입점·버튼명·진행 순서·보호 조건과 일치시킨다. 현재 개념 시안의 화면을 그대로 옮기지 않으며 구체적인 대조와 보정은 AKC-07에서 진행한다.
- 예시는 자동 재생하지 않고 키보드로도 조작하며 재시작할 수 있다. 언어·테마 전환으로 현재 단계를 잃지 않고 모바일에서는 순서대로 쌓는다. 예시를 조작해도 파일·실제 연결·브라우저 권한·설치 스킬·업데이트 상태를 읽거나 변경하지 않는다.

- 같은 프로젝트 안의 `index.html`, 로컬 CSS/JS/폰트와 `review-notes.md`. 해시 라우팅을 써도 되며 검토용 상태만 별도 접이식 패널에 둔다.
- 정식·카나리, 한국어·영어, 라이트·다크, 데스크톱·390px 대표 상태. 채널 전환 검토 스위치는 실제 제품 기능처럼 헤더에 넣지 않는다.
- 검색→문단, 목차, 코드 복사, 메뉴와 Escape/초점 복귀, 릴리즈 목록→상세→관련 docs, 없는 주소, 뒤로/앞으로·새로고침을 확인할 수 있어야 한다.
- 실제 제품을 변경하거나 폴더 권한·설치·업데이트를 수행하지 않는다. 계정·서버·CMS·분석 전송을 만들지 않는다.
- 노트에는 화면별 상태, 컴포넌트 대응, 제안과 구현의 구분, 확인한 항목과 아직 확인하지 않은 항목을 분리한다. 사람의 디자인 승인이나 제품 구현 완료를 추정하지 않는다.

## 확인·결정이 필요한 사항

- 없음. 구성의 세부 배치와 시각 완성도는 시안으로 제시하고 사용자 검토 후 확정한다.
