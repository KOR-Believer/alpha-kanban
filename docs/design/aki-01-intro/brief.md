# AKI-01 스킬과 칸반을 연결하는 소개 시안

작성일: 2026-10-18

## 목적과 범위

- [소개 계획](../../19_alpha_kanban_skill_intro_plan.md)과 [AKI-01](../../20_alpha_kanban_skill_intro_tickets.md)을 기준으로 새 랜딩 시안을 만든다.
- Alpha Kanban과 implementation-ledger 양쪽 가치를 보여준다. 칸반은 전체 진행·티켓 상세·남은 결정·검증을 읽는 화면이고 스킬은 AI와 합의한 범위·결정·구현 결과를 같은 Markdown에 남긴다. 첫 시안의 스킬 단독 강조와 하단 칸반 부록 배치는 사용자 검토에서 채택되지 않았다.
- 별도 디자인 프로젝트의 정적 시안만 만든다. 사용자 검토 전 실제 `/intro`, `/`, 보드, 공통 컴포넌트와 PWA를 변경하지 않는다. 이전 AKL-14 승인은 이번 구성의 승인이 아니다.
- 개인 전역 스킬과 사용자 폴더·설정은 읽거나 변경하지 않는다. 설치 실행·AI 실행·문서 쓰기·공개 배포·커밋·푸시는 하지 않는다.

## 화면 구성

1. Alpha Kanban 이름과 간결한 가치 설명, `칸반 시작하기`·`스킬 설치하기`를 첫 화면에 함께 둔다. implementation-ledger가 어떤 기록을 만들어 주는지 즉시 드러나게 한다.
2. 소개 바로 아래에 실제 조작 가능한 가상 독서 기록 프로젝트 보드를 둔다. 데스크톱 첫 화면에 열 제목과 티켓을, 모바일에도 보드와 티켓 일부를 보여준다. 같은 가상 데이터의 보드·Markdown을 전환해 읽는다.
3. 가상의 Codex 채팅창에서 대화를 따라가는 인터랙션을 만든다. 순서는 문서·코드 없이 아이데이션 → 플랜·티켓 초안 요청 → 사람이 플랜과 열린 질문 읽기 → AI와 질문 논의·결정·문서 갱신·다시 읽기 → 질문 해소와 최종 검토 후 순차 구현 요청 → 결과 검토와 다음 논의다. 초안에서 바로 구현으로 건너뛰지 않는다.
4. 처음에는 재생 대기 상태로 두고, 재생·일시 정지·이전/다음 대화·장면 이동·다시 보기를 제공한다. 대화에 맞춰 문서가 아직 없는 상태, 초안의 열린 질문, 결정 반영 후 `확인·결정이 필요한 사항: 없음`, 구현 기록을 보여준다. 질문이 남으면 토론과 문서 검토로 돌아가는 반복을 드러낸다. 실제 입력창·AI 실행으로 오해시키지 않으며 가상 사례임을 표시한다. 이번 사례는 플랜과 티켓을 함께 만들지만 인벤토리나 보드 수동 편집을 필수로 요구하지 않는다.
5. `#skill`에서 처음 설치와 기존 스킬 업데이트를 선택하고 공식 출처의 요청문을 확인·복사한다. 전체 폴더 설치, 기존 설치본 비교·백업·개인 수정 보존·덮어쓰기 전 확인을 포함한다. `#updates`도 같은 설치 영역의 업데이트 모드로 연결한다.
6. 독립적인 대형 업데이트 영역은 없애고 마무리에도 칸반·스킬의 두 행동을 제공한다. 실제 배포 계약 전에는 공식 원본 비교를 안내하고 버전·최신 여부·변경 이력을 지어내지 않는다. 칸반이 선택적이라는 문구를 반복하거나 메뉴를 `선택적 칸반`으로 부르지 않는다.

## 디자인과 동작

- 현재 `styles.css`의 semantic token, Raleway Variable와 Pretendard Variable, shadcn b1 컨트롤·Lucide 아이콘을 따른다. 기존 보드나 시작 화면의 디자인을 바꾸지 않는다.
- 가상 채팅 안쪽은 사용자가 제공한 Codex.app 캡처의 배치를 따른다. 오른쪽 회색 사용자 말풍선, 테두리 없는 AI 본문, 절제된 작업 기록·문서 링크, 하단 읽기 전용 입력창을 재현한다. 채팅과 플랜·티켓을 하나의 창으로 묶고 오른쪽에 문서 탭·경로·본문·파일 목록을 둔다. 재생 컨트롤은 모의 앱 바깥에 둔다. 캡처의 실제 대화·개인 경로와 이미지 자체는 산출물에 포함하지 않는다.
- 재생 막대에서 원하는 시점으로 이동하고 경과/전체 시간을 확인할 수 있다. 배속은 0.5·1·1.5·2·3배이며 기본은 1배다. 재생 대기·재생 중·일시정지·재생 완료를 구분하고 완료 후 다시 재생한다. 배속 변경·정지·언어 전환은 현재 위치를 보존하고, 되감기는 문서 생성 전 상태와 열린 질문까지 되돌린다.
- 한국어 기본과 영어 전환을 제공한다. 섹션은 테두리 없는 흐름이나 전체 폭 영역으로 구성하고 카드 중첩·가짜 터미널·사적인 프로젝트 캡처·장식용 사진을 넣지 않는다.
- 설치/업데이트 모드, 언어 전환 중 선택 보존, 앵커, 요청문 확인, 닫기·Escape·초점 복귀, 복사 성공·수동 복사 대체를 실제 조작할 수 있게 한다. 복사를 설치 완료로 표시하지 않는다.
- 시안은 독립 HTML과 로컬 자산으로 다시 열 수 있어야 한다. 폴더 picker, IndexedDB, 제품 localStorage, 서비스 워커, API와 설치기를 호출하지 않는다.
- 사용자에게 필요한 설명만 페이지에 둔다. 배포 계약 준비·검증 공백·시안 적용 승인 등 제작자 보고는 검토 문서와 티켓에 남긴다.

## 검토 기준

- 1440×900과 390×844의 한국어·영어에서 첫 화면의 위계, 가로 넘침·텍스트 겹침, 다음 내용 노출, 폰트·아이콘 로드를 확인한다.
- `#skill`·`#updates` 진입, 언어 전환, 설치/업데이트 요청, 키보드·대화상자 닫기·초점 복귀, 복사 실패 처리를 확인한다.
- 보드와 Markdown의 데이터 일치 및 질문 결정 전후의 의미를 확인한다. 첫 화면에서 두 제품의 이름·행동·사용 가치가 보이는지, 업데이트가 설치 안내에 통합됐는지 확인한다. 시안의 기능 확인과 실제 스킬 설치·제품 앱 검증을 구분한다.
- 대화 재생·정지·되감기·장면 이동·언어 전환과 문서 상태가 일치해야 한다. 아이데이션 중에는 문서를 만들지 않고, 질문에 대한 결정과 문서 재검토가 구현 요청보다 먼저 나와야 한다. 질문 섹션 자체를 삭제해 해결한 것처럼 보이지 않게 한다.
- 재생 중 배속 변경·진행 막대 이동·종료 후 다시 재생을 검사한다. 탭·파일 목록·대화의 파일 링크가 같은 문서를 열며, 좁은 화면에서도 선택·시점이 유지되는지 확인한다.
- 산출물·검증 결과는 저장소 상대경로로 연결한다. 개인 경로·세션 ID·임시 미리보기 주소는 공개 문서에 기록하지 않는다.

## 확인·결정이 필요한 사항

- 사용자가 새 시안의 배치·카피·상호작용을 검토하고 채택 여부를 결정한다. 판단 전 AKI-02의 제품 적용과 AKI-03의 배포 계약 연결은 진행하지 않는다.
