- 한국어·영어 각각 1440×900, 1024×900, 390×844에서 첫 화면의 보드, 가로 넘침 부재, 문서 선택을 확인했다. 모바일 대화/문서 전환은 같은 메시지·선택 문서·스크롤을 유지한다. 기존 테마의 색상·컨트롤·폰트를 사용하며 별도 토큰을 도입하지 않았다.
- 21개 대화가 문서 없는 토론, 초안·질문, 결정 반영, 사람의 재검토, 구현, 피드백 순서로 진행된다. 초안 응답 전에는 파일이 없고, 질문은 문서 갱신 응답 뒤에만 해소된다. 뒤로 이동하면 해당 시점으로 돌아가며 마지막 기록은 첫 화면 보드와 같은 데이터를 사용한다.
- 브라우저 시계 제어로 0.5/1/2/3배속, 중간 배속 변경, 정지·재개, 전체 재생과 완료 후 다시 재생을 검사했다. `3:20 / 3:20`, `21 / 21`, 재생 완료와 다음 버튼 비활성화를 확인했다. 실제 휠로 위쪽을 읽으면 정지한다. 이 검사는 3분 20초의 실제 시간 관찰과 구분한다.
- 문서 탭·파일 목록·대화 링크의 선택 일치, 소스/미리보기, 언어 변경 중 위치·선택 보존을 확인했다. 요청문 모달의 Tab 순환, Escape, 애니메이션 종료 후 호출 버튼으로 초점 복귀를 검사했다. Clipboard 성공·거부는 대역으로 확인했으며 실제 개인 클립보드나 스킬 설치는 변경하지 않았다.
- `#skill`·`#updates` 직접 진입, 모드 버튼과 URL 일치, 상단 설치 링크, 새로고침·뒤로가기를 확인했다. 업데이트를 선택한 뒤 같은 설치 앵커를 누르면 모드가 남던 문제를 수정했다. 페이지 JavaScript 오류와 `/api/` 요청은 없었다. 개발 서버의 기존 favicon 404는 별도로 확인했다.
- 전체 테스트, typecheck, build를 통과했다. 새 회귀 검사는 재생 시간 계산·문서 경계·번역, 완료·재생·언어/페이지 숨김 정지·타이머 해제, 모달 복사와 지연 응답, 모드/앵커 동기화를 다룬다. 기존 intro 자동 열기 on/off·폴더 쿼리 격리와 공통 안내 테스트도 유지했다.
- `pnpm test:pwa`의 16개 검사를 통과했다. 격리 Chrome의 CDP 설치, 실제 OPFS 핸들, 오프라인 재실행·쓰기, 여러 창의 갱신 차단·적용, 복구·폐기와 설정 보존을 검증했다. 네이티브 설치 프롬프트나 사용자의 OS 폴더 선택을 새로 실행한 검사는 아니다. PWA 식별자·시작 주소·저장 구조·워커 정책은 변경하지 않았다.

## 구성

1. Alpha Kanban 이름과 `AI와 계획하고, 칸반에서 한눈에 확인하세요.`를 첫 화면에 둔다. implementation-ledger가 범위·결정·구현·검증을 Markdown에 남기는 역할을 바로 설명한다.
2. `칸반 시작하기`와 `스킬 설치하기`를 같은 크기의 채움·윤곽 버튼으로 함께 제공한다. 그 아래의 가상 독서 프로젝트 보드를 첫 화면에서 읽을 수 있다. 칸반을 하단 부록으로 다루지 않는다.
3. 네 티켓의 카드와 Markdown은 단일 데이터를 공유한다. 데스크톱은 티켓이 있는 네 상태를, 모바일은 선택한 상태를 보여준다. 각 카드에 범위와 남은 질문·검증을 담고 클릭하면 해당 기록을 읽는다. 진행 중인 READ-02는 필수 모바일 검증이 남아 75%이며 완료로 표시하지 않는다.
4. 21개의 한영 대화를 여섯 장면으로 따라간다. 문서·코드 없이 아이데이션하고, 초안 작성 요청 후 사람이 플랜·티켓과 열린 질문을 읽는다. 질문을 토론하고 결정 내용을 문서에 반영한 뒤 다시 읽으며, 이번 구현의 질문 해소와 최종 검토 후에만 순차 구현을 요청한다. 결과 검토·피드백은 다시 토론과 문서 갱신으로 이어진다. 티켓별 수동 지시나 미래 작업의 질문까지 모두 해소할 것을 요구하지 않는다. 3분 20초 분량의 진행 막대·경과/전체 시간·메시지 위치와 0.5/1/1.5/2/3배속을 제공하며, 재생 대기·재생 중·일시정지·재생 완료를 구분한다. 완료 후에는 자동 반복하지 않고 다시 재생할 수 있다.
5. 스킬 설치와 기존 스킬 업데이트를 같은 영역의 탭으로 묶었다. `#skill`과 `#updates`는 같은 위치에서 각각의 모드를 연다. 전체 폴더, 비교·백업·개인 수정 보존·덮어쓰기 전 확인 요청을 유지하며 별도 대형 업데이트 영역은 제거했다.
6. 마무리에도 칸반·스킬의 두 행동을 함께 둔다. 독립 사용 가능성은 사용 안내에서 한 번만 설명하며 보드 편집·폴더 연결을 AI 구현의 필수 조건으로 만들지 않는다. 실제 배포 버전·변경 이력·고정 다운로드 연결은 AKL-10/12/13과 AKI-03의 결과를 사용한다.

## 디자인 근거

- 첫 시안의 스킬 단독 강조와 칸반 부록 배치는 사용자 검토에서 채택되지 않았다. 이번 수정은 Local Codex에서 동일 시안의 브랜드·정보 위계·첫 화면 보드·설치 영역을 다시 구성한 결과다. 내부 티켓 표기 없는 제품 카피, 한국어 줄바꿈과 대화상자 Tab 순환을 유지했다.
- 단계 요약만 보여주던 구성을 대화 재생으로 바꿨다. 첫 대화 시안도 실제 Codex와 달라 사용자 피드백에 따라 다시 수정했다. 제공받은 앱 캡처를 참고해 오른쪽 회색 사용자 말풍선, 테두리 없는 AI 본문, 문서 변경 목록, 하단 읽기 전용 입력창을 구현했다. 최신 전체 화면 참조에 맞춰 채팅·문서 탭·본문·파일 목록을 하나의 Codex 모의 창으로 묶고 상단 높이와 구분선을 맞췄다. 재생·배속·진행 막대는 모의 창 바깥에 있다. 캡처 자체와 실제 대화·개인 경로는 산출물에 포함하지 않았다.
- 대화의 문서 링크, 우측 파일 탭과 목록은 같은 선택 상태를 공유한다. Markdown 소스/미리보기 전환을 제공하고 시점을 되돌리면 문서 내용도 함께 되돌린다. 모바일은 같은 창 안에서 대화/문서를 전환하며 대화로 돌아올 때 현재 장면을 유지한다.
- [현재 테마](../../../apps/web/src/styles.css)의 light semantic token과 Raleway Variable·Pretendard Variable을 사용했다. 섹션은 전체 폭 영역이며 문서 예시와 보드는 반복되는 가상 데이터를 사용한다.
- [이전 소개 시안](../akl-14-intro/README.md)은 테마·상호작용의 참고 자료이며 새 배치의 승인 근거로 사용하지 않았다.
- 정적 시안은 HTML 컨트롤로 상호작용을 표현한다. AKI-02 적용 시 기존 React·shadcn 컴포넌트와 공통 SkillGuide를 재사용하며 이 시안의 별도 CSS·아이콘 함수를 제품의 새 디자인 시스템으로 들이지 않는다.
- 로컬 폰트와 Lucide 라이선스는 [assets](prototype/assets/)에 함께 보존했다. 여기의 전체 Pretendard 파일은 시안 재열기용이며 제품의 폰트 패키징을 변경하지 않는다.

## 검증 결과

### 현재 통합 창과 재생 제어

2026-10-19 Chrome에서 현재 화면을 확인하고 격리된 Playwright 세션으로 아래 항목을 검사했다. 한영 각각 1440×900·1024×900·390×844의 여섯 조합에서 가로 넘침이 없었고, 모바일 대화/문서 전환 중 현재 메시지·선택 문서·대화 스크롤을 유지했다.

- 초기 재생 대기, 재생·일시정지, 이전/다음, 여섯 장면 이동, 진행 막대의 Home/End 이동을 확인했다. 마지막에는 `3:20 / 3:20`, `21 / 21`, `재생 완료`가 표시되고 다음 버튼만 비활성화된다. 재생 버튼은 다시 재생으로 바뀌며 선택한 배속을 유지한다.
- 초안 작성 응답 전에는 문서가 없고, 결정 내용을 갱신해 달라는 요청까지 질문을 유지한다. AI의 갱신 응답 뒤에만 질문이 `없음`으로 바뀌며, 뒤로 이동하면 그 시점의 질문이 다시 보인다. 사람의 재검토와 구현 요청 순서를 확인했다.
- 실제 타이머로 진행 막대가 움직이는 것을 확인했다. 브라우저 시계 제어로 메시지 중간의 1배속→2배속 변경·정지·재개·0.5배속·3배속 전체 재생·완료 후 재생의 경과 시간을 검사했다. 시점 이동 후에는 이전 타이머가 진행시키지 않고, 완료 후 자동 반복하지 않는다. 이 가속 검사는 3분 20초의 실제 시간 관찰과 구분한다.
- 실제 마우스로 위쪽 스크롤 시 일시정지하고, 요청문 대화상자를 열어도 정지하며 버튼 아이콘·이름이 함께 바뀌는 것을 확인했다. 프로그램의 자동 스크롤은 재생을 멈추지 않는다.
- 문서 생성 경계(59.9초/60초), 질문 해소 경계(129.9초/130초), 파일 탭·목록·대화 링크의 선택 일치, 소스/미리보기 전환, 언어 변경 시 위치·배속 보존을 검사했다. 모바일의 숨긴 대화창으로 돌아올 때 스크롤이 처음으로 돌아가던 문제를 수정하고 재검사했다.
- 읽기 전용 입력창은 실제 AI 입력을 받지 않는다. 모의 DOM 검사는 21개 메시지·문서 경계·재생 타이머·화면 숨김/스크롤 정지·분리된 이전 DOM의 지연 스크롤 이벤트·공유 티켓·요청문·복사 성공/실패 대역·초점 복귀·로컬 자산을 확인했다. 이 검사는 브라우저 배치 검증과 구분한다. 방향키·Space·모달 Escape·복사 안내의 실제 브라우저 검증은 앞선 대화 시안에서 수행한 기록을 유지한다.
- 실제 앱·PWA·사용자 폴더·설정·개인 스킬은 변경하지 않았다. 사용자 적용 판단, 실제 스킬 설치·업데이트, 제품 전체 테스트·배포는 이번 검증 범위가 아니다.

- 예시 장면 탭의 방향키·Home·End, 모바일 상태 선택, 카드 선택 후 Markdown의 ID·상태·진행률 일치를 확인했다. 첫 화면의 보드와 두 행동, 설치 영역 내부의 업데이트 앵커도 DOM 위치로 확인했다.
- 네 카드 × 두 언어의 상태·진행률 일치, 네 작업 요청문 × 두 언어의 열기·Escape·초점 복귀, 선택 티켓·사례 단계의 언어 전환 중 유지, 업데이트에서 명시적 설치 버튼으로 전환을 추가 확인했다. 페이지 로드 중 외부 origin 자산 요청은 없었으며 칸반 링크의 공개 URL만 확인하고 실제 프로젝트는 열지 않았다.
- 생성 시안의 모의 DOM 검사로 6종 요청문 × 2개 언어, 보드·Markdown의 4개 티켓, DONE 티켓의 미완료 체크 부재, 선택 유지, 자산·라이선스 존재와 폴더 picker·저장소·서비스 워커·네트워크 API 호출 부재를 검사한다. 모의 DOM 검사는 브라우저 검증을 대체하지 않는다.
- 실제 소개 코드·PWA·사용자 설정·연결 정보는 변경하지 않았다. 제품의 전체 테스트·빌드, 실제 스킬 설치·업데이트, 공개 배포 검증은 이번 시안 검증에 포함하지 않는다.
