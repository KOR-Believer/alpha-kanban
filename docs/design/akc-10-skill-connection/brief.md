# 스킬 폴더 연결 디자인 검토

기존 스킬 관리자에서 설치한 implementation-ledger 폴더 하나를 연결하는 흐름을 다듬는다. 새 설치·다중 스킬 관리·업데이트 엔진 교체는 범위 밖이다.

## 사용자 흐름

- 연결 전: 연결의 목적을 한 문장으로 설명한 뒤 전용 폴더 드롭 영역과 폴더 선택 버튼을 함께 제공한다. 상위 skills 폴더나 SKILL.md 파일 하나를 요구하지 않는다.
- 드롭 후: 폴더 이름과 대상을 확인하고 명시적인 버튼으로 읽기·쓰기 권한을 요청한다. 등록은 파일을 바꾸지 않으며 업데이트는 별도의 변경 비교와 확인을 거친다.
- 연결됨: 연결된 폴더, 설치본 확인 결과, 변경 확인·폴더 변경·연결 해제를 계층적으로 배치한다. 기존 비교·백업·복원 화면과 일관된 흐름을 유지한다.
- 권한 만료: 저장된 연결을 유지한 채 접근 다시 허용을 우선 제시한다.
- 실패: 다른 스킬·상위 폴더·파일·여러 항목·거부·취소 때 기존 연결을 유지한다. 필요한 다음 행동만 짧게 알린다. 드롭을 지원하지 않으면 폴더 선택을 사용한다.
- 위치 찾기: 외부 agent에게 실제 설치 위치를 확인하고 가능하면 파일 관리자에서 열어 달라는 요청을 제공한다. 선택창의 경로 이동은 Mac과 Windows를 구분해 안내한다. 앱이 임의의 홈 경로나 설치 위치를 알 수 있다는 표현은 금지한다.

## 시각 기준

- 현재 앱의 DialogHeader/Body/Footer, Button, Badge, CodeDiff, details 등 내부 컴포넌트 우선. 상단 배치와 기존 업데이트·백업 흐름은 유지한다.
- styles.css의 의미 토큰과 기존 간격·반경, Raleway/Pretendard 폰트를 사용한다. 별도 색상 체계를 만들지 않는다.
- 한국어/영어, 라이트/다크, 390px, 키보드 조작을 확인한다. 목적과 조건을 먼저 설명하고 예시·상세 안내는 그 뒤에 둔다.
- 개발 과정·로드맵·검증 현황은 시안의 제품 문구에 넣지 않는다. 스킬 경로는 개인 경로 대신 일반적인 예시를 쓴다.
