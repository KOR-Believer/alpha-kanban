# 스킬 폴더 연결 검토 결과

Local Codex의 독립 시안에서 연결 전·후, 권한 후보, 접근 재허용, 잘못된 대상과 여러 항목 드롭 흐름을 검토했다. 제품에서는 시안의 모달·파일 비교 엔진을 복제하지 않고 기존 내부 컴포넌트와 스킬 저장 엔진에 연결했다.

## 반영한 흐름

| 상태 | 화면과 동작 |
| --- | --- |
| 연결 전 | 목적 설명 뒤에 전용 폴더 드롭 영역과 폴더 선택 버튼을 함께 둔다. 위치 찾기 안내는 접어 둔다. |
| 드롭 후보 | 폴더의 루트 SKILL.md를 확인하고 이름·권한 설명·접근 허용 버튼을 표시한다. 기존 연결은 유지한다. |
| 폴더 선택 | 기존 readwrite 선택창을 사용한다. 선택과 권한 승인이 끝나면 같은 설치 검사로 합류한다. |
| 연결됨 | 연결한 폴더와 설치본 확인을 먼저 보여주고, 변경 비교·업데이트·재설치·백업은 기존 흐름을 유지한다. |
| 접근 만료 | 저장된 폴더를 지우지 않고 접근 다시 허용을 제공한다. 자동 권한 요청은 하지 않는다. |
| 실패·취소 | 여러 항목은 전체를 거절하고, 다른 스킬·파일·상위 폴더·권한 거부 때 기존 연결과 백업을 유지한다. |

`SkillFolderConnection`은 연결 상태와 위치 안내를 표시하고, `SkillUpdates`는 후보와 저장된 연결을 구분한다. `folderDrop`은 드롭 이벤트 안에서 핸들 요청을 시작한다. `verifySkillDirectory`와 `SkillRepository.connect`를 공유하며 부모·홈 디렉터리를 탐색하지 않는다.

DialogHeader/Body/Footer, Button, Badge, Textarea, 기존 CodeDiff와 의미 색상 토큰을 재사용했다. 시안에서 제안한 새 팔레트나 모의 업데이트·백업 상태는 가져오지 않았다. 중단된 복구의 연결 해제 정책도 기존대로 유지한다.

일반 안내와 복사 요청은 사용자의 AI 도구를 기준으로 한다. 실제 Codex 경로를 안내하는 수동 설치는 도구 이름이 붙은 예시로 구분한다. 다른 AI 도구의 기본 경로나 설치 지원을 추측하지 않는다.

파일 목록의 추가·변경·삭제는 초록·주황·빨강 배지와 글자로 함께 표시한다. 일반 업데이트·재설치·PWA 업데이트가 같은 `SkillChanges`를 사용한다. 스킬 관리자는 티켓과 같은 가장자리·모서리 드래그와 키보드 크기 조절을 사용하고, 전체 화면·이전 크기·기본 크기 복원을 제공한다. 크기와 표시 방식은 티켓 설정과 별도로 기억한다. 헤더·닫기 버튼을 고정하고 본문만 스크롤하며, 크기 전환으로 비교 내용이나 확인 체크를 초기화하지 않는다.

`SkillComparisonSummary`는 현재 설치본과 적용할 스킬을 구분한다. 설치본의 전체 경로·파일 해시가 대상 묶음과 같으면 같은 번들 ID를 표시하고, 알려진 이전 배포본과 같으면 그 기록의 원본 커밋을 표시한다. 어느 쪽과도 일치하지 않으면 배포본 식별 안 됨으로 표시하며 버전을 만들지 않는다. 오른쪽은 실제 적용 대상의 채널과 번들 ID이고, PWA에서는 대기 중인 릴리즈를 따른다. 개별 diff 열도 현재 설치본/적용할 스킬로 구분한다. 호환성 확인과 적용 동의는 출처 표시와 별도로 유지한다.

## 확인 결과

- 자동 검사: 단일 디렉터리 핸들의 동기 획득, 루트 검사, 여러 항목·파일·다른 스킬·상위 폴더·미지원 거절, 권한 확인 전 미등록, 거부·취소의 기존 연결/백업 보존, 같은 핸들의 재연결, 늦은 응답 무시와 언어 전환을 확인했다.
- 기존 공식 업데이트·명시적 재설치·백업/복원·외부 변경·복구·PWA 동의를 포함한 웹 테스트 619개와 타입 검사가 통과했다. 실제 파일 보호의 OS 검증과는 구분한다.
- 배지·크기 조절 추가 후 웹 테스트 622개가 통과했다. 자동 검사로 비교 DOM·동의 보존, 독립 설정, 재마운트 후 크기 복원, 뷰포트 축소 후 원래 크기 복원, 드래그 중 Escape와 저장 중 닫기 거절을 확인했다. Mac Chrome에서는 실제 모서리 드래그, 전체 화면 왕복, 한국어 라이트·영어 다크의 390px 배치와 내부 스크롤을 확인했다. 이 검증은 파일 연결의 Windows 실기기 검증을 대신하지 않는다.
- 비교 대상 표시 변경은 현재 묶음·기존 공식 배포본·본문 수정·추가 파일의 식별과 미확인 호환성 상태의 적용 차단, 재설치·PWA 비교를 포함한 관련 검사 118개로 확인했다. 문서 정리 diff의 기본 변경 전/후 표시는 유지했다. Mac Chrome 스모크에서 설치본의 원본 커밋과 적용 대상 번들 ID, 좁은 화면의 세로 배치를 확인했다.
- macOS Chrome: agent가 실제 합성 폴더 선택과 readwrite 허용, 새로고침 후 연결 유지, 한국어 라이트/영어 다크 390px 배치, Escape와 트리거 초점 복귀를 확인했다.
- 실제 Finder 드롭은 agent의 시도로 성공을 입증하지 못했다. 사용자가 직접 수행한 뒤 후보 확인과 권한 허용·연결이 정상이라고 보고했다. 이를 사용자 확인 결과로 기록한다.
- Mac 스모크의 기존 합성 파일 35개는 해시가 유지되었다. 파일 관리자가 만드는 `.DS_Store` 같은 OS 메타데이터는 검사 결과에서 별도 표시하고 스킬 파일 변경과 구분한다.
- Windows 실제 폴더 검증 결과는 아래 2026-11-05 수신 기록을 따른다. 같은 날 Mac에서도 전체 Chrome 종료·재시작과 개별 폴더 권한 철회 후 재허용을 확인했다. 탭 새로고침 결과와 프로세스 재시작 결과를 구분한다.

현재 `SkillRepository.inspect`도 대상 호환성이 미확인이면 설치본 분류보다 `review`를 먼저 반환한다. 개인 수정본 전용 안내에 도달하지 않는 원인은 보고서와 일치한다. 다만 파일 목록과 해시는 현재 묶음·기록된 공식 스냅샷과의 일치 여부만 증명하며, 미등록 공식 빌드와 개인 수정본을 확실히 구별하지 못한다. 현재 비교 요약의 `배포본 식별 안 됨`이 적절한 표시다. 검증 기준은 개인 수정 여부를 단정하는 문구가 아니라 설치본의 확인 가능한 출처, 호환성에 따른 적용 제한, 원본 파일 보존이다.

2026-11-05 사용자 결정으로 위 안내와 권한 복구에 추가 기능 개선을 요구하지 않는다. 사이트 설정에서 권한을 다시 켠 뒤 새로고침으로 저장된 연결을 재사용한 결과는 허용되는 복구 경로다. 자동 감지·자동 새로고침을 완료 조건에 추가하지 않는다. 원본 보고서의 실패·부분 확인 표시는 당시 기대값과 관찰 범위로 보존하며, 이 두 건을 제품 결함이나 배포 차단으로 취급하지 않는다. Windows의 전체 재시작 후 저장된 폴더 재허용은 통과했지만, 개별 폴더 권한 철회 경로까지 확인했다고 확대하지 않는다.

## 재현 자료

`scripts/package-skill-connection-smoke.mjs`는 빌드된 정적 앱, 검증된 이전 공식 스냅샷으로 만든 합성 설치본, 잘못된 대상과 여러 폴더 사례, 결과 작성 화면과 파일 해시 검사기를 ZIP으로 묶는다. 개인 설치본·프로필·브라우저 데이터는 읽거나 포함하지 않는다.

ZIP 실행에는 Node.js가 필요하며 저장소 체크아웃이나 pnpm은 필요하지 않다. 등록만으로 파일이 바뀌지 않는지 검사하고, 실제 업데이트·재설치·복원 적용은 이 수동 연결 검사에서 하지 않는다. 결과 JSON과 파일 검사 JSON을 함께 받아 OS별 검증에 기록한다.

Mac의 실제 재시작·권한 복구 검증과 Windows 결과 판정을 마쳐 AKC-10을 DONE 100%로 정리했다. 공개 배포와 개인 스킬 변경은 수행하지 않았다.
