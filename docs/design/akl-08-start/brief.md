# AKL-08 Start 화면 시안

작성일: 2026-10-18
상태: 디자인 제작용 확정 요구. 사용자 디자인 승인은 별도다.

## 목적과 경계

Alpha Kanban은 로컬 Markdown을 읽고 사용자의 지시를 문서에 남기는 작업 도구다.
지금은 제품 코드 적용이 아니라 Open Design에서 검토할 시작 화면만 만든다.
실제 앱, 연결 폴더, 개인 AI 설정, 기존 Open Design 프로젝트를 수정하지 않는다.
새 디자인 프로젝트 안에서만 작업하며 이름과 데이터는 전부 가상으로 만든다.
외부 공개, 배포, 실제 스킬 설치, 실제 폴더 권한 요청, AI 실행은 하지 않는다.

## 화면 구성

- 웹앱 Start 화면이지 홍보용 랜딩이 아니다. 화면의 가용 가로폭을 사용한다.
- 상단은 Alpha Kanban 로고/이름, 작은 언어 선택, 전체 티켓 진입점이다. 선택하지 않은 프로젝트의 사이드바나 빈 문서 헤더를 만들지 않는다.
- 페이지 제목은 작고 명확하게 둔다. 프로젝트 열기, 워크스페이스 등록, 새 프로젝트를 간결한 명령 버튼으로 묶는다.
- 마지막 프로젝트 자동 열기는 카드 없이 체크박스다. 변경 시 즉시 이동하지 않고 다음 시작부터 적용하는 설정이다.
- 최근 프로젝트는 왼쪽, 나머지 프로젝트는 오른쪽이다. 양쪽 제목과 검색/정렬 도구는 고정하고 같은 높이의 목록 내부만 각각 스크롤한다.
- 최근 목록과 다른 목록에 같은 프로젝트를 중복 표시하지 않는다. 최근 기록이 없으면 정말 비워 두며 임의의 항목을 최근으로 꾸미지 않는다.
- 행은 프로젝트 이름, 등록된 워크스페이스 기준의 상대 위치, 간결한 문서/권한 상태로 구성한다. 프로젝트마다 큰 카드를 반복하지 않는다.
- 등록된 워크스페이스는 작은 목록 또는 관리 진입점으로 둔다. 높이가 무한히 늘어나거나 중첩 카드가 생기지 않게 한다.
- 목록이 길어져도 AI 작업/스킬 안내가 계속 아래로 밀리지 않아야 한다. 약 1440x900 화면에서 두 목록과 안내의 주요 진입점이 함께 보이는 밀도를 제안한다.
- 좁은 화면에서는 최근/다른 프로젝트를 탭으로 전환하는 단일 목록을 우선 시안으로 검토한다. 이것은 이번 시안의 제안이며 제품 결정 완료로 간주하지 않는다.

## 워크스페이스 용어

기본 명칭은 '워크스페이스 등록'이다. 설명이 필요한 등록 창에서 다음 의미를 전달한다.

> 프로젝트들이 모여 있는 상위 폴더를 등록하면 바로 아래 폴더들을 프로젝트로 자동 탐색해 추가합니다.

프로젝트 열기는 폴더 하나를 직접 여는 동작이다. 워크스페이스 등록이 필수 선행 단계가 아니다.
파일을 복사하거나 업로드하는 동작으로 설명하지 않는다. 중첩 등록은 더 구체적인 워크스페이스를 우선한다.
브라우저에서는 새 프로젝트 폴더를 만들 수 있지만 git init이나 Codex 실행은 지원하지 않는다.

## AI 작업과 스킬 안내

길고 거대한 설명 카드 대신 읽을 수 있는 짧은 흐름과 자세히 보기로 구성한다.

1. 외부 AI 도구에서 만들고 싶은 기능과 사양을 논의한다. 문서가 없는 프로젝트로 시작해도 된다.
2. implementation-ledger로 계획과 티켓을 만들고, 필요할 때 인벤토리를 만든다.
3. 이 화면에서 문서를 검토하고 상태 변경 사유나 수동 지시를 기록한다.
4. AI 도구에 최신 문서를 다시 읽도록 요청하고 티켓을 진행한다. 수정과 검토를 반복한다.

주요 설치 동작은 'Codex에 전달할 설치 요청 복사'다. GitHub 원본 보기와 인라인 설치 안내를 제공한다.
ZIP은 보조 수단이다. 스킬 없이도 호환 Markdown을 볼 수 있다.
설치 요청 예시는 전체 스킬 폴더, 검증한 배포 출처, 기존 개인 수정 비교와 보존을 요구한다.
아직 공개하지 않은 버전/태그/설치 파일이 배포된 것처럼 표시하지 않는다.
버전 영역은 '배포 버전: 준비 중', '설치된 버전: 이 웹에서 확인하지 않음'처럼 사실과 예시를 구분한다.
Claude 설치와 검증은 후속 예정이며 지원 완료로 표시하지 않는다.
웹이 AI를 실행하거나 스킬을 자동 설치하는 것처럼 보이는 채팅창/실행 버튼을 추가하지 않는다.

## 디자인 기반

기존 Alpha Kanban의 shadcn b1 기반을 유지한다. Notion 테마나 새 색상 체계로 교체하지 않는다.
아래는 현재 styles.css에서 읽은 참고 토큰이다. 시안 내부에서도 의미별 변수로 재사용한다.

```css
:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.153 0.006 107.1);
  --card: oklch(1 0 0);
  --primary: oklch(0.841 0.238 128.85);
  --primary-foreground: oklch(0.405 0.101 131.063);
  --muted: oklch(0.966 0.005 106.5);
  --muted-foreground: oklch(0.58 0.031 107.3);
  --border: oklch(0.93 0.007 106.5);
  --sidebar: oklch(0.988 0.003 106.5);
  --ring: oklch(0.737 0.021 106.9);
  --radius: 0.625rem;
  --ak-space-xxs: 4px;
  --ak-space-xs: 8px;
  --ak-space-sm: 12px;
  --ak-space-md: 16px;
  --ak-space-lg: 24px;
  --ak-space-xl: 28px;
  --ak-space-xxl: 32px;
}
```

- Raleway Variable와 시스템 한글 fallback을 쓴다. 자간은 0이다.
- 기존 버튼은 기본 높이 32px, 작은 버튼/언어 선택은 28px다. 모바일 터치 목표는 충분히 확보한다.
- 가는 테두리와 절제된 그림자, 밝은 중립 배경, 제한된 acid-green 강조를 쓴다.
- 도구 버튼은 Lucide 아이콘을 사용하고 아이콘 단독 버튼은 이름/툴팁을 제공한다.
- 입력/선택/체크박스/팝오버/모달은 shadcn 기반 스타일과 접근성을 유지한다. 기본 브라우저 select로 대체하지 않는다.
- 모달 제목/본문/하단의 좌우 패딩을 맞춘다. 크기가 커지는 컨트롤이나 중첩 스크롤바를 피한다.
- 페이지 섹션을 떠 있는 카드들로 감싸거나 카드 안에 카드를 넣지 않는다. 표제/목록/구분선 중심의 작업 화면이다.
- 장식 사진, 히어로, 그라디언트, 큰 마케팅 카피, 과한 배지는 필요 없다.
- 사용자용 UI와 시안 검토용 상태 전환기는 분리한다.

## 검토할 상태와 동작

- 기본/많은 프로젝트: 가상 프로젝트 약 30개, 최근 5개와 나머지의 중복 없는 목록. 양쪽 독립 스크롤과 고정 제목.
- 최근 기록 없음: 최근 칸은 빈 상태이며 나머지 프로젝트는 그대로다.
- 연결 폴더 없음: 프로젝트 열기/워크스페이스 등록과 AI 문서 생성 안내가 보인다.
- 권한 재연결: 해당 행만 재연결 상태를 표시하고 다른 행은 정상 사용한다. 실제 OS 권한 창은 열지 않는다.
- 검색 결과 없음, 긴 이름/경로, 한국어/영어 문구, 자동 열기 체크 상태를 확인한다.
- 워크스페이스 등록 설명, 스킬 설치 안내, 예시 설치 요청 복사, 새 프로젝트 모달의 열기/닫기/입력 상태를 검토할 수 있게 한다.
- 데스크톱 1440x900/1920x1080, 좁은 화면 390x844를 기준으로 넘침/가림 없이 확인한다.
- 가상 프로젝트 열기나 전체 보드 이동은 테스트용 안내만 표시한다. 실제 제품/파일로 이동하거나 쓰지 않는다.

## 산출물과 승인

- Open Design에서 다시 열 수 있는 프로젝트와 렌더 가능한 index.html.
- 상태 전환용 review.html 또는 query parameter 목록. 각 상태로 바로 갈 수 있어야 한다.
- 주요 화면 캡처와 짧은 동작/검증 기록.
- 사용자 승인 전에는 AKL-09/13 앱 적용으로 넘어가지 않는다. 생성 성공은 승인이나 구현 완료가 아니다.

## 확인·결정이 필요한 사항

- 생성된 시안의 배치와 좁은 화면 구성을 사용자 검토 후 확정한다.
