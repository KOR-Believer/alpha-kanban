# AKD-13 연결과 문서 탐색 시안 검토

작성일: 2026-11-03

## 검토할 흐름

1. `검색 개선 계획`의 `검색 화면 설계` 링크를 누른다.
2. `product-local`을 선택하고 `선택한 폴더 확인`을 누른다.
3. 옛 `/old/product`와 내 `product-local`, 실제 열 파일 `docs/design/spec.md`를 함께 확인한다. 연결은 `Product Notes`에서 해당 경로의 링크에 재사용한다.
4. `연결하고 열기`를 누르면 읽기 전용 문서 페이지로 이동한다.
5. 본문의 `검색 API 계약`을 열고 브라우저 뒤로가기·앞으로가기·새로고침으로 문서를 오간다. 절대 링크와 상대 링크 모두 같은 문서로 이어진다.
6. 페이지 아래의 `시안 검토 도구`에서 하위 폴더 연결, 여러 대응 후보, 파일 없음, 권한 만료, 초안 보존 등의 상태를 고른다. 이 도구는 제품 UI에 추가할 기능이 아니다.

## 디자인에서 달라지는 부분

- 내 repo를 고른 뒤 원래 경로의 대응 범위를 확인한다. 기존처럼 옛 경로부터 사람이 계산해 선택하는 순서를 바꾼다.
- 연결 확인 화면은 내 폴더·옛 폴더·열 파일·재사용 범위를 한곳에서 보여준다. Git 없는 폴더와 하위 폴더 연결도 같은 화면에서 범위 차이를 드러낸다.
- 문서 연결만 대화상자로 처리한다. 연결한 문서는 본문 페이지로 열고, 다음 링크에서도 모달을 쌓지 않는다.
- 원래 프로젝트의 문서 목록을 유지하고 연결 문서의 repo·내부 경로·읽기 전용 상태와 출발 문서 복귀를 표시한다.
- 기존 Dialog·Button·Input·Select·Badge 등의 규격을 독립 HTML 시안에 대응했다. 제품 React 컴포넌트를 통합한 결과는 아니며 새 shadcn 의존성을 추가하지 않았다.
- 초기 시안의 제품 영역에 들어간 개인 메모 입력은 제거했다. 초안 보존 검토는 시안 검토 도구에서만 수행한다.

## 검증 범위

기존 Chrome의 별도 시안 탭에서 가상 문서로 확인한다. 실제 폴더 선택·Git 탐색·OS 권한·IndexedDB·제품 초안 보호의 검증 결과로 해석하지 않는다. 권한 확인 대화상자는 OS 응답을 가상으로 보여주는 대역이며, 제품에 추가 확인창을 만드는 결정이 아니다.

1차 시안에서 repo 선택과 명시적 저장, 연결 문서의 절대·상대 링크, 뒤로가기·새로고침, 여러 대응 후보의 미선택 상태, 하위 폴더 범위와 Escape 후 초점 복귀, 영어·다크·390×844의 파일 없음/권한 화면을 확인했다.

2026-11-03 작업 에이전트가 최종 보완본에서 다음을 다시 확인했다. 사람의 디자인 승인이나 제품 기능 검증을 뜻하지 않는다.

- repo 선택 → 원래 경로·내 폴더·실제 파일 확인 → 명시적 저장 → 문서 페이지 이동. 연결한 문서의 후속 링크와 뒤로·앞으로가기, 새로고침 후 동일 문서 및 연결 유지.
- 제품 밖 검토 도구에 입력한 가상 초안이 문서 이동·언어 전환·새로고침 뒤에도 유지됨. 제품 화면에는 메모 입력 기능이 없음.
- 한국어·라이트 데스크톱 화면과 영어·다크 모바일 화면. 390×844에서 문서 위치는 전체 폭의 별도 행, 문서 목록·연결 관리 버튼은 다음 행이며 가로 넘침 없음.
- 문서 본문 14px, 헤더 버튼의 접근성 이름 중복 제거, 연결 취소 후 출발 링크로 초점 복귀.

최종 캡처는 위 산출물에 보관한다. 실제 OS 폴더 권한, Git 탐색, 제품 라우터·IndexedDB·초안 보호, 스크린리더 및 모든 예외 상태 조합의 검증은 이번 디자인 검토 결과에 포함하지 않는다.

## 연결 시나리오 보강

2026-11-03 사용자가 주요 연결 시나리오의 빈틈을 보강하도록 요청했다. 상단의 언어·테마와 나머지 도구의 순서 및 좁은 폭의 글자 생략은 유지한다. 생성 결과의 헤더 함수와 폰트·라이선스 파일이 이전 시안과 같은 것도 확인했다.

| 검토 도구에서 고를 상태 | 보강한 내용 |
| --- | --- |
| 여러 root · 같은 이름 · clone/worktree | 이름이 같은 세 폴더를 등록 root·그 안의 위치·작업 폴더 유형으로 구분한다. root 필터와 이름·위치 검색을 제공한다. |
| 기존 좁은 연결 유지 | 저장할 연결과 이번에 실제 사용할 연결을 따로 보여준다. 기존 하위 연결을 유지하거나 명시적으로 변경할 때 최종 안내와 실제 열린 폴더·파일이 일치한다. |
| 검색 가능한 root 없음 / 검색 결과에 repo 없음 | 상황에 맞는 이유와 직접 선택을 제공한다. 상위 위치를 모르는 직접 선택 폴더는 이름·내부 파일만 표시한다. |
| 탐색 깊이 제한 / 탐색 시간 제한 / Git 정보 확인 불가 | 불완전하거나 확인할 수 없는 범위를 알리고 발견된 후보 선택·재검색·직접 선택을 유지한다. |
| Windows 드라이브 · 한글 경로 / UNC 공유 · 공백 경로 / 긴 원본 경로 · 긴 파일명 | 전체 원본 주소와 실제 파일을 읽을 수 있게 표시하고 연결·후속 링크·새로고침까지 이어지는 가상 사례를 제공한다. |

작업 에이전트가 기존 Chrome의 별도 시안 탭에서 다음을 확인했다.

- root 필터 및 `harness/tools`, `worktrees` 검색으로 동명 후보를 구분하고, 선택한 worktree 위치가 최종 확인과 열린 문서에 동일하게 표시됨.
- 겹친 연결 유지 시 기존 `design/spec.md`, 명시적 변경 시 선택한 worktree의 `design/spec.md`가 열림. 임시 변경 뒤 최종 취소하면 기존 연결 하나만 남고 기존 문서가 열림.
- root가 없는 상태에서 일반 폴더를 직접 연결할 수 있음. 후보·확인 화면·문서·연결 관리에 알 수 없는 상위 위치가 표시되지 않음. repo 없음·깊이/시간 제한·Git 확인 실패 안내와 후속 행동을 확인함.
- Windows 드라이브와 UNC 사례에서 절대·상대 링크 모두 다음 문서로 이동하며, 브라우저 뒤로가기와 새로고침 후 연결이 재사용됨. 긴 한글 파일명 사례도 후속 상대 링크와 새로고침을 확인함.
- 390×844 영어·다크 화면에서 UNC 및 긴 경로의 페이지·대화상자에 가로 넘침이 없고, 최종 행동 영역이 화면 안에 유지됨. 긴 원본 주소 전체를 펼쳐 읽을 수 있음.

직접 선택 위치 표시의 최종 수정은 후보·위치 표시와 빈 목록 안내에 한정되며 경로 해석·겹침 우선순위·저장 함수는 앞선 보강본과 동일하다. 생성 도구가 수행한 논리 검사는 별도 검토 노트의 기록이며, 위 브라우저 검토와 구분한다. 제품 소스 119개 파일의 작업 시작 전후 해시가 같았고, 새 의존성이나 실제 폴더 연결은 추가하지 않았다. 이 기록은 사람의 디자인 승인이나 Windows 실기기 검증을 뜻하지 않는다.

## 확인·결정이 필요한 사항

- 없음. 보강된 시안의 제품 적용은 승인됐다. 연결 문서의 본문은 기존 일반 문서 뷰어·렌더러를 공유한다.
