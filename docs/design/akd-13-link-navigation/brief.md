# AKD-13 repo 연결과 문서 페이지 탐색 디자인 브리프

작성일: 2026-11-03

## 목적과 범위

- [팀 문서 계획](../../24_alpha_kanban_team_documents_plan.md#9-연결-범위를-이해하고-문서를-연속해서-읽는-ux)과 [AKD-13](../../25_alpha_kanban_team_documents_tickets.md#akd-13-링크-연결과-문서-탐색의-ux를-먼저-검토한다)을 기준으로 설치된 디자인 프로그램의 Local Codex에서 검토 가능한 시안을 만든다. 사용자가 클라우드 로그인 사이트 대신 로컬 프로그램 사용을 지정했다.
- 다른 PC 경로의 링크를 내 repo에 한 번 연결하고, 그 repo의 다른 문서를 따라 읽을 때 연결을 반복하지 않는 흐름을 보여준다.
- 이번 산출물은 제품 적용 전 디자인이다. 사용자가 디자인을 본 뒤 AKD-14·15 구현을 결정한다. 앱 소스, 사용자 폴더 연결, 원본 Markdown, agent 설정과 배포는 변경하지 않는다.
- 공개용 가상 프로젝트와 문서만 사용한다. 시안은 실제 폴더 선택·파일 쓰기·프로젝트 등록·서비스 워커를 실행하지 않는다.

## 현재 확인한 문제

- `LocalLinkDialog`는 링크 파일의 바로 위 폴더를 기본 연결 범위로 선택한다. 내 repo를 골라도 옛 경로의 범위가 그대로여서 사용자가 두 폴더의 대응을 계산해야 한다.
- `MarkdownResources`는 정상 프로젝트 문서를 페이지로 열지만 연결 문서는 읽기 모달로 연다. 다음 문서를 눌러도 모달이 쌓이고 URL과 브라우저 방문 기록은 읽는 문서를 따라가지 않는다.
- 연결해서 연 문서의 상대 링크는 현재 폴더를 기준으로 읽지만, 옛 절대경로는 출발 프로젝트의 저장된 연결을 이어받지 못한다.
- 이번 디자인의 핵심은 repo 대응과 재사용 범위의 이해, 그리고 일반 문서와 일관된 페이지 탐색이다. 보드·전체 팀 기능·프로젝트 등록 체계를 다시 설계하지 않는다.

## 기본 시나리오

가상 프로젝트는 `Product Notes`, 내 repo 표시 이름은 `product-local`로 한다. 폴더 이름이 달라도 실제 내부 경로를 대조해 사용자가 연결을 확인한다.

| 대상 | 가상 예시 |
| --- | --- |
| 출발 문서 | `docs/12_search_plan.md`, 제목 `검색 개선 계획` |
| 클릭한 옛 링크 | `/old/product/docs/design/spec.md` |
| 연결할 옛 repo 범위 | `/old/product` |
| 내 repo에서 열 파일 | `product-local` 안의 `docs/design/spec.md`, 제목 `검색 화면 설계` |
| 다음 절대 링크 | `/old/product/docs/api.md`, 제목 `검색 API 계약` |
| 다음 상대 링크 | `../api.md`, 현재 `docs/design/spec.md` 기준 |
| 다른 종류의 파일 | `/old/product/src/search.ts`, 기존 다운로드 동작 유지 |

1. 기존 문서 화면에서 `검색 화면 설계` 링크를 누른다. 현재 연결로 열 수 없으면 폴더 연결 대화상자가 열린다. 출발 문서와 배경 화면은 보존한다.
2. 연결해 둔 root 아래 발견한 repo를 검색·선택하거나 `폴더 직접 선택`으로 연결할 폴더를 고른다. 발견한 항목은 후보이며 이름이 비슷하거나 하나뿐이라는 이유로 연결을 확정하지 않는다.
3. 선택한 폴더 안에 실제로 있는 경로를 바탕으로 대응을 제안한다. 옛 `/old/product`와 내 `product-local`, 열릴 `docs/design/spec.md`를 함께 보여준다. 긴 옛 PC 주소는 확인에 필요한 범위만 강조하되 전체 주소도 펼쳐 읽을 수 있게 한다.
4. `연결하고 열기`를 누를 때만 저장한다. 확인 전에는 후보 선택이나 취소로 저장되지 않는다. `Product Notes에서 이 repo의 링크에 재사용`한다는 범위를 읽을 수 있게 한다.
5. 연결 대화상자를 닫고 `검색 화면 설계`를 읽기 전용 문서 페이지로 연다. 문서 제목·repo 이름·repo 내부 경로·읽기 전용 상태·출발 문서로 돌아가는 동작이 구분되어야 한다.
6. 그 안의 `검색 API 계약` 링크를 누르면 같은 연결을 재사용해 다음 문서 페이지로 이동한다. 절대 링크와 상대 링크 모두 제공하되 상대 링크는 현재 문서 위치가 기준이다.
7. 브라우저 뒤로가기·앞으로가기·새로고침으로 읽는 문서를 유지한다. 직접 주소 진입도 같은 브라우저의 저장된 연결로 열며 주소에는 PC 경로 대신 불투명 식별자를 사용한다.

## 화면 구성의 검토 방향

- 기존 프로젝트 화면의 헤더·문서 목록·본문 영역을 바탕으로 한다. 연결 과정은 대화상자, 연결 결과는 본문 페이지로 구분한다.
- 대화상자에서 폴더 선택과 연결 확인은 같은 흐름으로 이어진다. 사용자가 원본 앞 경로부터 수동으로 고르게 하는 현재 순서는 개선한다. 단계 수와 세부 배치는 시안에서 검토한다.
- 확인 화면은 `내 폴더`, `연결할 원래 폴더`, `열 파일`의 관계를 읽을 수 있게 한다. 읽기 어려운 원시 경로 입력 두 개만 나란히 놓지 않는다. 주 행동은 한 개로 두고 범위 변경은 보조 행동으로 둔다.
- 연결 문서 페이지는 기존 Markdown 본문 스타일과 문서 헤더를 재사용한다. 출발 프로젝트 문서 목록을 연결 repo의 전체 파일 목록으로 몰래 교체하거나 새 프로젝트가 등록된 것처럼 표시하지 않는다.
- 읽기 전용 문서에는 편집·티켓 상태 변경 버튼을 두지 않는다. 연결 확인·변경이 필요할 때는 현재 문서의 연결 정보에서 기존 관리 흐름으로 접근한다.
- 사용자 카피에는 현재 조작에 필요한 정보만 둔다. 개발 진행, 티켓 번호, 테스트 한계, IndexedDB·핸들·resolver 같은 구현 설명은 시안 바깥 검토 자료에 둔다.
- 상단의 언어·테마와 나머지 도구를 나누는 순서, 폭이 좁아질 때 도구의 글자를 생략하고 아이콘을 유지하는 동작은 사용자 선호로 유지한다.

## 함께 설계할 상태

| 상태 | 화면에서 확인할 내용과 동작 |
| --- | --- |
| repo 검색 중·일부 폴더 검색 실패 | 발견한 후보를 먼저 보여주고 직접 선택·검색 중단을 제공한다. 실패를 빈 목록의 정상 완료로 표시하지 않는다. |
| 여러 repo 또는 여러 경로가 대응 | 후보마다 폴더 위치와 열릴 상대경로를 비교하게 한다. 서로 다른 등록 root·중첩 깊이에 있는 동명 repo와 같은 repo의 여러 clone/worktree를 구분하는 예시를 포함한다. 선택하기 전에는 연결을 확정하지 않는다. |
| root 없음·repo 없음·탐색 제한·Git 정보 확인 실패 | 원인을 구분해 짧게 안내하고 직접 폴더 선택으로 이어진다. 발견된 후보는 선택할 수 있게 유지하며 불완전한 탐색을 정상 완료나 후보 유일성으로 표시하지 않는다. 등록 root가 없어 상위 위치를 모르는 직접 선택 폴더에는 이름과 확인한 내부 파일만 표시하고 상위 위치를 만들어내지 않는다. 새 프로젝트 등록 마법사는 추가하지 않는다. |
| Git 없는 폴더·하위 폴더만 연결 | 직접 선택을 유지한다. `/old/product/docs/design`과 내 `design`을 연결했다면 `spec.md`를 열고 재사용 범위도 그 하위로 제한됨을 보여준다. |
| 선택한 폴더에 파일 없음 | 찾으려던 상대경로를 유지하고 다른 폴더 선택·범위 변경·취소를 제공한다. 다른 동명 파일로 자동 대체하지 않는다. |
| 이전에 저장한 좁은 연결이 있음 | 넓은 repo 연결로 조용히 덮어쓰지 않는다. 저장할 연결과 이번 파일을 여는 데 적용할 연결을 구분한다. 최종 확인에 표시한 폴더·파일이 실제 열린 문서와 일치해야 한다. 기존 연결 유지와 명시적인 변경·취소를 기존 관리 흐름에서 검토한다. |
| Windows·네트워크·긴 한글 경로 | 드라이브·UNC·공백과 긴 한글 이름의 원본 주소를 확인하고 범위 선택·재사용·새로고침까지 이어지는 가상 예시를 둔다. 전체 주소 열람과 줄바꿈을 제공하며 좁은 화면에서도 실제 열 파일과 주 행동을 읽을 수 있게 한다. |
| 저장 실패·다른 창에서 연결 변경 | 성공 화면으로 넘어가지 않는다. 선택과 요청 파일을 유지하고 다시 확인할 방법을 제공한다. |
| 폴더 권한 만료 | 같은 요청 문서를 유지한 채 `접근 허용` 또는 다른 폴더 선택을 제공한다. 화면을 여는 것만으로 권한 창을 띄우지 않는다. |
| 연결 해제·파일 삭제·알 수 없는 주소 | 문서 페이지에서 열려던 대상을 유지하고 재연결 또는 출발 문서 복귀를 제공한다. 임의의 문서로 이동하지 않는다. |
| 취소·Escape | 저장·이동 없이 출발 링크에 초점을 돌린다. 기존 문서·스크롤·초안을 보존한다. |
| 작성 중인 초안이 있는 상태의 이동 | 기존 초안 보호와 복귀 동작을 유지한다. 시안에서는 가상 초안으로 확인하며 실제 앱의 저장 기능을 실행하지 않는다. |

연결은 같은 출발 프로젝트에서 이어 읽는 동안만 재사용한다. 별개 프로젝트로 전역 공유하지 않는다. 연결 상태와 실제 파일을 다시 확인하는 제품 검증은 AKD-14·15에서 수행한다.

2026-11-03 후속 검토에서 겹친 연결의 확인 화면이 새 repo의 파일을 안내하지만 실제로는 기존 하위 폴더의 파일을 여는 불일치를 재현했다. 사용자는 위 네 가지 보강을 요청했다. 이 시안에서는 우선순위를 바꾸거나 기존 연결을 자동 삭제하지 않고 안내와 실제 열 대상을 일치시킨다. 실제 앱의 구현 완료로 기록하지 않는다.

## 시각 기준

- `apps/web/src/styles.css`의 shadcn b1 기반 의미 토큰을 기준으로 한다. 새로운 색·간격 체계를 만들지 않는다.
- 폰트 순서는 Raleway Variable → Pretendard Variable → system sans다. 로컬 자산을 우선 사용하고 폰트 CDN을 추가하지 않는다.
- light: background/card/popover `oklch(1 0 0)`, foreground `oklch(0.153 0.006 107.1)`, muted `oklch(0.966 0.005 106.5)`, muted-foreground `oklch(0.58 0.031 107.3)`, border `oklch(0.93 0.007 106.5)`.
- primary는 양 테마 모두 `oklch(0.841 0.238 128.85)`, primary-foreground는 `oklch(0.405 0.101 131.063)`다. 기존 olive/acid 색상을 유지한다.
- dark: background `oklch(0.24 0.006 106.6)`, sidebar `oklch(0.265 0.006 106.7)`, card `oklch(0.32 0.006 106.7)`, popover `oklch(0.34 0.006 106.7)`, muted `oklch(0.35 0.005 106.7)`, foreground `oklch(0.955 0.001 106.4)`, muted-foreground `oklch(0.76 0.012 107.1)`.
- 기본 radius 10px, 내부 별칭 6/8/10/14px, 간격 4/8/12/16/24/28/32px. 얇은 테두리·절제된 그림자·작고 둥근 컨트롤을 유지한다. 필드 36px, 일반 버튼 32px, 작은 툴바 버튼 28px가 기준이다.
- 문서 제목·섹션 제목·필드 레이블·보조 설명의 위계를 분명히 한다. 작은 영문 레이블이나 회색 경로가 주 행동보다 두드러지지 않게 한다. 긴 경로는 줄바꿈하되 파일 이름과 대응 경계를 찾기 쉬워야 한다.
- 한국어 기본·영어 전환, 라이트·다크, 데스크톱 1440×900·모바일 390×844를 고려한다. 좁은 화면은 세로 흐름으로 정렬하며 주 행동·취소를 가리지 않는다.

## 산출물과 검토

- Local Codex의 별도 디자인 프로젝트에 연결→확인→문서 A→문서 B를 조작할 수 있는 시안을 만든다. 예외 상태는 별도의 시안 검토 메뉴로 전환하되 제품 화면의 일반 메뉴로 오해되지 않게 분리한다.
- 시안과 함께 내부 컴포넌트 대응, 선택한 배치의 이유, 후속 구현에서 확인할 조건을 남긴다. 제품 화면에는 이 제작자 설명을 넣지 않는다.
- 대표 흐름·취소·모호한 대응·권한 복구·좁은 연결·연속 탐색을 실제로 눌러본 결과와 미확인 항목을 구분한다. 브라우저 방문 기록과 새로고침이 모의 동작이면 실제 동작으로 보고하지 않는다.
- 사용자 폴더 권한·IndexedDB·OS 동작의 실기기 검증은 이번 디자인 검토로 대체하지 않는다. 기존 페이즈 5 완료 이력은 그대로 보존한다.
- 공개 저장소에는 개인 경로·인증 정보·디자인 세션 식별자·임시 미리보기 주소를 넣지 않는다. 디자인 승인 전에는 AKD-14·15에 착수하지 않는다.

## 확인·결정이 필요한 사항

- 사용자가 시안의 연결 범위 표현과 문서 탐색 배치를 본 뒤 제품 적용 여부를 결정한다. 기존 확정 동작을 다시 질문하지 않으며 시안 검토 전 앱 구현은 진행하지 않는다.
