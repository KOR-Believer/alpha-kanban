# Alpha Kanban · 링크 연결과 문서 탐색 AKD-13

별도 디자인 프로젝트 안의 인터랙티브 시안입니다. 실제 제품 구현, 배포, 실제 파일 탐색 및 OS 권한 검증 결과가 아닙니다.

## 열기

`index.html`을 브라우저 또는 디자인 프로젝트 미리보기에서 엽니다. 빌드, 패키지 설치, 계정 로그인, 외부 서버 연결은 필요하지 않습니다. `styles.css`, `app.js`, `assets/fonts/`는 같은 폴더에 유지합니다.

화면 아래의 **시안 검토 도구**를 펼치면 예외 상태와 브라우저 탐색 도구가 나옵니다. 제품 영역 밖에 배치했습니다. 기본 화면은 Product Notes의 검색 개선 계획입니다.

### 기본 흐름

1. 본문의 **검색 화면 설계** 링크를 누릅니다.
2. 검색된 `product-local`을 명시적으로 선택합니다. 후보가 하나여도 자동 선택하지 않습니다.
3. **선택한 폴더 확인**에서 아래 관계를 확인합니다.
   - 내 폴더: `product-local`
   - 연결할 원래 폴더: `/old/product`
   - 실제 열 파일: `docs/design/spec.md`
4. **연결하고 열기**를 누릅니다. 이 시점에만 시안 전용 연결이 저장됩니다.
5. 읽기 전용 **검색 화면 설계** 페이지에서 **검색 API 계약**을 누릅니다. 절대 링크와 `../api.md` 상대 링크 모두 같은 문서로 이동합니다.
6. 브라우저 뒤로·앞으로·새로고침, 검토 도구의 직접 진입으로 탐색을 이어갑니다.
7. `search.ts 다운로드`는 가상의 TypeScript 파일을 내려받습니다. 문서 모달로 표시하지 않습니다.

### 주소와 상태

| 대상 | 시안 내 해시 주소 |
| --- | --- |
| 출발 문서 | `#/p/pn7/d/n12` |
| 검색 화면 설계 | `#/p/pn7/r/r84/d/x21` |
| 검색 API 계약 | `#/p/pn7/r/r84/d/x22` |
| 없는 문서 ID | `#/p/pn7/r/r84/d/u404` |

해시에는 PC 경로를 넣지 않습니다. ID는 공개용 가상 값입니다. `r84`는 시안 내 연결 문서 묶음의 논리 ID이며 실제 폴더 핸들 또는 Git ID가 아닙니다. 새 브라우저 환경에서 연결 없이 직접 진입하면 연결 필요 화면이 나옵니다. 같은 시안 저장소에 연결이 있으면 새로고침 후 재사용합니다.

- `akd13-design-state-v1`: 이 시안의 연결, 언어, 테마, 가상 초안, 권한·삭제 상태와 경로 사례(`family`). 기존 시안 연결을 읽을 때 `family`가 없으면 기본 Unix 사례로 처리합니다.
- `akd13-design-session-v1`: 창별 검토 상태와 문서별 스크롤 위치.
- 실제 Alpha Kanban의 저장 키, 파일 핸들, 원본 Markdown에는 접근하지 않습니다.
- 브라우저가 로컬 저장을 막으면 성공 처리하지 않습니다. 가상 초안 저장 실패는 제품 밖 검토 도구의 입력 바로 아래에 표시합니다. 현재 창의 이동·복귀에서는 입력을 유지하지만, 저장 실패 후 새로고침 복구는 보장하지 않습니다.
- 로컬 HTML의 저장소 지원·범위는 브라우저마다 다를 수 있습니다. 새 창 테스트는 동일한 시안 주소와 동일한 origin에서 해야 합니다.
- 다른 창의 연결 변경은 저장 revision 및 `storage` 이벤트로 감지합니다. 실제 제품에 필요한 원자적 다중 창 쓰기 잠금이나 OS 동시성 보장은 이 시안의 검증 대상에 포함되지 않습니다.

### 추가한 다중 root·탐색·경로 상태

기존 검토 도구의 상태 선택기를 사용합니다. 모든 root와 폴더, Git 식별 정보는 공개용 가상 데이터입니다. 실제 Git 명령, 디렉터리 검색, OS 선택기, 외부 API를 사용하지 않습니다.

| 상태 선택 | 확인 방법 | 예상 결과 |
| --- | --- | --- |
| 여러 root · 같은 이름 · clone/worktree | root를 전체로 두고 `product` 후보 세 개를 비교. `workspace-b`로 필터하거나 `harness/tools`로 검색 | 후보는 이름이 같아도 합쳐지지 않음. 선택 전 저장·자동 확정 없음 |
| 검색 가능한 root 없음 | 상태를 다시 열기 → 폴더 직접 선택 → 일반 `design` 폴더 선택 → 확인 | 등록 위치가 없는 별도 후보. ‘직접 선택한 폴더’·`design`·`spec.md`만으로 내 폴더를 식별. 원본 범위는 `/old/product/docs/design` |
| 검색 결과에 repo 없음 | 검색 상태가 끝난 뒤 이유 확인, 폴더 직접 선택 또는 다시 검색 | 빈 목록에서 직접 선택을 우선 안내. 검색 진행 중·필터 불일치와 구분하며 일반 폴더도 연결 가능 |
| 탐색 깊이 제한 | 발견한 `workspace-a/product`와 제한 안내 확인 | 깊은 위치까지 검색 완료했다고 표시하지 않음. 직접 선택 목록에서 하네스 하위 폴더 선택 가능 |
| 탐색 시간 제한 | 발견한 두 후보 확인 | 목록이 전체 결과가 아님을 안내. 발견한 후보·직접 선택·재검색 사용 가능 |
| Git 정보 확인 불가 | `workspace-b/harness/isolated/product` 선택 | Git 동일성을 주장하지 않음. 실제 가상 파일 경로가 있으면 연결 가능 |
| Windows 드라이브 · 한글 경로 | 출발 문서 링크 → 연결 → 문서 A → 절대·상대 링크로 B → 새로고침 | 드라이브 절대경로로 처리. Windows 사례와 연결이 시안 상태에 보존됨 |
| UNC 공유 · 공백 경로 | 같은 흐름으로 UNC 원본 주소를 펼쳐 확인 | 서버·공유 루트가 유지됨. 이 사례의 Git 확인 불가 표시는 UNC 일반의 제약이 아니라 해당 가상 폴더의 상태 |
| 긴 원본 경로 · 긴 파일명 | 390px에서 원본 전체 주소, 후보, 범위 선택, 최종 대상 확인 | 긴 경로·한글·공백을 줄바꿈하며 표시. 폴더·실제 파일·CTA를 별도 영역으로 유지 |

중단은 **검색 중단됨**, 제한은 **탐색 깊이 제한 / 탐색 시간 제한**으로 표시합니다. 중단·제한·부분 실패를 검색 완료나 유일 후보의 근거로 사용하지 않습니다. 재검색은 같은 가상 제한을 다시 재현하며, 직접 선택으로 계속 진행할 수 있습니다. 이미 확인된 연결로 열리는 정상 링크는 검색을 다시 시작하지 않고 문서 페이지로 이동합니다.

### 후보를 구분하는 정보

| 표시 이름 | 등록 root | root 내부 상대 위치 | Git 저장소 식별 | 작업 폴더 유형 | 확인할 내부 파일 |
| --- | --- | --- | --- | --- | --- |
| product | workspace-a | product | product | clone | docs/design/spec.md |
| product | workspace-b | harness/tools/product | product | clone | docs/design/spec.md |
| product | workspace-b | worktrees/product | product | worktree | docs/design/spec.md |
| product | workspace-b | harness/isolated/product | 확인 불가 | 분류하지 않음 | docs/design/spec.md |

동일한 Git 저장소 식별값을 가진 작업 폴더도 각각 다른 폴더 ID를 사용합니다. 같은 이름이나 Git 식별값으로 자동 선택하거나 연결을 합치지 않습니다. 후보 검색은 이름·등록 root·root 내부 위치·확인된 가상 저장소 이름을 대상으로 하며, 필터 때문에 선택 항목이 목록에서 사라지면 선택을 해제합니다.

등록 root와 상대 위치를 알고 있는 후보는 최종 확인, 열린 문서, 연결 관리에도 그 위치를 동일하게 표시합니다. 기존 `product-local`과 `product-archive`, 다중 root의 clone/worktree 후보는 이 규칙을 유지합니다. 이는 시안이 이미 알고 있는 가상 위치 메타데이터이며, 브라우저가 내 PC 절대경로를 알아냈다는 뜻이 아닙니다. root 등록 정책이나 새 workspace 등록 마법사는 추가하지 않았습니다.

**등록 위치를 모르는 직접 선택은 별도입니다.** `검색 가능한 root 없음`의 직접 선택 목록은 `design`, `docs`, `product-local`, `product-assets`의 별도 가상 후보를 사용합니다. 이 후보에는 등록 root나 상위 상대 위치를 넣지 않습니다. 후보·최종 확인·연결 문서·연결 관리에서는 ‘직접 선택한 폴더’, 선택한 폴더 이름, 그 폴더 안에서 확인한 파일 경로로 식별합니다. 연결 관리의 ‘확인된 내부 파일’도 원본 범위와 선택 폴더의 가상 파일 목록이 일치하는 경우에만 표시합니다.

예를 들어 `design`을 연결하면 내 폴더의 확인된 파일은 `spec.md`입니다. `/old/product/docs/design`은 원본 문서 링크에서 확인한 **옛 경로의 연결 범위**이지, 선택한 내 폴더의 실제 상위 경로가 아닙니다. 이름이 `design` 또는 `product-local`이라고 해서 `workspaces` 소속이거나 서로 상하위 폴더라고 추정하지 않습니다. 별도 폴더 ID를 저장하므로 상태 직렬화·복원 후에도 위치 미상 표시를 유지합니다. 기존 등록 위치 후보와 저장된 연결은 일괄 변경하지 않으므로, 이 수정 사례는 검토 도구에서 `검색 가능한 root 없음` 상태를 다시 열어 확인합니다.

### 겹친 연결의 결정과 실제 열 대상

`기존 좁은 연결 유지` 상태는 `/old/product/docs/design` ↔ `design`이 저장된 상태에서 시작합니다. `design`의 위치는 `workspaces / product-local/docs/design`입니다.

| 최종 확인의 항목 | 기존 하위 연결 유지 | 하위 연결을 명시적으로 변경 |
| --- | --- | --- |
| 저장할 상위 연결 | `/old/product` ↔ `product-local` | 동일 |
| 새로 선택한 폴더에서 확인한 파일 | `product-local`의 `docs/design/spec.md` | 동일 |
| 이번에 실제 사용할 원래 범위 | `/old/product/docs/design` | 동일 |
| 이번에 실제 사용할 폴더 | `design` — `workspaces / product-local/docs/design` | `design` — `workspace-b / worktrees/product/docs/design` |
| 실제 열 내부 파일 | `spec.md` | `spec.md` |
| 후속 API 문서의 연결 | 더 넓은 `/old/product` 연결의 `docs/api.md` | 동일 |

확인 방법:

1. 상태를 열고 **저장할 연결**과 **이번에 실제로 열 대상**을 비교합니다. 새 폴더의 파일 존재 확인을 실제 열 대상이라고 표시하지 않습니다.
2. 기존 연결을 유지하려면 범위·대상 확인 체크 후 **연결하고 열기**를 누릅니다. 열린 문서의 root·상대 위치·파일이 최종 확인과 같아야 합니다.
3. 바꾸려면 **이 하위 연결 변경**을 누르고 `workspace-b / worktrees/product/docs/design`의 `design`을 선택합니다. 기존 범위를 유지한 채 파일 `spec.md`를 확인합니다.
4. **변경 내용 적용**은 이전 확인 화면에 임시 변경만 반영합니다. 여기서 **취소**하면 상위 연결과 하위 연결 변경을 모두 저장하지 않습니다. 하위 선택 단계에서 **변경 취소 / Escape**를 누르면 이전 확인 화면으로 돌아갑니다.
5. 최종 **연결하고 열기**에서만 상위 연결과 명시한 하위 변경을 시안 저장소에 함께 기록합니다. 다른 하위 연결은 보존합니다.
6. **로컬 폴더 → 변경**에서도 같은 폴더 선택·확인 과정을 사용합니다. 현재 요청 문서가 해당 범위 안에 있으면 그 문서를 대상으로 확인하며, 범위 밖이면 해당 연결에 속한 가상 문서를 확인 대상으로 표시합니다.

확인 화면, 저장 직전, 열린 문서는 같은 `resolveTarget` 판정을 사용합니다. 경로 구성요소 경계가 맞는 연결 중 가장 깊은 범위를 선택합니다. `/old/product`는 `/old/product-other`를 포함하지 않습니다. 실제 사용할 더 좁은 연결의 파일이 없으면 넓은 연결의 동명 파일로 조용히 대체하지 않으며, 연결 변경을 요구합니다. 겹침 없는 기본 확인 화면은 한 개의 간결한 대응 표를 유지합니다.

### Windows·UNC·긴 경로의 가상 모델

| 사례 | 원래 repo 범위 | 문서 ID |
| --- | --- | --- |
| 기존 Unix | `/old/product` | `x21` → `x22` |
| Windows 드라이브 | `C:UserswriterDocumentsProduct Notesproduct` | `w21` → `w22` |
| UNC 공유 | `\fileserver	eam docsProduct Notesproduct` | `u21` → `u22` |
| 긴 Unix 경로 | `/old/shared teams/공개 문서/Product Notes/archives/search-experience/product` | `l21` → `l22` |

Windows·UNC의 설계 파일은 `docs/검색 설계/검색 화면 설계와 키보드 탐색 동작 명세.md`, API 파일은 `docs/검색 API 계약.md`입니다. 두 문서 사이 상대 링크는 `../검색 API 계약.md`입니다. 긴 Unix 사례에는 더 긴 한글 설계·API 파일명을 사용합니다. 각 파일은 고정된 가상 파일 목록에 존재하며 파일명만 비교해 대체하지 않습니다.

- 드라이브·UNC·Unix 절대경로를 먼저 구분합니다. `C:...`와 `\servershare...`를 Unix 상대경로에 덧붙이지 않습니다.
- 상대 링크는 현재 문서 디렉터리를 기준으로 처리합니다. `..`로 드라이브·공유·Unix 루트 위로 넘어가는 경로와 `C:relative.md` 형태의 드라이브 상대경로는 거부합니다.
- Windows·UNC의 **범위 비교**는 이 가상 모델에서 대소문자를 무시하고, Unix는 구분합니다. 파일 존재는 고정된 가상 내부 경로 목록으로 확인합니다. 실제 볼륨·공유의 대소문자 정책, symlink, 실제 gitdir을 검증한 결과가 아닙니다.
- 원본 표시 주소는 드라이브/UNC 접두어와 구분자를 유지합니다. 내부 파일 경로는 읽기 쉬운 `/` 구분자로 표시합니다.
- 범위 선택은 원래 repo부터 문서 부모 폴더까지 실제 구성요소에서 만듭니다. 후보가 하나여도 폴더는 직접 선택하며, 최종 저장 전에는 연결하지 않습니다.
- 원본 전체 주소는 펼쳐서 확인할 수 있습니다. 페이지 해시에는 `w21`·`u21`·`l21` 등의 불투명 ID만 포함됩니다. 예: `#/p/pn7/r/r84/d/w21`.
- 경로 사례는 `family`로 저장하며 각 문서 ID의 원본 주소는 고정입니다. 저장 후 검토 모드를 바꾸지 않고 새로고침하면 같은 요청·연결을 다시 사용합니다. **상태 열기**는 비교용 가상 초기 상태를 다시 구성하므로 기존 시안 연결을 초기화합니다. 가상 초안은 보존합니다.

실패 재현 상태는 검토 도구에서 시작합니다. `연결 저장 실패`는 첫 저장 시도에 실패한 뒤 재시도할 수 있게 설계했습니다. 검색 진행 시간은 일반 상태 약 1.4초, 검색 중 검토 상태 약 12초입니다. 실제 디스크를 검색하는 시간은 아닙니다.

### 제품 밖의 가상 초안 검토

출발 문서의 **내 메모 / My notes**는 제거했습니다. 가상 초안 입력은 `#product` 밖의 **시안 검토 도구** 안에만 있습니다. 실제 앱에 메모 기능이나 읽기 전용 문서 편집 기능을 추가하는 제안이 아닙니다.

1. 시안 검토 도구를 펼쳐 **가상 초안 입력**에 내용을 적습니다. **작성 중 초안 유지** 상태를 선택하면 입력란으로 초점이 이동합니다. 이미 입력한 내용은 덮어쓰지 않고, 비어 있을 때만 가상 예문을 채웁니다.
2. **연결 저장 실패** 상태를 열고 **연결하고 열기**를 누릅니다. 첫 연결 저장은 실패하며, 취소 후 검토 도구에서 초안이 남아 있는지 확인할 수 있습니다. 이는 연결 저장 실패 재현으로, 초안 저장 실패와는 별개입니다.
3. 출발 문서에서 연결 문서로 이동했다가 돌아오거나 브라우저 뒤로·앞으로를 사용한 뒤, 같은 도구에서 입력을 확인합니다. 실제 브라우저 저장 실패가 없다면 새로고침에도 시안 전용 저장소의 초안을 불러옵니다.
4. 가상 초안 입력은 어느 문서 페이지에서도 같은 검토 도구 안에만 표시됩니다. 언어·테마 전환과 기존 연결 판단 방식은 바꾸지 않았습니다.

### 권한 재승인 표현 범위

권한 만료 화면의 **접근 허용** 뒤에 열리는 시안 대화상자는 실제 OS 권한 요청과 응답을 가상으로 보여주기 위한 대역입니다. 실제 OS 창을 호출하거나 권한을 변경하지 않습니다. **제품에 OS 권한 요청 전후의 별도 추가 확인창을 도입하는 계획이 아닙니다.** 실제 제품 구현에서는 기존 권한 재요청 경로와 OS 동작을 별도로 검토해야 합니다.

### 취소와 해제

- 대화상자 닫기·취소·Escape: 연결 변경과 문서 이동 없이 원래 링크 또는 호출 버튼으로 초점 복귀.
- 연결 관리의 해제: 별도 확인 후 해당 연결만 삭제. 실제 파일은 삭제하지 않음.
- 검토 도구 초기화: 확인 후 시안의 연결·가상 초안만 삭제. 선택한 언어·테마는 유지.
- 메뉴나 대화상자는 한 번에 하나만 열림. 문서 탐색은 대화상자로 쌓지 않음.

## 시각 규칙과 반응형

- 사용자가 지정한 Light/Dark OKLCH 토큰 및 olive/acid green primary를 그대로 사용합니다.
- 폰트: Raleway Variable → Pretendard Variable → system sans. 설치된 로컬 패키지의 실제 WOFF2를 `assets/fonts/`에 복사했습니다. CDN은 사용하지 않습니다.
- Raleway는 Latin subset, Pretendard는 전체 variable WOFF2입니다. 기존 제품의 Pretendard 동적 subset 로딩과는 배포 방식이 다릅니다. 폰트 파일을 읽지 못할 때만 system fallback이 적용됩니다.
- 두 폰트의 OFL 라이선스를 함께 보관했습니다.
- 문서 링크 색은 Light의 primary-foreground, Dark의 primary를 사용해 문서 본문에서 구분합니다. 지정된 muted-foreground 토큰은 그대로 보존했습니다. 대비 수치 실측은 수행하지 않았습니다.
- 디자인 기준은 사용자 제공 규격 및 현재 UI 소스입니다. 새로운 디자인 시스템이나 대시보드를 추가하지 않았습니다.
- 1440px: 280px 사이드바, 읽기 본문, 작은 문서 목차.
- 1024px 부근: 보조 툴바 텍스트 축약, 본문 여백 조정.
- 768px 미만: 문서 목록 펼치기, 헤더 도구 메뉴, 본문 1열, 44px 터치 영역, 내용에 맞춰 줄바꿈하는 연결 관계. `.location-bar`의 breadcrumb는 전체 폭의 별도 첫 행에 표시하며 필요하면 자연스럽게 줄바꿈합니다. Documents와 Connections 동작은 다음 행에 배치합니다. 데스크톱 배치는 유지합니다.
- 390×844를 포함하는 모바일 규칙: 대화상자 최대 높이는 viewport 내부, 본문만 스크롤, 푸터 CTA는 별도 행, safe-area 하단 여백.
- URL과 원본 경로는 구분합니다. 긴 원본 경로는 펼치면 모두 읽을 수 있으며 줄바꿈합니다.
- 모션은 대화상자 진입 180ms, 검색 상태 표현에 한정했습니다. `prefers-reduced-motion`에서는 제거합니다.

### 이번 위치 정보 수정과 검사 기록

- `app.js`: root 없는 직접 선택에 위치 미상 후보를 사용하고, 위치 표시를 후보·확인·연결 문서·관리에서 일치시켰습니다. root 없음·repo 없음의 빈 목록은 필터 변경 대신 직접 선택을 우선 안내합니다. 실제 후보가 있고 필터만 맞지 않는 경우의 기존 안내는 유지합니다.
- `index.html`: 변경된 `app.js`를 읽도록 스크립트 버전만 갱신했습니다. `styles.css`, 툴바, 폰트·토큰, 14px Markdown, 모바일 위치 배치는 수정하지 않았습니다.
- `node --check app.js`: 구문 검사 통과.
- Node VM의 가상 저장소·최소 DOM 대역으로 **16개 집중 논리 검사 통과**. 한영 각각 root 없는 빈 목록 안내, 직접 후보의 상위 위치 부재, 확인 범위·파일, 저장 후 문서·관리 표시, 저장 상태 직렬화·복원, repo 없는 안내를 확인했습니다. 추가로 알려진 다중 root·worktree 위치 및 필터, 직접 선택 취소 시 미저장·미이동, 동명 파일 자동 대체 방지, 기존 겹친 연결의 좁은 범위 우선을 확인했습니다.
- 이번 턴에서는 브라우저 실행·캡처·OS 동작을 수행하지 않았습니다. 논리 검사는 화면 렌더링, 실제 새로고침, 키보드·초점 동작의 재검증이 아닙니다.
