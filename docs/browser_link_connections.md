# 브라우저 로컬 링크 연결

## 사용 방법

1. Markdown 보기에서 열리지 않는 로컬 파일 링크를 누른다. 이미 열 수 있는 상대 링크와 HTTP(S)·메일 링크는 기존대로 열린다.
2. **이 컴퓨터의 폴더**에서 발견된 repo를 선택하거나 **폴더 직접 선택**으로 디렉터리를 지정한다. repo가 여러 곳에 있으면 연결된 루트와 그 아래 위치, 확인된 Git 정보를 비교한다. 같은 이름이나 remote여도 서로 다른 checkout은 따로 선택한다.
3. 선택한 폴더에 실제로 존재하는 내부 경로를 확인해 **연결할 원래 폴더**를 제안한다. 예를 들어 `/old/product/docs/guide.md`와 내 repo를 연결하면 `/old/product` → 내 repo, 열 파일 `docs/guide.md`가 된다. `docs`만 선택하면 `/old/product/docs` → 선택한 폴더, 열 파일 `guide.md`다. 가능한 경로가 여러 개면 사용자가 선택한다.
4. **선택한 폴더 확인**에서 저장할 연결·열 파일·재사용할 프로젝트를 확인한다. 더 구체적인 기존 연결이 적용되면 **이번에 실제로 열 대상**을 별도로 표시한다. 그 연결을 유지하거나 **기존 연결 변경하기**로 변경 대상을 다시 고른다. 확인을 취소하면 저장하지 않는다.
5. **연결하고 열기**를 누른다. 실제 파일과 연결 상태를 다시 확인한 뒤 저장한다. 같은 출발 프로젝트에서 이어 읽는 문서의 절대 링크에도 연결을 재사용하고, 상대 링크는 현재 읽는 문서 위치를 기준으로 해석한다. 별개 프로젝트에는 자동으로 공유하지 않는다.

연결된 Markdown은 일반 문서와 **같은 문서 뷰어와 렌더러**를 쓰는 읽기 전용 페이지에서 열린다. 본문·목차·제목 이동·표·코드의 표시를 공유하며 연결 위치와 **출발 문서로 돌아가기**가 추가된다. 원래 프로젝트의 문서 목록과 선택은 유지한다. 뒤로·앞으로가기, 같은 브라우저의 직접 주소·새로고침으로 문서를 다시 열 수 있다. 주소에는 PC 경로 대신 브라우저가 발급한 문서 식별자를 사용한다. 다른 파일은 다운로드한다. 프로젝트 등록·소유자·티켓 상태는 바뀌지 않는다.

**로컬 폴더 → 링크 연결**에서 연결을 바꾸거나 해제할 수 있다. 권한이 끊긴 링크는 **접근 허용 후 다시 열기**로 재승인하거나 폴더를 다시 선택한다. 직접 주소에서 연결 해제·변경·파일 부재·교체가 확인되면 요청한 문서의 주소를 유지하고 재연결을 안내한다. 파일이 없으면 같은 이름의 다른 파일을 대신 열지 않는다. 원래 페이지의 작성 중인 티켓 초안은 연결 문서 탐색 중 유지하며, 출발 문서로 돌아오면 다시 표시된다. 그 초안을 둔 채 다른 문서나 프로젝트로 떠날 때는 버릴지 확인한다.

원본 Markdown과 `.ak.config`·`.ak.user`·agent 규칙·Git 설정은 수정하지 않는다. 연결 정보는 현재 사이트의 IndexedDB에만 저장하며 별도 설정 파일을 만들지 않는다. 다른 브라우저·프로필·PC를 사용하거나 사이트 데이터를 지우면 다시 연결해야 한다.

## 판정과 지원 범위

- Mac/Linux 절대경로, Windows 드라이브·UNC 경로, 로컬 `file:` URL, 문서 위치를 반영한 상대경로를 정규화한다. 접두사는 경로 구성요소 경계로 비교하고 더 구체적인 연결을 먼저 사용한다. 남은 경로에 `..`가 있거나 연결 폴더를 벗어나면 열지 않는다.
- 정상 상대 링크 → 저장된 연결 → 접근 가능한 원본 repo의 정확한 상대 위치/Git 정보 → 최초 선택 또는 수동 연결 순서다. 옛 절대주소만으로 원본 repo를 알 수는 없다. 후보가 하나이거나 clone 이름이 같다는 이유로 자동 연결하지 않는다.
- 자동 발견은 허용된 폴더 안에서만 진행하며 현재 문서의 연결 폴더부터 탐색한다. 하네스 자체가 repo여도 중첩 repo를 계속 찾는다. 파일에는 가장 가까운 repo 경계를 적용한다. 알 수 없는 중첩 repo를 부모 repo로 대신 식별하지 않는다.
- `.git` 디렉터리와 상대 `gitdir`·`commondir`를 읽는다. 허용된 다른 상위 연결로 검증 가능한 경우도 포함한다. 브라우저 핸들에서 PC 절대경로를 추정하지 않으므로 절대 `gitdir`, 범위 밖 메타데이터, 미지원 Git 구성은 수동 연결로 넘긴다. Git 명령·네트워크·전역 Git/SSH 설정을 사용하지 않는다.
- remote는 자격 증명을 제외한 호스트/포트/repo 경로와 remote 이름으로 식별한다. 일반 SSH/HTTPS 표기를 맞추되 경로의 대소문자와 fork·remote 역할은 보존한다. SSH 별칭, `include`/`includeIf`, `insteadOf`, 불명확한 중복 URL은 자동 식별하지 않는다. remote 설정 원문을 저장하지 않는다.
- 선택한 checkout 핸들을 보존하고 열 때 권한·파일·확인된 Git 정보를 다시 검사한다. 접근 실패나 repo 변경을 다른 checkout으로 자동 대체하지 않는다. 같은 경로의 연결을 다른 창에서 바꾸면 이전 화면의 저장·해제를 거부한다.
- repo 탐색은 최대 깊이 20, 디렉터리 3,000개, 항목 50,000개, 경과 시간 8초를 기준으로 다음 탐색 단계를 중단한다. 진행 중인 브라우저 파일 읽기 자체를 강제 종료하지는 못한다. `.git` 내부 순회, 숨김 디렉터리, `node_modules`, `vendor`, `dist`, `dist-browser`, `build`, `coverage`, `target`을 제외한다. 결과는 연결 목록과 권한이 같을 때 60초 동안 재사용한다. 중지·제한·권한 오류로 불완전한 탐색은 자동 연결의 근거로 쓰지 않으며 수동 선택은 계속 제공한다.
- 미싱 이미지 자동 연결, repo 내부 파일 구조 변경 추측, 경로의 원문 치환, 문서 편집은 포함하지 않는다. 연결한 Markdown의 이미지도 해당 폴더 안의 기존 이미지 규칙과 외부 이미지 동의 절차를 따른다.

## 구현과 검증

`linkPaths.ts`가 경로와 핸들 경계를, `gitDiscovery.ts`가 제한된 Git 읽기/탐색을, `linkMappings.ts`가 저장·재사용을 담당한다. 연결 UI는 `LocalLinkDialog.tsx`, 링크 처리는 `MarkdownResources.tsx`, 주소·복구는 `LinkedDocumentPage.tsx`와 `linkedNavigation.tsx`에 있다. 일반·연결 문서의 읽기 화면은 `components/MarkdownDocumentReader.tsx`를 공유한다. 기존 프로젝트 등록·소유자 판정에는 연결을 추가하지 않는다. 연결 문서는 별도 `ld_` 식별자를 가지며 대상 연결 안에서만 식별된다.

기존 IndexedDB의 `link-mapping:v1:map:*`와 `link-mapping:v1:document:*` 키를 보존하고 직접 주소 조회용 `link-mapping:v1:page:*` 인덱스를 추가한다. 기존 연결의 문서를 다시 열면 기존 `ld_` ID를 유지해 페이지 인덱스를 기록한다. DB 이름·스키마 버전·기존 기록을 변경하지 않는다. IDB 저장 실패를 성공으로 표시하지 않고 기존 연결을 보존한다.
