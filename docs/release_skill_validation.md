# 릴리즈 안내·스킬 업데이트 검증

검증일: 2026-10-26 (초기), 2026-10-27 (등록 권한 개선), 2026-10-28 (오프라인 다운로드), 2026-10-30 (배포 전 회귀·실기)

대상: [AKU-01~07](23_alpha_kanban_release_skill_tickets.md). 아래 개발·실기 검증은 공개 전 기능 브랜치에서 수행했다. 기존 PWA 창 색상 변경을 보존했으며 개인 전역 스킬은 변경하지 않았다. 2026-10-30 공개 승인과 남은 사용자 검증은 별도 항목으로 구분한다.

## 구현 범위

- 한영 릴리즈 원본에서 논리 릴리즈 ID·순서·날짜·노출 정책과 현재/과거 기록을 생성한다. 기존 `buildId`, `notes`, protocol 1 계약을 유지한다. 새 의미 버전이나 문서 형식 번호는 발행하지 않았다.
- 실제 대기 워커의 기록을 보여주고 적용 직전 대상을 다시 확인한다. 원격 최신 배포가 달라도 읽은 대상과 적용할 대상이 섞이지 않는다. 적용은 기존 PWA 보호 절차를 사용한다.
- 준비 완료 알림, 적용 전 읽기, 실제 프로젝트 선택 화면에서의 1회 모달과 수동 재열람을 연결했다. 최초 방문은 기준점만 기록하며 문서 화면으로 복귀한 사용자를 강제로 이동시키지 않는다.
- 최초 설치는 agent가 담당한다. 성공 시 실제 설치 디렉터리와 경로 없는 공개 등록 링크를 안내하도록 요청문·README·로컬 설치 도구를 맞췄다. 기존 대상이 있으면 로컬 설치 도구는 삭제하지 않고 중단한다.
- 웹은 사용자가 선택한 기존 스킬 폴더만 등록한다. 빌드에 고정된 전체 파일·payload 해시와 알려진 공식 커밋을 비교하며, 개인 수정·추가 파일·출처 불명·호환성 불명에서는 직접 교체하지 않는다.
- 적용 전 전체 백업과 pending 저널을 strict durability IDB에 저장한다. 전용 Web Lock, 원본 재확인, close/readback 검증, 명시적 복원·백업 내보내기와 PWA 초안/쓰기 보호를 연결했다. 연결 해제는 백업을 삭제하지 않는다.

### 릴리즈·PWA

- A 실행/B 준비/C 원격 최신, 워커 교체, 잘못된 워커 메타데이터, 중복 적용 확인을 검사했다.
- 최초 방문·여러 버전 건너뛰기·동일 ID·롤백·읽음 저장 실패, 문서/전체 보드/소개 화면의 자동 모달 금지, 실제 선택 화면 준비·초안·다른 모달 대기를 검사했다.
- 알림 닫기와 읽음은 분리된다. 숨은 화면이나 경로 이동으로 닫힌 자동 모달을 읽음으로 처리하지 않으며, 사전 열람한 릴리즈는 적용 후 재노출하지 않는다.
- 릴리즈 내역에서 스킬 관리로 이동했다 돌아올 때 하나의 모달과 선택한 기록·언어를 유지하는 컴포넌트 검사를 추가했다.
- Chrome에서 적용 전 노트, 현재 경로 복원, 선택 화면 1회 표시·재열람, 오프라인 재실행·기록 읽기를 확인했다.
- 다른 창의 초안·진행 중 파일 저장·응답하지 않는 창은 적용을 막는다. 설치 창도 업데이트 조율에 참여한다.
- 손상 자산 거부, 앱 자산 복구, 고장 난 워커의 같은 URL 교체, 복구 배포에서 정상 앱 복귀, 오프라인 퇴역과 최종 퇴역을 검사했다.
- 연결·문서 ID·설정·미해결 문서 복구본·스킬 연결/백업·릴리즈 읽음이 유지됐으며 로컬 Markdown 업로드/API 요청은 없었다.

### 스킬 파일 보호

- 빈 폴더·부모 폴더·다른 스킬·임의 폴더명, 공식본·개인 수정·추가 파일·누락 파일·mtime 변경을 가짜 핸들로 검사했다.
- payload와 파일 해시, 전체 목록, 경로 이탈·절대 경로·대소문자 충돌·파일/디렉터리 충돌·용량 제한을 검사했다. 패키징도 같은 검증기를 사용하고 비정규 파일을 거부한다.
- 백업 실패·용량 부족·권한 거부는 쓰기를 시작하지 않는다. 부분 close 실패·readback 불일치는 pending 상태를 남기고 재시도 대신 복원을 요구한다.
- 새로 생성한 빈 파일까지 복구 기록에 남기며, 외부 편집 내용은 업데이트/복원에서 덮어쓰지 않는다. 여러 적용 요청은 직렬화된다.
- OPFS에서 공식 이전본 등록 → 비교 → 확인 → 백업/업데이트 → 백업 내보내기 → 명시적 복원과 전체 내용 일치를 확인했다. 이것은 실제 OS 디렉터리 검증이 아니다.

## 2026-10-27 등록 권한 개선 검증

- 워크스페이스·프로젝트·기존 스킬 폴더 선택에서 처음부터 `readwrite`를 요청한다. 기존 연결 재허용은 저장된 핸들을 사용하고, 관리 메뉴는 권한이 이미 있으면 편집 허용 버튼을 숨긴다. 등록 권한과 실제 파일 변경 확인은 별개다.
- `pnpm test` 372개(shared 45, web 327), `pnpm typecheck`, `pnpm build`, `git diff --check`를 통과했다. 빌드의 기존 500 kB 청크 경고는 남아 있다. 권한 흐름 컴포넌트 검사 12개를 추가했으며 이번에는 전체 PWA 배포 교체 스모크를 다시 실행하지 않았다.
- 자동 검사에서 세 종류의 등록 요청, 등록 취소·거부 시 기존 연결/설정/백업 유지, 이전 읽기 전용 연결 재허용, 권한 허용 후 버튼 숨김, 등록 후 권한 철회 시 쓰기 차단을 확인했다. 권한이 이미 있어도 업데이트 확인·전체 백업·검증·명시적 복원을 거친다.
- 실제 macOS Chrome에서는 개인 연결과 분리된 로컬 개발 출처 및 테스트 전용 OS 폴더를 사용했다. 워크스페이스 등록의 수정 권한 거부/허용, 프로젝트 직접 열기, 두 연결의 편집 허용 표시와 추가 버튼 숨김을 확인했다. 기존 사용자 출처의 연결·설정을 바꾸지 않았다.
- 알려진 이전 공식본을 복사한 스킬 폴더로 네이티브 선택·수정 권한 허용·비교·확인·백업/업데이트·명시적 복원을 수행했다. 등록 직후 8개 파일이 원본과 같았고, 적용 후 동봉 스킬 전체와 일치했으며, 복원 후 8개 파일이 원본과 다시 일치했다. 같은 테스트 워크스페이스의 티켓 문서도 변경되지 않았다. 개인 전역 스킬은 사용하지 않았다.
- 새로고침 후 스킬 연결과 복원된 백업 기록, 한영 전환·다크 테마 설정이 유지됐다. 이는 개발 화면의 네이티브 파일 접근 검증이며 설치형 PWA·브라우저 완전 재시작·숨김 경로·OS 링크/속성·실제 Codex 인식까지 검증한 결과는 아니다.

## 2026-10-28 앱 버전별 ZIP 다운로드 검증

- 공통 설치 안내의 다운로드 주소를 실행 중인 앱의 `skillBundle`에 고정했다. 최신 manifest나 버전 없는 ZIP으로 대체하지 않으며 시작 화면·소개 화면의 한영 전환 후에도 같은 주소를 사용한다.
- 격리 Chrome에서 일반 다운로드 링크가 오프라인에서 취소되는 현상을 확인했다. 고정된 ZIP을 `fetch`로 읽은 뒤 Blob으로 내려받도록 보완했으며 닫기 시 요청 취소, Blob URL 해제, 중복 클릭 방지와 실패 시 재시도를 검사했다. HTTP 오류나 HTML fallback을 ZIP으로 저장하지 않는다.
- `pnpm test:pwa` 24개 시나리오 통과. 새 워커가 대기 중인 이전 앱, 업데이트 후 오프라인 Chrome 재시작, 설치형 standalone 창에서 실제 다운로드 버튼으로 파일을 저장했다. 네트워크와 테스트 서버 응답을 차단한 상태에서 워커 응답, 버전별 파일명, ZIP 전체 SHA-256, 스킬 8개 파일의 해시 및 설치 안내를 대조했다. 테스트 설치는 CDP이며 네이티브 설치 대화상자 검증으로 간주하지 않는다.
- 관련 UI·다운로드·번역 검사 21개, 공유 패키지 45개 및 전체 웹 334개 검사를 통과했다. 전체 웹 검사는 `--maxWorkers=2`로 실행했다. 기본 병렬 실행에서는 기존 navigation/SkillUpdates의 비동기 화면 대기 단언 2개가 실패했으며, 해당 테스트의 대기 안정성은 별도 점검 대상이다.
- `pnpm typecheck`, `pnpm build`, `git diff --check` 통과. 기존 500 kB 앱 청크 경고는 남아 있다. 기존 연결·설정·복구 기록 보존도 PWA 회귀 검사에 포함했다. 개인 스킬·사용자 연결은 변경하지 않았고 커밋·푸시·공개 배포는 하지 않았다.

## 2026-10-30 배포 전 회귀·실기 검증

### 자동 검사와 릴리즈 화면

- 비동기 검사 두 곳을 보완했다. 뒤로/앞으로 이동 검사는 상세 화면이 다시 나타날 때까지, 스킬 복원 검사는 적용 후 비교가 끝나 버튼이 활성화될 때까지 기다린다. 검사 중 복원 버튼이 비활성 상태임도 별도로 확인했다.
- 기본 병렬 설정의 `pnpm test`에서 shared 45개, web 341개, 총 386개가 통과했다. `--maxWorkers=2`로 우회하지 않았다. UTF-8 BOM이 있는 참조 파일을 공식 원본으로 오인하지 않는 검사와 짧은 한글 파일로 교체 후 truncate/복원 검사도 포함한다.
- 두 프로젝트 선택 창에서 자동 모달이 동시에 열리는 문제를 재현했다. Vite의 객체형 빌드 상수가 기본 인자에서 매 렌더마다 새 객체가 되어 Web Lock을 해제하던 원인을 수정했다. 빌드 상수를 모듈에서 고정하고, 다른 창에 반복 확인 기회를 준 상태에서도 모달 하나만 열리고 읽음이 공유되는지 검사했다.
- `pnpm test:pwa` 27개 시나리오를 통과했다. 실제 길이의 릴리즈 원문과 스킬 안내를 넣고 한영·라이트/다크·1360/390px의 8개 조합을 검사했다. 단일 본문 스크롤, 화면 밖 넘침 없음, Escape와 호출 버튼 초점 복귀, 내역→스킬 관리→같은 내역 복귀를 확인했다. 투어·투어 제안·선택 메뉴·입력 중 자동 모달 대기는 컴포넌트 검사로 구분했다.
- 기존 업데이트/초안/쓰기/다중 창 보호, 오프라인 재시작·버전 고정 ZIP 다운로드, 복구·퇴역의 연결/설정/백업/읽음 보존도 통과했다. 이 검사는 격리 Chrome·로컬 배포·OPFS이며 공개 호스팅 검증이 아니다.
- 사용자 승인 아래 실제 워크스페이스도 읽기 전용으로 열어 프로젝트 목록·티켓 상세·문서 검색·플랜·안내 복귀·새로고침 보존을 확인했다. 문서 내용 해시가 같았고 콘솔 오류가 없었다. 저장 검사는 그 워크스페이스가 아닌 테스트 복사본에서만 수행했다.
- 한영 릴리즈 원문을 이번 변경 내용으로 정리했다. 공개 전 같은 논리 ID를 유지하며 스킬과 문서의 의미 버전은 새로 만들지 않았다. 현재 허용한 이전 공식본과 동봉본의 차이는 구현 전 질문 확인 규칙이며 기존 문서 형식은 유지된다.

### 네이티브 폴더와 파일 보존

- macOS 15.7.4, 격리 Chrome 프로필, 별도 로컬 출처의 설치형 standalone 창에서 확인했다. 설치/실행은 CDP를 사용했으며 네이티브 설치 대화상자 검증으로 간주하지 않는다. 폴더 선택과 읽기·쓰기 허용/거부는 실제 OS 선택창과 Chrome 권한 UI를 사용했다.
- 테스트 전용 숨김 `.codex/skills/implementation-ledger` 경로의 선택 취소, 등록, 권한 철회·거부·재허용, Chrome 프로세스 완전 종료/재시작을 확인했다. 등록만으로 파일이 바뀌지 않았고 연결 ID·두 백업 ID가 재시작/재허용 후에도 같았다. 연결 해제 후 연결만 사라지고 두 백업은 유지됐다.
- 공식 이전본 8개 파일의 백업/업데이트/복원 후 전체 내용이 각각 동봉본/원본과 일치했다. 빈 폴더와 외부 파일을 가리키는 `SKILL.md` 심볼릭링크 폴더는 등록을 거부했고 기존 연결·백업과 링크 바깥 파일은 유지됐다. 개인 전역 스킬은 사용하지 않았다.
- 기본 `createWritable()`이 macOS 사용자 확장 속성을 잃는 문제를 실제 파일에서 발견했다. 기존 데이터를 swap 파일로 복사하고 UTF-8 바이트 길이로 truncate한 뒤 닫도록 수정했다. 이후 업데이트와 복원 모두 기존 모드 `0750`과 테스트 사용자 확장 속성을 유지했다. Chrome이 `com.apple.quarantine`을 추가/변경하는 것은 확인됐으므로 모든 OS 메타데이터의 동일 보존으로 표현하지 않는다.
- 현재 허용한 공식 스냅샷에서의 기존 파일 변경을 검증한 결과다. 삭제 후 재생성하는 파일의 메타데이터, 임의 파일시스템/다른 OS의 속성까지 검증한 것은 아니다. 새 공식 업그레이드 경로를 추가할 때 별도로 확인하고 안전성이 불명확한 설치는 agent 비교 경로를 사용한다. 내용 백업을 native metadata 백업이라고 부르지 않는다.

### Codex 인식과 남은 경계

- 별도 `CODEX_HOME`의 테스트 설치본으로 Codex app-server의 `skills/list`를 새로 읽어 `implementation-ledger`가 user scope, enabled 상태로 발견되고 오류가 없음을 확인했다. 업데이트된 `SKILL.md`와 상대 참조 파일도 읽을 수 있었다. 모델을 호출해 참조 내용을 실제 사용한 검사는 아니다.
- 설치 도구의 성공 경로 출력·등록 URL과 기존 대상 거부는 검증했다. 실제 모델이 설치 요청을 수행하고 성공/실패를 올바르게 보고하는 검사는 미완료다. 격리 환경의 `codex login status`는 `Not logged in`이며 이를 해결하려고 개인 인증 자료를 복사하거나 개인 설정·스킬을 변경하지 않았다.

## 공개 승인과 남은 사용자 검증

1. **사용자 직접 검증:** 2026-10-30 사용자가 남은 실제 Codex 설치 검증을 직접 수행하기로 하고 현재 변경의 커밋·master 병합·푸시·배포를 승인했다. 실제 설치 요청의 성공/실패 보고, 경로/등록 링크와 참조 규칙 사용은 결과를 받기 전까지 미검증이다. AKU-05/06/07의 해당 항목은 열어 두며 이번 공개를 막는 자동 검사로 재요구하지 않는다.
2. **검증 범위:** 현재 macOS Chrome의 알려진 공식본 변경/복원까지 확인했다. 다른 OS와 파일 삭제/재생성이 추가된 업그레이드는 별도 실기가 필요하다. 파일 해시가 OS 메타데이터나 외부 Codex 잠금을 증명하지 않는다.
3. **후속 계약/배포:** 의미 있는 스킬·문서 형식 버전 정책은 AKL-10/11/12의 남은 범위다. 공개 호스팅 응답 검사는 이번 승인에 따라 별도로 수행한다. 다른 PC/하네스 검증을 공개 성공만으로 완료 처리하지 않는다.

## 재현 준비

`node scripts/prepare-native-skill-smoke.mjs`는 무시되는 `output/playwright/` 아래에 테스트 전용 정상/빈/링크 폴더와 격리 홈의 숨김 스킬 폴더를 만든다. 알려진 이전 공식 커밋에서만 복사하며 개인 스킬·설정은 읽지 않는다. macOS에서는 검사할 사용자 확장 속성과 파일 모드도 준비한다. 출력된 경로는 공개 URL에 넣지 않는다.

`pnpm preview`의 별도 출처와 전용 Chrome 프로필에서 `/intro#updates`를 열고 등록 버튼으로 테스트 폴더를 선택한다. 먼저 취소/빈 폴더와 읽기·쓰기 거부/허용을 확인하고, 정상 복사본의 파일 해시·모드·확장 속성을 기록한 뒤 업데이트/복원을 확인한다. 링크 fixture의 바깥 파일은 변경되면 안 된다. 복구 검사는 성공한 파일 저장과 실제 Codex 인식을 구분해 기록한다.

이 환경에서는 CLI/MCP가 관리하는 Chrome의 디렉터리 선택이 창 없이 취소됐지만, 파일 선택 가로채기를 사용하지 않는 별도 headed Chrome과 네이티브 UI 조작에서는 즉시 열렸다. 반응이 없다고 앱 버튼 고장이나 Mac 잠금으로 단정하지 않는다. 네이티브 권한 검사는 테스트 전용 프로필의 실제 선택창으로 하고 OPFS 대체 선택기는 별도 증거로 남긴다.

릴리즈 작성·검사 절차는 [CONTRIBUTING](../CONTRIBUTING.md), 공개 운영 절차는 [deployment](deployment.md)를 따른다. 생성된 캡처·프로필·백업에는 실제 로컬 경로가 포함될 수 있으므로 커밋하지 않는다.
