# 릴리즈 안내와 선택형 Codex 스킬 업데이트 계획

작성일: 2026-10-23
수정일: 2026-11-03

## 목표와 이유

- 사용자가 업데이트 전에 실제 적용할 버전의 변경 내용을 읽고 적용 여부를 결정한다. 업데이트 후에는 프로젝트 선택 화면에서 변경 내역을 한 번 확인하고, 필요할 때 다시 읽는다.
- 웹앱 변경과 implementation-ledger 변경을 구분한다. 최초 설치는 기존처럼 agent에게 요청한다. 설치를 마친 agent가 실제 설치 디렉터리와 등록 링크를 안내하고, 원하는 사용자만 그 폴더를 연결해 확인 후 업데이트한다.
- 2026-10-26 기능 브랜치 구현·개발 테스트 승인에 이어, 2026-10-30 사용자가 현재 변경의 커밋·master 병합·푸시·배포를 승인했다. 남은 Codex 설치·완료 안내 검증은 사용자가 직접 수행하며 이를 자동 검증 통과로 기록하지 않는다. 자동 확인·알림과 매 적용 전 사용자 확인, 기존 PWA 타이틀바 테마를 유지한다. 개인 전역 스킬은 변경하지 않는다.
- 실행 원장: [23_alpha_kanban_release_skill_tickets.md](23_alpha_kanban_release_skill_tickets.md). 기존 원장은 삭제하거나 완료 처리하지 않는다.
- 2026-10-30 후속 변경은 PWA 업데이트 모달의 한 번 승인으로 등록 스킬도 백업·교체하는 흐름이다. 로컬 검증 후 사용자가 릴리즈 노트·ZIP 정합성 확인과 커밋·master 푸시·배포를 승인했다. 남은 실제 Codex 설치 확인은 기존대로 사용자가 수행한다.

## 영향 범위

- `apps/web/pwa.config.ts`, `apps/web/src/pwa`, `apps/web/public-browser/_headers`: 릴리즈 정보·변경 이력·기존 업데이트 제어와 보존 계약.
- `apps/web/src/components/ProjectLauncher.tsx`, `apps/web/src/components/SkillGuide.tsx`, `apps/web/src/components/ui`, `apps/web/src/i18n`: 프로젝트 선택 화면의 안내, 공통 모달과 선택형 스킬 관리 진입점.
- `apps/web/src/browser`: 스킬 전용 연결·비교·복구 상태. 기존 워크스페이스 탐색과 문서 저장은 분리한다.
- `scripts`, `skills/implementation-ledger`: AKL-10/12가 소유하는 버전·고정 배포·전체 파일 검증 계약을 소비한다.
- `docs`, `README.md`, `README.en.md`, `CONTRIBUTING.md`, `AGENTS.md`: 배포별 기록 절차, 사용자 설치 안내와 검증 근거. 운영 절차는 `docs/deployment.md`에 둔다.

## 계획 작성 시 확인한 상태

- `src/pwa/client.ts`와 `protocol.ts`는 실행 시, 활성 창에서 30분 간격, 마지막 확인 후 5분 이상 지난 복귀·재연결 시 업데이트를 확인한다. 수동 확인과 적용도 이미 있다. 알림 서버를 새로 만들 필요는 없다.
- `PwaMenu.tsx`는 준비된 업데이트를 아이콘의 작은 점과 팝오버로 알리고 `app.next.notes`를 표시한다. `pwa.config.ts`의 한영 notes는 초기 PWA 기능 설명으로 고정되어 있어 릴리즈별 기록과 적용 후 재열람은 없다.
- `/release.json`은 동일 출처에서 no-store로 조회하고, 설치 대기 워커의 정보로 실제 적용 대상을 확인한다. `kanban.giveit2.me`와 `alpha-kanban.pages.dev`는 각각 상대 URL을 사용한다. 두 출처의 권한·저장 상태를 공유한다고 가정하지 않는다.
- `src/pwa/session.ts`는 준비에 동의한 창을 현재 URL에서 다시 불러온다. 초안·진행 중 쓰기와 다중 창 보호를 릴리즈 안내 때문에 우회하지 않는다.
- `components/SkillGuide.tsx`에는 설치/업데이트 요청 확인·복사와 비교·백업·개인 수정 보존 안내가 있다. 공식 원본 링크는 master이며, 브라우저가 개인 설치본을 읽거나 설치하지 않는다.
- `scripts/package-browser-assets.mjs`는 전체 폴더 ZIP, 내용 해시와 파일 목록을 만든다. 의미 있는 스킬 버전·문서 형식 및 파일별 검증 계약은 AKL-10/12의 미완료 범위이며 `skillVersion`과 `documentFormat`은 현재 null이다.
- `scripts/install-implementation-ledger-skill.mjs`는 대상 디렉터리를 삭제한 뒤 복사한다. 이를 웹 설치 엔진으로 가져오지 않는다. 안전한 CLI·배포 계약의 보완은 AKL-12에서 유지한다.
- 현재 브라우저의 문서 쓰기 보호는 단일 Markdown 수정용이다. 여러 파일로 된 전역 스킬의 부분 설치·복구나 Codex의 동시 읽기를 검증한 근거는 아니다.

## 할 일과 선택한 방향

### 1. 릴리즈 기록과 실제 적용 대상을 함께 관리

- 저장소에 배포 단위의 한영 변경 이력을 누적하고, 빌드가 같은 자료에서 현재 릴리즈 정보와 이력을 생성한다. 사용자에게 보이는 개선·수정·주의 사항만 제품에 표시한다. 구현 진행률·테스트 대기·로드맵은 티켓에 남긴다.
- 사용자용 릴리즈 ID·배포일·공개 순서와 기술적 buildId를 구분한다. 같은 릴리즈 재빌드만으로 재알림하지 않는다. 앱/스킬/문서 형식/브라우저 저장 구조 버전도 섞지 않는다. 초기 의미 버전이나 태그를 이번 문서에서 임의로 발행하지 않는다.
- 기존 클라이언트가 읽는 `buildId`, `notes.ko`, `notes.en` 등 현재 필드와 검증 계약은 보존하며 메타데이터를 확장한다. 구버전 앱도 새 notes를 읽을 수 있어야 한다. 새 모달 UI는 해당 UI를 포함한 버전을 적용한 뒤 사용할 수 있다.
- 최신 확인은 `/release.json`을 유지하고, 릴리즈별 이력·스킬 자료는 고정된 참조로 묶는다. 별도 GitHub Pages, API 서버, CORS 우회 서비스는 추가하지 않는다.
- 실행 중 버전, 발견한 최신 버전, 준비된 적용 대상은 구분한다. B가 적용 대기 중인데 C가 배포되면 B의 설명 옆에서 C를 적용하거나 그 반대가 되는 일을 막는다. 적용 직전 대상이 바뀌면 변경 내용을 다시 확인받는다.
- 설치 대기 중인 스킬 자료도 해당 웹 버전의 검증된 호환 범위에 묶는다. 현재 뷰어에서 안전한지 확인되지 않은 새 스킬을 먼저 설치하도록 유도하지 않는다.
- 이력 원문은 실행하지 않는 데이터로 렌더한다. 한영 누락·잘못된 링크·중복 릴리즈 ID·버전/파일 불일치는 배포 검증에서 잡는다. 조회 실패나 오프라인에서 모르는 배포를 최신·호환으로 표시하지 않는다.
- 현재 배포의 노트와 필요한 이력은 앱 자산에 포함해 오프라인 재열람을 지원한다. 최신 확인 자료를 오래된 앱 캐시에 가두지 않는다. 내부 정리만 있는 배포도 기록하되 사용자 대상 자동 알림/모달 노출 여부는 릴리즈 자료에서 구분한다.

### 2. 업데이트 전 알림과 읽기

- 기존 확인 주기와 수동 적용을 유지한다. 완전한 새 앱이 적용 준비 상태일 때 비차단 알림과 `업데이트 보기` 행동을 제공한다. 단순 발견·다운로드 중·실패를 적용 가능 상태와 혼동하지 않는다.
- 같은 대상 릴리즈의 발견 알림은 한 번만 제안하고, 닫아도 업데이트 아이콘의 표시와 팝오버 진입은 남긴다. 주기 확인·포커스 복귀·언어 변경 때마다 알림을 반복하지 않는다.
- 사용자가 알림이나 팝오버에서 선택하면 공통 릴리즈 내역 모달을 연다. 적용 전에는 준비된 버전의 내용임을 명확히 하고, 기존 업데이트 보호 절차를 거쳐 사용자가 적용하게 한다.
- 입력·저장·다른 모달·투어를 방해하거나 포커스를 빼앗지 않는다. 팝오버를 닫은 뒤 모달을 열고, 닫을 때 호출한 버튼으로 초점을 돌린다. OS 푸시와 종료된 앱의 정시 확인은 추가하지 않는다.

### 3. 적용 후 프로젝트 선택 화면에서 한 번, 언제든 다시 보기

- 자동 릴리즈 모달은 `/`의 프로젝트 선택 화면이 실제 표시된 시점에만 연다. `/w/:id`, `/all`, `/intro`에서는 업데이트 직후라도 자동으로 열지 않는다.
- 프로젝트에서 업데이트했다면 같은 URL·선택 상태로 복귀하고, 이후 사용자가 프로젝트 선택 화면에 돌아왔을 때 보여준다. `/`에서 업데이트했다면 그 화면이 복원되고 준비된 뒤 보여준다. 프로젝트 자동 다시 열기 설정을 바꾸거나 안내 때문에 `/`로 강제 이동하지 않는다.
- 최초 방문에는 기준 릴리즈를 기록하고 과거 업데이트 모달을 자동 표시하지 않는다. 기록 도입 이전 사용자와 신규 사용자를 확인 가능한 정보로 구별할 수 없으면 과거 방문을 추정하지 않고 첫 기준으로 처리한다. 이 경우에도 수동 내역 읽기는 가능하다.
- 알림 노출 여부, 변경 내역 읽음, 실제 적용 버전을 각각 보존한다. 알림을 닫은 것만으로 읽음 처리하지 않는다. 해당 릴리즈 내역이 실제로 열린 뒤 닫기·Escape로 마무리되면 읽음으로 기록한다. 적용 전에 이미 읽은 같은 릴리즈는 적용 후 다시 자동 표시하지 않는다.
- 여러 버전을 건너뛴 경우 확인하지 않은 변경 내역을 한 모달에서 순서대로 보여준다. 앞으로 나올 버전이나 롤백된 상위 버전을 이번에 적용된 내용으로 표시하지 않는다.
- 같은 출처·브라우저 프로필의 여러 창에서 읽음과 노출을 공유하고 동시에 자동 모달을 여러 개 열지 않는다. 숨은 탭이나 다른 모달에 가린 상태를 노출 완료로 소비하지 않는다. 브라우저 저장이 차단되면 세션 범위로 중복을 억제하며 영구 1회 보장을 주장하지 않는다.
- 업데이트 팝오버에 `업데이트 내역` 진입점을 항상 둔다. 적용 후에는 현재/과거 기록을, 적용 대기 중에는 그 대상의 기록도 구분해서 읽는다. 이 행동은 화면 이동·업데이트 적용·권한 요청을 발생시키지 않는다.
- shadcn Dialog·Popover·Button, 현재 색상·폰트·다크 테마와 한영 전환을 유지한다. 모달은 한 개의 본문 스크롤을 사용하고 키보드·좁은 화면에서 읽고 닫을 수 있어야 한다.

### 4. agent로 최초 설치한 뒤 원하는 사용자만 폴더 등록

- 뷰어만 변경되면 웹 업데이트만 안내한다. 스킬도 변경되면 스킬 변경 이유, 적용 대상, 권고인지 호환성상 필요한지와 문서 조치 유무를 따로 보여준다. 계약과 실제 검증 없이 필수 업데이트로 표시하지 않는다.
- 최초 설치는 외부 AI용 요청 확인·복사를 기본으로 유지한다. agent가 해당 환경의 실제 설치 위치를 결정하고 전체 스킬을 설치·검증한다. 수동 다운로드는 보조 수단으로 남기며 웹의 OS·하네스별 기본 경로 선택/복사 마법사와 최초 설치 엔진은 만들지 않는다.
- 설치 요청문은 agent가 성공한 경우 마지막 채팅/콘솔 안내에 실제 설치 디렉터리를 복사 가능한 텍스트로 출력하고, 웹에서 업데이트를 관리하려면 그 폴더를 등록할 수 있다고 안내하도록 한다. 실패 시 완료·등록을 권하지 않고 실제 실패와 다음 행동을 보고한다.
- 완료 안내에는 `스킬 폴더 등록` 링크로 공개 `/intro#updates` 진입점을 제공한다. 링크를 지원하지 않는 콘솔에서는 동일한 일반 URL을 표시한다. 웹에는 `설치된 스킬 폴더 등록` 버튼을 두고 클릭했을 때만 선택창을 연다. 등록 진입은 기존 설치 안내에서도 다시 찾을 수 있다.
- 실제 설치 경로는 agent의 채팅/콘솔 안내에서 제공한다. Alpha Kanban의 공개 링크 query/hash, 서버 요청, 분석 정보에는 경로를 싣지 않는다. 링크가 권한이나 파일 핸들을 전달하거나 해당 폴더를 자동 선택한다고 표현하지 않는다.
- 선택형 업데이트 관리는 Codex용 implementation-ledger부터 제공한다. 다른 하네스 선택기를 먼저 만들지 않으며 Claude 포팅·인식 검증은 기존 AKL-07에 남긴다. 폴더 등록 없이도 agent에 업데이트를 요청하는 기존 방법을 계속 쓸 수 있다.
- 사용자가 명시적으로 선택한 기존 스킬 전용 폴더에만 별도 동의를 받는다. 워크스페이스 권한을 재사용하거나 홈/AI 설정/부모 skills 폴더를 탐색하지 않는다. 스킬 핸들·상태는 프로젝트 목록·문서 검색·전체 보드에서 제외한다.
- 선택한 폴더의 SKILL.md 이름과 배포 자료·내용을 확인한다. 폴더명만으로 전역 위치나 Codex 인식을 보증하지 않는다. 빈 폴더·다른 스킬·부모 폴더를 선택하면 새 스킬을 생성하지 않고 올바른 폴더를 다시 선택하거나 agent 설치 요청으로 돌아가게 한다.
- 등록 시 읽기·쓰기 권한을 함께 받되 최초 읽기·비교만 수행하며 파일을 생성·수정하지 않는다. 워크스페이스·프로젝트도 동일하게 등록하고 권한이 있는 연결에는 추가 허용 버튼을 표시하지 않는다. 이전 연결의 재허용은 저장된 핸들을 유지한다. 이후 웹이 업데이트 확인과 파일 배치를 돕되 실제 교체는 기존 합의대로 매번 사용자 확인 후 수행한다. 등록을 무확인 백그라운드 교체 동의로 해석하지 않는다. 취소·거부·권한 만료 시 기존 연결·설정·백업과 요청문 경로를 유지한다.
- 등록한 설치본만 버전 자료·전체 파일 목록/해시로 공식 배포와 비교한다. 공식본 일치, 개인 수정·추가 파일, 출처/버전 불명, 권한 필요를 구분하고 외부 변경 후 다시 확인한다. 파일 내용·경로·해시를 서버에 업로드하지 않으며 미등록 사용자의 설치 버전을 추측하지 않는다.
- 연결 해제는 앱이 기억한 핸들과 연결 상태만 제거하며 설치 파일이나 미해결 복구본을 삭제하지 않는다. 브라우저 사이트 권한 철회와 핸들 기억 삭제는 다른 동작으로 안내한다.

### 5. 등록된 설치본의 확인 후 업데이트와 실패 복구

- AKL-10/12의 공식 고정 배포·호환 정보·전체 파일 해시를 사용한다. SKILL.md만 교체하지 않고 references/assets/scripts/버전 자료를 함께 다룬다. 배포 출처는 변경 가능한 master가 아닌 확인된 커밋·태그에 고정한다.
- 등록·검증한 기존 설치본에만 대상과 변경 요약을 제시하고 매 업데이트마다 확인받는다. PWA 업데이트 모달에서 실제 대기 버전과 등록 스킬의 변경 파일을 함께 확인하면 한 번의 승인으로 처리한다. Codex 작업이 끝난 뒤 누르도록 안내하되 별도 중지 확인 체크박스나 세션 감지는 추가하지 않는다. 이전 폴더 권한이나 이번 승인을 다른 배포의 포괄 동의로 취급하지 않는다. 일반 업데이트와 PWA 결합 업데이트는 개인 수정·출처 불명을 계속 차단하며 최초 설치는 기존 AI 요청 경로를 유지한다.
- AKU-08은 사용자가 스킬 관리에서 별도로 선택하는 재설치다. 카나리·미확인·개인 수정 설치본도 추가/변경/삭제 파일의 실제 변경 전후 내용을 보고 명시적으로 확인하면 현재 앱에 고정된 공식 번들로 교체한다. 교체 전 전체 설치본을 백업하며 기존 확인의 재사용·무확인 교체·호환 불명 대상·미해결 복구·외부 변경·경로 충돌·배포 무결성 오류는 허용하지 않는다. 정식 앱에서는 정식 번들이 대상이고 다른 도메인의 백업 없이도 시작할 수 있다.
- 승인은 대상 앱 build·스킬 payload·등록 폴더·설치본 전체 해시/수정시각에 묶어 영속 저장한다. 기존 PWA 보호 절차로 새 앱이 열린 뒤 상태를 다시 확인해 백업·교체한다. 앱 적용이 보류되면 스킬은 쓰지 않고, 개인 수정·권한 만료·호환 불명·미해결 복구에서는 명시적으로 앱만 업데이트할 수 있다. 파일 교체가 중단되면 자동 재시도하지 않고 스킬 관리에서 확인·복원한다.
- 모든 배포 파일을 확보·검증하고, 기존 전체 설치본의 복구 가능한 백업과 작업 기록을 먼저 만든 뒤 파일 배치를 시작한다. 네트워크 실패·용량 부족·해시 불일치에서 기존 폴더를 먼저 삭제하지 않는다.
- 백업은 Codex가 또 다른 스킬로 읽지 않는 앱 전용 복구 저장소 또는 별도 허용 백업 위치에 둔다. 영속 기록·백업 확보 실패 시 교체를 시작하지 않는다. 파일 목록·추가 파일·이전 내용과 재개/복원 상태를 보존하고 백업 내보내기 경로를 마련한다.
- 백업은 해당 출처의 IndexedDB에 교체 전후 내용을 저장하고 복원·연결 해제 후에도 자동 삭제하지 않는다. 재설치 미리보기와 백업 목록에 UTF-8 파일 내용 합계와 보관 방식을 표시한다. 브라우저의 실제 디스크 사용량으로 주장하지 않으며 자동 정리·보존 기간 변경은 이번 범위에 넣지 않는다.
- 배포 파일 경로 이탈, 절대 경로, 심볼릭링크, 중복/대소문자 충돌, 잘못된 파일 목록과 과도한 압축·용량을 검증한다. 다른 스킬, 전역 AGENTS·인증·설정·프로젝트 문서는 수정하지 않고 번들 스크립트를 실행하지 않는다.
- 설치본의 확인 시점과 쓰기 직전 상태를 비교하고, 파일 close 후 재읽기·해시 검증을 완료해야 성공으로 기록한다. 다중 창 쓰기는 직렬화하고 모든 파일 작업을 기존 PWA 활동 보호에 참여시킨다. 스킬 비교/적용 대화상자의 미확정 선택도 업데이트로 잃지 않는다.
- 브라우저 파일 API의 여러 파일 쓰기를 원자적 폴더 교체라고 주장하지 않는다. 외부 Codex 프로세스의 읽기·쓰기를 잠글 수 없으므로 스킬 사용 중 적용을 피하도록 안내한다. OS 권한·파일 속성·링크 제한으로 안전한 전체 설치가 불가능하면 직접 적용을 막고 대체 설치 경로를 제공한다.
- 중단·탭 종료·권한 철회·부분 쓰기 실패는 성공이 아닌 복구 필요로 남긴다. 다음 시작과 재연결에서 사용자가 상태를 확인하고 재개/복원을 선택한다. 복원도 외부 최신 변경을 다시 검사하며 불확실한 작업을 자동 재실행하지 않는다.
- 파일 검증 성공은 설치 파일 저장 완료이며 Codex의 로딩 성공과 다르다. 웹은 Codex를 실행·재시작하지 않는다. 실제 인식은 격리된 Codex 환경에서 별도로 확인한다.

## 성공을 확인할 방법

- 구버전·준비된 버전·더 최신 배포가 다른 fixture로 알림/노트/적용 대상 일치와 기존 클라이언트 JSON 호환을 검증한다. 같은 릴리즈 재빌드, 여러 버전 건너뛰기, 롤백, 조회 실패·오프라인도 포함한다.
- 프로젝트에서 업데이트 후 같은 문서로 돌아오며 자동 모달이 없고, 이후 실제 프로젝트 선택 화면에서 한 번만 뜨는지 검사한다. 최초 방문·기록 없음·미리 읽음·다중 창·저장 차단·자동 프로젝트 재열기·투어/다른 모달과 충돌을 확인한다.
- 격리된 agent 최초 설치 결과의 실제 디렉터리 보고·등록 링크와 웹의 기존 폴더 등록을 연결해 확인한다. 테스트 전용 OS 폴더에서 권한 거부/철회·재시작·공식본/개인수정본 비교·전체 파일 업데이트·실패 복구·하네스 인식을 검증한다. 현재 사용자의 개인 전역본은 사용하지 않는다.
- 빈 폴더·다른 스킬·부모 폴더 선택 시 파일이 생성되지 않고, agent 링크에는 개인 경로가 없으며, 등록 안내 링크를 여는 것만으로 선택창·권한 요청이 자동 발생하지 않는지 검사한다. 텍스트 콘솔에서도 URL로 등록 진입을 찾을 수 있어야 한다.
- 실제 Chrome에서 숨김 경로 선택, 쓰기 허용, 파일 종류/속성·심볼릭링크 제한을 먼저 확인한다. 가짜 핸들·OPFS 검사만으로 실제 스킬 설치 가능 판정을 내리지 않는다.
- 설치 중 PWA 업데이트, 다른 창 작업, 외부 파일 변경, close/readback 실패와 복원 후 추가 변경을 재현한다. 프로젝트 문서·다른 스킬·인증/설정 파일이 바뀌지 않았는지 대조한다.
- 한영, 라이트/다크, 키보드·좁은 화면·포커스 복원, 연결 해제와 요청문 복사 fallback을 검사한다. 사용하지 않는 연결 방식이나 검증되지 않은 하네스 지원을 광고하지 않는다.
- 구현 단계에서 범위에 맞는 단위/통합 검사와 `pnpm typecheck`, `pnpm build`를 수행하고, 자산/저장/PWA 경로를 바꾼 부분은 격리된 `pnpm test:pwa`와 실제 Chrome 검사로 보완한다. 기능 브랜치의 수행 결과와 남은 병합 조건은 [릴리즈·스킬 검증 기록](release_skill_validation.md)에 구분한다.

## 확인·결정이 필요한 사항

- 없음. 최초 설치는 agent가 수행하고 실제 디렉터리와 선택형 등록 링크를 안내한다. 웹은 기존 설치본 업데이트와 별도 확인을 거친 재설치를 관리하며 매 적용 전 확인·프로젝트 선택 화면의 1회 모달을 유지한다. 2026-10-30 PWA·스킬 결합 승인 변경은 로컬 검증 후 커밋·master 푸시·배포가 승인됐다. AKU-08 재설치는 로컬 구현·검증 범위이며 별도 배포 승인은 없다. 남은 실제 Codex 설치 검증은 사용자가 직접 수행한다.

## 제외 범위

- 개인 전역 스킬 설치·수정, 릴리즈 태그 발행·DNS 변경, 별도 팀 기능 계획 문서. 이번 PWA·스킬 결합 승인 변경의 커밋·master 푸시·공개 배포는 2026-10-30 후속 승인 범위에 포함한다.
- 무동의 전역 폴더 탐색·백그라운드 자동 스킬 교체·원격 스크립트 실행·AI 세션 제어·Node API/상주 설치 서비스.
- 웹의 최초 스킬 설치, OS·하네스별 기본 경로 추천/복사 마법사, 부모 skills 폴더 관리, 개인 설치 경로를 포함한 등록 URL.
- 홈/설정/인증 폴더 전체 관리, 다른 스킬 정리·삭제, 사용자 문서 자동 변환, 임의 개인 수정 병합.
- 다른 출처·브라우저 프로필 간 연결/읽음 기록 동기화, OS 푸시 알림, 종료된 앱의 정시 실행.
- Claude 등 다른 하네스의 직접 설치 지원. 현재 문서 뷰어·스킬 기본 동작을 스킬 연결 필수로 바꾸는 것.
