# PWA 검증 기록

검증일: 2026-10-18. 브라우저 전환 구현에 대한 로컬 검증 기록이다. DNS·공개 배포 검증은 포함하지 않았으며, 기존 사용자 환경과 분리한 서버와 브라우저 프로필을 사용했다.

## 환경과 재현

- macOS / Darwin 24.6.0 arm64, Chrome 155.0.8059.85, Node 24.14.0.
- `pnpm test:pwa`는 새 Chrome 프로필과 임의 localhost 출처를 만들고 앱 A/B, 복구, 퇴역 빌드를 생성한다. 서비스 워커가 허용되는 localhost에서 `_headers`의 CSP·MIME·캐시 정책을 모사한다.
- 테스트 산출물은 무시된 `output/playwright/pwa-<timestamp>/`에 빌드 로그, 화면 캡처와 `results.json`으로 남는다. `PWA_SMOKE_BUILD_DIR=<이전 산출물 경로>`는 디버깅용 빌드 재사용이며 기본 실행은 새 빌드다.
- 파일 테스트는 picker 반환값을 실제 OPFS `FileSystemDirectoryHandle`로 교체한다. IndexedDB 직렬화와 파일 write/close/readback은 실제 Chrome API지만, 네이티브 폴더 선택기·OS 폴더 권한·권한 재허용을 증명하지 않는다.
- 설치 검사는 Chrome DevTools Protocol의 설치·standalone 선택·실행 명령을 사용한다. 네이티브 설치 버튼을 사람이 누른 검증과 구분한다.

## 통과한 검사

| 검사 | 확인한 내용 |
| --- | --- |
| `pnpm test` | shared 15 + server 84 + web 203 = 302개 통과. 설치 이벤트/취소, 초안·쓰기 차단, DB 미지원 버전과 저장 실패 보존, 자산 설치 중 퇴역 차단 포함 |
| `pnpm typecheck` | shared/server/web 타입 검사 통과 |
| `pnpm build:browser` / `pnpm build` | 정적 브라우저 빌드와 기존 서버 모드 빌드 통과. 기존 큰 JS 청크 경고는 남음 |
| 설치·독립 창 | CDP 설치, standalone 표시, `/intro` 실행, 다른 두 탭과 함께 새 버전으로 전환 |
| 설치 앱 오프라인 재실행 | Chrome 프로세스를 닫고 같은 프로필을 네트워크 차단 상태로 다시 열어 설치 앱 실행 |
| 완결된 오프라인 자산 | 현재 스킬 ZIP 하나, JS/CSS, 아이콘, 모든 동봉 폰트와 안내 자료를 SRI로 검사. 복구/최신 배포 정보는 precache 제외 |
| 오프라인 문서 작업 | 미방문 `/intro`·`/all`·프로젝트 직접 링크 진입과 OPFS 지시 append/readback |
| 전환 보류 | 다른 탭의 미저장 초안, 파일 close 지연, 응답 없는 앱 창에서 전환 거부. 초안은 그대로 유지 |
| 다중 창 전환 | 동의한 탭·설치 창만 잠그고 전환. 새 버전·연결 ID·문서 ID·보기 설정·미해결 복구 기록 비교 |
| 부분 다운로드 실패 | JS 대신 HTML을 반환하는 고장 배포를 SRI로 거절하고 기존 정상 앱 유지 |
| 독립 복구 | 앱 JS 캐시를 삭제한 뒤 `/repair.html`로 파일 재확보. 사용자 데이터·문서 원문은 보존 |
| 고장 워커 복구 | 앱 JS가 없는 잘못된 화면에서 같은 `/sw.js`를 요청 비개입 복구 워커로 교체하고 Chrome 재실행. 이후 정상 PWA로 복귀 |
| 오프라인 퇴역 | 퇴역 워커 설치 후 네트워크를 차단하고 Chrome 재실행. 마지막 완결 앱과 사용자 데이터 유지 |
| 온라인 퇴역 | 온라인 재방문 시 소유 등록·캐시만 제거. 별도로 심은 타 앱 등록/캐시, 폴더 참조, 설정, 미확정 저장 기록 보존 |
| 네트워크 경계 | 시나리오의 요청은 GET/HEAD뿐이며 원본 Markdown이나 지시를 업로드하지 않음 |
| 좁은 화면 | 1360px / 390px 앱 메뉴 캡처와 팝오버 경계 확인. 모바일 지원 완료 판정은 아님 |

최종 검사에서 Chrome 시나리오 16개가 통과했고 캡처 4개를 검토했다. 테스트의 라우트 전환 대기는 실제 화면 조건으로 바꾸었고, 워커 설치 완료를 확인한 뒤 Chrome을 재시작한다.

일반 미리보기 빌드는 `c5558b85803dbdcd`다. 중복을 제외한 오프라인 자산 108개, 폰트 97개, 스킬 ZIP 1개이며 합계는 4,606,071바이트(약 4.39 MiB, HTTP 압축 전)다. 별도 스모크의 A/B/복구/퇴역 빌드 ID는 `results.json`에 남긴다. 검증에는 격리된 설치 앱과 Chrome 프로필을 사용했다.

## 사용자 확인

- 2026-10-18: 사용자가 기본 설치와 워크스페이스 불러오기가 정상 동작한다고 보고했다. 사용자 수동 스모크 결과이며 위 자동 검사와 구분한다.
- 설치 취소, OS 앱 아이콘 재실행, 오프라인 재실행, 업데이트·복구·폐기와 그 과정의 폴더 연결·설정 보존까지 확인한 것은 아니다. 구체적인 설치 경로와 권한 재허용 여부도 이번 보고만으로 확정하지 않는다.

## 남은 출시 조건

- 실제 Chrome 설치 대화상자에서 설치·취소·이미 설치된 상태와 OS 아이콘 재실행을 확인한다.
- 실제 OS 폴더로 오프라인 재실행, 권한 재허용, 상태 변경/지시 저장, 외부 수정 충돌, 복구 기록, 상대 이미지와 수정 시각을 확인한다. 사용자 원본 대신 전용 테스트 폴더를 사용한다.
- 실제 CacheStorage 용량 부족과 브라우저의 저장 공간 정책을 확인한다. IndexedDB 저장 실패 단위 검사를 캐시 할당 실패 검증으로 취급하지 않는다.
- 장기 중단·여러 릴리스 건너뛰기·반복 업데이트 확인·보관 요청 거부를 추가 검증한다. 이번 버전에는 DB 구조 변환이 없고, 미래 구조를 거부하는 검사는 수행했다.
- AKL-10~13의 스킬/문서 형식 계약을 연결한다. 현재 `release.json`에는 웹 빌드 ID·동봉 해시·저장 구조 버전만 사실대로 넣고 미정인 의미 버전은 null로 둔다.
- 별도 배포 승인 후 `https://kanban.giveit2.me`에서 TLS, 실제 CSP/MIME/캐시 헤더, SPA fallback, 직접 링크, 동일 설치 식별과 데이터 보존을 확인한다. localhost 검증으로 대체하지 않는다.

필수 실사용·정식 출처 검사와 버전 계약 연결이 남아 있으므로 AKP 티켓은 완료 처리하지 않는다. 운영 절차는 [pwa_operations.md](pwa_operations.md), 세부 상태는 [AKP 티켓](16_alpha_kanban_pwa_tickets.md)에 유지한다.
