## 확인·결정이 필요한 사항

- 같은 implementation-ledger를 여러 에이전트·전역/프로젝트 위치에 설치한 경우 여러 폴더를 동시에 등록·관리할 것인가? AKC-10은 전용 폴더 하나의 드롭 또는 선택까지 확정한다. 다중 등록을 택하면 설치 위치 구분·중복 대상·업데이트 선택·실패/복구 범위를 별도로 정한다.
- 리뷰·QA 기능을 릿저 안에 둘 것인가, 별도 스킬 폴더로 배포할 것인가? 분리한다면 SKILL.md 이름은 종류 식별의 후보일 뿐이며 관리할 스킬과 검증된 배포본의 대응이 필요하다. 폴더명이나 이름만으로 다른 스킬을 덮어쓰지 않는다. 다중 드롭·배포 형식은 보류하며 위 두 질문은 AKC-10의 선행 조건이 아니다.

채널·공개 페이지의 기존 확정 사항은 유지한다. 디자인은 설치된 프로그램의 Local Codex를 거치고 내부 컴포넌트를 우선 사용하며 없는 요소만 shadcn에서 선별한다.

### AKC-10. 설치한 릿저 폴더를 드롭하거나 선택해 업데이트에 연결한다

목표:

현재 문제:

- agent와 설치 범위에 따라 스킬 위치가 달라 사용자가 폴더 선택창에서 목표 폴더를 찾기 어렵다. 연결의 목적·받는 범위·쓰기 권한과 실제 업데이트 승인의 차이도 화면에서 이해하기 어렵다.

구현 범위:

- Local Codex에서 연결 전·연결됨·권한 만료·잘못된 대상의 흐름을 검토한 뒤 기존 스킬 관리자에 반영한다. 내부 컴포넌트를 우선 사용하고 없는 요소만 shadcn에서 선별한다.
- implementation-ledger 전용 폴더 자체를 드롭하는 방법과 기존 폴더 선택 버튼을 함께 제공한다. 받은 디렉터리 핸들 안의 SKILL.md와 기존 설치 검사로 대상을 확인하고 readwrite 권한을 명시적으로 요청한다. 연결만으로 파일을 쓰거나 업데이트를 승인하지 않는다.
- 상위 skills·홈 폴더를 요구하거나 자동 탐색하지 않는다. 드롭 기능을 쓸 수 없으면 폴더 선택으로 이어간다. 파일만 드롭·다른 스킬·잘못된 폴더·권한 거부·취소는 기존 연결을 유지하며 필요한 다음 행동을 안내한다.
- 여러 항목을 드롭해도 임의로 첫 항목을 등록하거나 기존 연결을 바꾸지 않는다. 이번 범위는 한 전용 폴더 연결이며 다중 설치 위치와 별도 리뷰·QA 스킬 관리는 열린 질문으로 남긴다.
- 첫 설치는 외부 agent 흐름을 유지한다. 완료 안내에서 실제 설치 위치를 알려주고 가능하면 파일 관리자에서 폴더를 여는 행동으로 연결한다. 직접 선택할 때는 경로 이동 방법을 안내하되 웹이 임의 절대경로로 선택창을 열거나 경로 붙여넣기만으로 권한을 얻는다고 약속하지 않는다.
- 이미 연결된 핸들·설치 정보·백업을 재사용하고 재시작 후 권한 재허용과 기존 연결 해제/변경 흐름을 유지한다. agent 이름·개인 경로를 추측하거나 검증하지 않은 도구의 설치 지원을 주장하지 않는다.
- 실행 앱에 고정된 배포본·해시, 확인된 공식 배포본과 미확인 설치본의 판정, 업데이트별 확인과 명시적 재설치, 백업·외부 변경 거절·쓰기/읽기 검증·복구·잠금·PWA 초안 보호를 그대로 사용한다. 드롭과 폴더 선택은 같은 연결·갱신 경로로 합류한다. 해시 불일치만으로 개인 수정이라고 단정하지 않는다.

- 일반 설치·비교·업데이트·복원, 오류·복사 요청·투어·소개 예시는 사용 중인 AI 도구를 기준으로 안내한다. 실제 도구별 경로·호출 문법은 이름을 붙인 설치 예시로 구분하고, 공개된 릴리즈 이력이나 기술 메타데이터는 바꾸지 않는다.
