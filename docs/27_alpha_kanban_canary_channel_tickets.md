목표:

- 어느 앱에서 설치 요청과 다운로드를 사용하든 그 앱에 고정된 스킬을 받고, 카나리 사용 후 정식 앱의 재설치 경로로 돌아온다.

현재 문제:

- 설치 요청문과 INSTALL.txt에는 정식 주소·master 안내가 남아 있어 카나리 앱에서 정식 스킬을 받을 수 있다. AKU-08은 로컬 완료 상태이며 실제 정식 배포 완료와는 별개다.

구현 범위:

- 스킬 이름과 호출은 implementation-ledger로 유지한다. 설치·업데이트 요청, ZIP의 INSTALL.txt, 설치 완료 후 등록 링크를 채널 설정과 앱에 고정된 배포본에 연결한다.
- JSON·ZIP·페이로드 해시를 같은 앱 빌드에 고정하고 오프라인 다운로드도 같은 묶음을 사용한다. 같은 스킬 내용의 묶음 ID를 채널명만으로 다르게 만들지 않는다.
- 스킬 교체 화면에서 정식 제공 스킬 또는 카나리 제공 스킬과 실제 변경 내용을 표시한다. 설치본 출처는 파일 비교 없이 추측하지 않는다.
- 일반·PWA 업데이트와 재설치의 파일 변경 내용은 문서 정리와 같은 CodeDiff로 표시한다. 긴 파일은 변경 부분부터 보여주고 문맥을 펼칠 수 있으며, 대화상자의 본문만 스크롤하여 제목과 닫기 버튼을 유지한다.
- 일반/PWA 업데이트의 공식 스냅샷·호환성·동의 보호와 AKU-08의 별도 재설치를 유지한다. 카나리 채널을 이유로 호환성을 승인하거나 무확인 덮어쓰기를 허용하지 않는다.

현재 문제:

구현 범위:

- 실행 중인 빌드의 채널·공개 이력에 맞춰 기본 목록을 제공한다. 카나리 전용 변경을 정식 내역에 섞지 않고 공개되지 않은 이후 기록을 노출하지 않는다. 당시 변경 사실과 계속 갱신하는 docs의 역할을 구분한다.
- 기존 업데이트 팝업의 요약·전체 내역 진입·실제 대기 워커의 대상과 적용 승인을 보존한다. 현재 빌드에 아직 없는 대기 릴리즈 상세를 무조건 링크하지 않고 검증된 팝업 요약을 유지한다. 페이지 방문으로 업데이트 동의·미열람 내역의 일괄 읽음·초기 알림 기준을 변경하지 않는다.
- 내부 컴포넌트와 공통 채널·언어·테마를 재사용한다. 폴더를 연결하지 않아도 목록·상세를 직접 열고 새로고침·오프라인 준비 후 열람할 수 있게 한다.

제외 범위:

- 게시글 작성용 관리자·댓글·계정·CMS, 업데이트 승인·알림 정책 변경, 문서 열람에 따른 앱·스킬 자동 교체
