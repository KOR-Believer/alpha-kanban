# Alpha Kanban 파일 탐색과 미리보기 계획

Document-ID: 1fe20e74-0d6e-44e0-a441-f99679c3aefa

작성일: 2026-11-13
수정일: 2026-11-20

## 목표와 이유

작업 기록과 참고자료가 함께 있는 프로젝트에서, 플랜·티켓을 빠르게 찾아 작업하면서 요구사항·스펙·이미지·PDF·HTML도 같은 앱에서 열어 본다. 수백 개의 일반 Markdown을 작업 목록에 한꺼번에 나열하지 않고 실제 폴더 구조로 찾아갈 수 있게 한다.

문서 패널에 **작업 문서 / 파일 탐색** 두 보기를 둔다. 작업 문서는 `.ak.config`의 `[documents] root`가 가리키는 폴더를 기존 카드·자세히 보기로 표시하고, 파일 탐색은 연결한 프로젝트의 폴더와 파일을 트리로 표시한다. 설정이 없으면 기존 기본값인 `docs`를 사용한다. `contexts`는 설정 예시이며 특정 폴더 이름이나 회사의 문서 체계를 제품에 고정하지 않는다.

이 문서는 지원 범위와 검증 방향을 정하는 플랜이다. [실행 티켓](33_alpha_kanban_file_explorer_tickets.md)의 AFE-01에서 기존 로컬 문서 패널 디자인 프로젝트를 이어 후속 시안을 검토했다. 2026-11-13 사용자가 시안을 승인하고 AFE-02부터 순서대로 앱에 구현하도록 지시했다. 다른 저장소의 설정·문서 변경, 스킬 교체, 커밋·배포는 포함하지 않는다.

## 영향 범위

- `apps/web/src/App.tsx`, `components/documents/`: 두 탐색 보기, 작업 폴더 범위, 트리와 기존 패널의 연결.
- `apps/web/src/browser/`: 연결 경계를 지키는 파일 목록·읽기, 설정 재사용, 링크에서 미리보기로 이동, 권한 복구.
- `apps/web/src/appRoute.ts`, `components/NavigationLink.tsx`: 파일 선택의 주소·뒤로 가기·새 탭 동작과 기존 문서 경로 보존.
- `apps/web/src/documentSearch.ts`, 관련 검색 상태: 현재 보기의 검색 범위와 프로젝트 전체 검색.
- `apps/web/src/components/`: 유형별 읽기 전용 미리보기와 기존 Markdown·보드·스모크 화면 재사용.
- `apps/web/src/i18n/`, `onboarding/`, `publicDocs/`: 기능을 적용할 때 실제 동작에 맞춘 안내와 접근성.
- `apps/web/vite.config.ts` 및 브라우저 자산 구성: 미리보기 모듈의 지연 로딩, 필요한 로컬 자산과 PWA 동작 확인.
- 스킬 규약, 문서 템플릿, Markdown 저장 형식, `.ak.config` 문법과 설정 상속은 변경하지 않는다.

## 할 일과 선택한 방향

### 1. 작업 문서와 파일 탐색

| 보기 | 대상 | 화면과 동작 |
| --- | --- | --- |
| 작업 문서 | 유효하게 판정한 `root` 폴더와 그 하위 Markdown | 기존 문서 묶음, 카드·자세히 보기, 정렬, 소유자·완료·유형 필터를 유지한다. 일반 Markdown도 기존 표시 설정을 따른다. |
| 파일 탐색 | 연결한 프로젝트에서 탐색이 허용된 폴더와 파일 | 실제 폴더 구조를 펼치고 접는다. Markdown 외 파일도 이름과 유형을 표시하고 선택하면 해당 미리보기를 연다. |

- 패널의 보기 선택과 카드·자세히 선택을 구분한다. 카드·자세히는 작업 문서 안의 표시 방식이다.
- 최초 기본값은 작업 문서와 기존 왼쪽 고정 카드 보기다. 이미 저장된 고정 위치·플로팅·크기·접힘·카드/자세히 설정을 초기화하지 않는다.
- 상하좌우 고정, 드래그 이동, 플로팅, 리사이저와 하단 문서 버튼은 기존 패널 동작을 유지한다. 문서 버튼은 현재 보기의 표시 여부만 바꾼다.
- 프로젝트별로 선택한 탐색 보기와 트리 펼침 상태를 기억한다. 작업 목록 필터와 트리 상태를 분리하고 기존 설정 키를 다른 뜻으로 재사용하지 않는다.
- 작업 문서에서 선택한 소유자·완료·유형 필터 때문에 파일 트리의 파일이 사라지지 않는다.
- 보기 전환이나 패널 크기 변경만으로 열린 문서·보드·스모크 시트·티켓 초안을 다시 만들거나 닫지 않는다.
- 작업 폴더가 비어 있거나 존재하지 않으면 파일 탐색으로 갈 수 있는 빈 상태를 표시한다. 설정 오류가 있으면 오류와 탐색 경로를 안내하되 이미 열린 문서와 프로젝트 파일 접근을 막지 않는다.
- 설정은 기존 판정 도구를 재사용한다. UI가 `.ak.config`를 만들거나 수정하지 않고, `.ak.user`를 사용자 판정에 읽거나 브라우저용 설정을 스킬에 추가하지 않는다.

설정 예시:

```text
[documents]
    root = contexts
```

```text
project/
├── .ak.config
├── contexts/       # 작업 문서 보기의 범위
│   └── @alice/
└── docs/           # 파일 탐색으로 찾아보는 참고 문서
    ├── projects/
    └── specifications/
```

`ownerFolders`는 기존의 별도 선택 설정이다. 폴더 위치·Owner·Document-ID를 탐색 도중 새로 기록하지 않는다. 작업 문서 범위 밖의 기존 문서도 파일 탐색·직접 주소·링크로 계속 열 수 있다. 전체 티켓 화면의 수집 범위와 필터도 이 작업으로 축소하지 않는다.

### 2. 파일 트리와 검색

- 트리는 폴더의 직계 항목부터 읽고, 펼친 폴더의 자식 목록을 추가한다. 목록에는 이름·상대경로·파일/폴더 구분·미리보기 유형을 사용하고, 펼치기만으로 모든 파일 본문이나 크기를 읽지 않는다.
- 기존 연결 경계, 중복 연결 제외, 관리 디렉터리·의존성·빌드 산출물 제외를 유지한다. 숨긴 폴더를 전부 탐색하도록 넓히지 않으며 명시적으로 설정한 문서 루트의 접근은 유지한다. 브라우저에서 확인하지 못하는 Git 추적·ignore 상태를 아는 것처럼 표시하지 않는다.
- `contexts`와 `contexts-old`를 구분하는 경로 구간 단위로 작업 범위를 판정한다. 단순 문자열 포함 검색을 문서 루트 판정으로 사용하지 않는다.
- 작업 문서 검색은 작업 폴더 안의 기존 이름·본문 검색을 사용하고, 프로젝트 전체 검색으로 확장하는 동작을 제공한다. 하단 상태바 검색은 현재 탐색 보기의 검색 상태와 연결하며 별도 색인을 만들지 않는다.
- 파일 탐색에서는 프로젝트 전체의 파일명·경로를 검색할 수 있다. 아직 펼치지 않은 폴더도 검색 시 제한된 동시성으로 조사하며, 진행 중이거나 읽지 못한 폴더가 있으면 검색 완료로 표시하지 않는다. 검색 취소와 프로젝트 전환 시 남은 작업을 중단한다.
- Markdown 본문 검색은 기존 검색 도구를 재사용한다. 코드·PDF·이미지·HTML 본문까지 일괄 추출하는 새 전체 본문 색인은 이번 범위에 넣지 않는다.
- 검색 결과를 선택하면 트리에서 대상 위치를 확인할 수 있고, 원래 탐색·검색 상태로 돌아올 수 있다. 파일 선택은 실제 주소를 갖는 링크로 제공하고 휠 클릭·수정키 클릭·뒤로 가기를 유지한다.
- 기존 프로젝트 배지의 Markdown 개수와 티켓 진행률에 일반 파일 수를 섞지 않는다. 트리의 항목 수를 표시할 경우 아직 읽지 않은 하위 파일을 모두 센 것처럼 보이지 않게 한다.

### 3. 유형별 미리보기 지원 범위

| 유형 | 이번 계획의 표시 방식 | 경계 |
| --- | --- | --- |
| Markdown, 플랜·티켓·인벤토리·스모크·실행 기록 | 기존 리더·보드·시트를 재사용한다. | 트리에서 열었다는 이유로 Markdown 원문 화면만 강제하지 않는다. 기존 문서 편집·명시적 정리와 저장 보호는 그대로다. |
| TXT, JSON, YAML/YML, SQL, 일반 소스코드 | 줄 번호·문법 색상·복사를 제공하는 읽기 전용 텍스트 화면. | 실행·편집 기능을 추가하지 않는다. 언어를 모르면 안전하게 판독 가능한 텍스트로 표시한다. |
| PNG, JPG/JPEG, WebP, GIF, SVG | 단독 이미지 보기, 확대·축소, 화면에 맞추기. | SVG는 문서 DOM에 직접 삽입하지 않는 이미지 표시 방식을 사용한다. |
| PDF | 로컬 파일의 Blob URL을 `iframe`에 전달해 브라우저 내장 뷰어로 표시한다. | 페이지 이동·검색·확대·인쇄는 브라우저가 제공한다. 별도 PDF 렌더러나 PDF.js 패키지를 동봉하지 않는다. |
| HTML/HTM | 렌더링 결과와 읽기 전용 소스 보기를 전환한다. HTML을 열면 격리된 화면에서 스크립트·외부 리소스를 바로 실행·로드한다. | 별도 실행 버튼을 선행하지 않는다. 구체적인 실행·리소스 범위는 아래 규칙을 따른다. |
| 그 밖의 파일 | 파일명·유형·크기 등 확인 가능한 정보와 다운로드. | 미리보기가 없다고 파일을 트리에서 숨기지 않는다. 크기는 선택 시 읽는다. |

- 브라우저가 지원하는 형식이라도 파일 손상·인코딩·권한·크기 문제로 읽지 못할 수 있다. 읽지 못한 이유와 다운로드 등 가능한 다음 행동을 해당 화면에 표시한다.
- 미리보기 유형은 확장자와 실제 파일 정보로 판정한다. 알 수 없는 바이너리를 텍스트나 HTML로 억지로 해석하지 않는다.
- 파일 크기·긴 줄·이미지 크기 등에 대한 표시 한계는 공통 상수로 두고 합성 대용량 파일로 조정한다. 큰 텍스트를 줄여 표시하면 일부 내용임을 명시하고 전체 파일은 다운로드할 수 있게 한다.
- 비Markdown 파일을 Markdown 문서 레지스트리나 UUID 마이그레이션 대상으로 등록하지 않는다. 기존 파일과 같은 대상을 가리키는 주소는 기존 문서 식별자를 유지한다.

### 4. PDF는 브라우저 내장 뷰어 사용

- 허용된 파일 핸들에서 선택한 PDF를 읽고, 적절한 PDF MIME을 가진 Blob URL로 `iframe`에 전달한다. 임의의 PC 절대경로를 `file://` 주소로 넘기지 않는다.
- `navigator.pdfViewerEnabled`로 인라인 표시 가능 여부를 확인한다. 브라우저 정책이나 설정으로 표시가 불가능한 경우 다운로드 경로를 제공한다. 이 값만으로 실제 파일이 정상 렌더링됐다고 판정하지 않는다.
- 미리보기를 닫거나 다른 파일로 바꿀 때 더 이상 사용하지 않는 Blob URL을 해제한다. 사용 중인 뷰어의 URL을 로드 직후 해제하지 않는다.
- HTML 미리보기와 PDF 미리보기는 필요한 브라우저 정책이 다르므로 별도 구성으로 확인한다. 앱의 iframe 허용 정책과 배포 빌드에서도 PDF 로딩이 동작하는지 검사한다.
- 근거: [MDN 로컬 PDF 표시 예제](https://developer.mozilla.org/en-US/docs/Web/API/File_API/Using_files_from_web_applications#example_using_object_urls_to_display_pdf), [PDF 뷰어 지원 판정](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/pdfViewerEnabled).

### 5. HTML은 선택할 때 바로 격리 실행

- 사용자 방향(2026-11-13): 정적 미리보기 뒤 실행 버튼을 누르는 방식보다 HTML을 열 때부터 격리 실행하는 방식을 선호한다. 이번 계획은 이를 기본 동작으로 삼는다.
- 파일을 직접 선택하거나 그 파일의 링크를 열었을 때 실행한다. 폴더 펼치기, 파일명 검색, 목록 생성만으로 HTML을 실행하거나 외부 리소스를 요청하지 않는다.
- HTML 안의 인라인 CSS·스크립트와 일반적인 외부 스타일·스크립트·이미지를 표시할 수 있도록 설계한다. 현재 선택한 HTML만 활성화하고 다른 문서로 이동하면 해당 프레임·네트워크 로딩·부모가 만든 리소스를 정리한다. 패널 배치나 너비를 바꾸는 것만으로 다시 실행하지 않는다.
- iframe은 부모 앱과 다른 origin으로 격리한다. 부모 DOM, 앱 저장소, 폴더 핸들, 파일 쓰기 기능을 노출하지 않는다. 스크립트 허용과 same-origin 허용을 함께 주어 격리를 해제하지 않는다. 부모 이동·팝업·다운로드 등은 무제한으로 열지 않고 앱의 명시적 탐색·다운로드 동작으로 다룬다.
- HTML이 직접 참조하는 로컬 CSS·JS·이미지는 이미 허용된 연결 경계 안에서 상대경로를 해석한다. 임의의 상위 폴더를 추측하거나 프로젝트 전체 파일 핸들을 HTML에 전달하지 않는다. 리소스 연결 구현은 최소 합성 HTML로 먼저 검증한다.
- 서버 API, 빌드가 필요한 애플리케이션, 임의의 동적 파일시스템 접근까지 재현하지 않는다. 외부 리소스의 네트워크 실패·CORS·오프라인 제약으로 일부 내용이 열리지 않을 때는 소스 보기와 다운로드를 유지한다. 로컬 콘텐츠는 업로드하지 않으며 HTML이 지정한 외부 요청은 발생할 수 있다.
- 앱 전체의 보안 정책을 느슨하게 만드는 방식으로 HTML을 붙이지 않는다. 별도 미리보기 정책, 리소스 전달 경계, 메시지 수신자 검증을 구현 단계에서 확인한다.
- 근거: [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox), [iframe 로딩 출처 정책](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-src).

### 6. 링크·권한·상태 보존

- 작업 폴더 밖의 파일도 트리와 문서 링크에서 같은 미리보기로 연다. 표시 범위 필터는 링크 접근 권한이 아니다.
- 기존 로컬 링크의 repo 연결·수동 경로 연결·권한 복구를 재사용한다. 연결 범위를 벗어나면 기존 연결 절차를 거치고, 원본 Markdown이나 타인 PC 경로를 자동 수정하지 않는다.
- 보기 전환, 파일 선택, 이미지·PDF·HTML 열기는 쓰기 권한을 요구하지 않는다. 기존 Markdown의 저장은 지금의 명시적 동작과 stale-file·복구 보호를 계속 사용한다.
- 기존 문서 URL·새 탭·뒤로 가기와 열린 초안을 보존한다. 새 유형의 파일 주소는 연결한 프로젝트 안에서만 해석하며 개인 PC 절대경로를 URL에 넣지 않는다.
- 트리에서 임의 파일을 삭제·이동·이름 변경하거나 설정을 수정하는 기능은 추가하지 않는다.
- 공개 `/docs`·`/releases`와 그 검색은 계속 명시적으로 작성한 공개 문서만 다룬다. 로컬 파일 탐색을 공개 검색이나 배포 자산 수집에 연결하지 않는다.

## 성공을 확인할 방법

1. **기본·선택 설정:** 설정 없는 프로젝트는 `docs`, `root = contexts` 프로젝트는 `contexts`를 작업 문서로 표시한다. 중첩 루트·한글/공백 경로·workspace 상속·잘못된 설정·루트 부재를 확인한다. 설정 판정과 스킬 파일은 바뀌지 않는다.
2. **두 보기:** 작업 목록과 파일 트리 사이를 전환해도 현재 문서·초안·소유자 필터·정렬·패널 크기와 접힘이 유지된다. 새로고침과 프로젝트 전환 뒤 해당 프로젝트의 보기·트리 상태가 복원된다.
3. **실제 탐색:** 트리에서 키보드와 포인터로 펼치기·선택하기·검색하기를 수행한다. 검색은 펼치지 않은 폴더의 파일도 찾고, 진행 중·부분 실패를 빈 결과와 구별한다. 기존 문서 주소와 새 탭 동작을 확인한다.
4. **미리보기:** 각 지원 유형과 대문자 확장자, MIME 누락/불일치, 손상 파일, 긴 줄, 큰 파일, 비텍스트 파일을 확인한다. 지원하지 않는 파일도 정보·다운로드에 접근할 수 있다.
5. **PDF 실제 화면:** 지원 대상 PC Chrome·Edge에서 브라우저 내장 뷰어의 페이지 이동·확대·검색과 다운로드를 확인한다. 인라인 PDF를 끈 환경의 처리도 확인하고 다른 플랫폼 결과로 대신하지 않는다.
6. **HTML 실제 화면:** 외부 CDN 없이 동작하는 문서, 상대 CSS·JS·이미지 문서, 통제된 외부 리소스 문서와 실패 사례를 합성한다. 선택 시 자동 실행, 소스 전환, 패널 크기 변경, 다른 문서 이동 후 타이머·메모리 정리를 확인한다. 부모 DOM·저장소·폴더 접근 시도가 차단되는지도 검사한다.
7. **원본과 권한:** 동일 파일을 트리와 Markdown 링크로 열고 출발 문서로 돌아온다. 읽기 전용·권한 해제·파일 이동/삭제·재연결을 확인한다. 열기 전후 파일 해시가 같고, 기존 Markdown 저장 보호가 유지된다.
8. **성능 비교:** 동일 합성 프로젝트에서 변경 전후 첫 목록·첫 문서·폴더 펼침·검색 시간을 비교하고 긴 메인 스레드 작업과 입력 지연을 기록한다. 보기 전환·반복 열기 뒤 메모리와 Blob URL이 누적되지 않는지 확인한다.
9. **회귀와 표시:** 기존 카드·자세히·전체 티켓·스모크·문서 정리·연결 문서·검색 결과와 개수를 확인한다. 한국어/영어, 라이트/다크, 안정/카나리 테마, 좁은 PC 창과 고정/플로팅에서 조작 가능해야 한다.

자동 검사·타입 검사·빌드는 구조와 회귀 근거로 사용한다. 실제 파일 권한, 네이티브 PDF 뷰어, HTML 상호작용과 화면 반응은 사람이거나 Computer Use / browser use가 앱을 조작한 별도 스모크로 확인한다. 개인 프로젝트·스킬·연결을 시험 대상으로 사용하지 않고 합성 폴더에서 수행한다. 이 플랜 작성 단계에서는 위 검증을 수행한 것으로 기록하지 않는다.

### Markdown 본문 안의 제한적 HTML로 기획 화면 표현

- 사용자 요청(2026-11-13): GitHub README처럼 Markdown 본문에 일부 HTML을 수용해 기획서 안에서 화면을 보여주고, 화면 기획 도구의 일부 용도로 활용하고 싶다. 이번에는 백로그로 둔다.

  ````md
  ```ak-html
  <html lang="ko"><body><h2>신청 내역</h2></body></html>
  ```
  ````

- 후속 검토는 허용 태그·속성·스타일의 범위, 기존 Markdown 렌더링과의 호환, 화면 레이아웃 표현력, 접근성·테마·링크 처리와 격리를 다룬다. GitHub README의 실제 허용 범위가 필요한 화면 표현을 충족하는지도 먼저 확인한다.
- HTML 파일의 격리 미리보기와 별도 기능이다. 이번 작업에서 Markdown의 raw HTML·CSS·스크립트를 새로 허용하거나 파서·문서 규약을 변경하지 않는다.

## 구현과 검증 현황

2026-11-13 AFE-02~07의 앱 코드를 반영했다. 작업 문서와 파일 트리의 상태를 분리했고, 일반 파일도 기존 문서 옆에서 읽을 수 있다. 스킬·문서 규격·개인 설치본은 이 작업에서 바꾸지 않았다. 완료 여부와 남은 실기기 검증은 [티켓](33_alpha_kanban_file_explorer_tickets.md), 실제 조작 기준과 관찰은 [스모크](34_alpha_kanban_file_explorer_smoke.md)와 [첫 실행 기록](35_alpha_kanban_file_explorer_smoke_run.md)에 남긴다.

읽기 한계는 `components/files/previewModel.ts`의 공통 값으로 관리한다. 텍스트는 512 KiB·10,000행·행당 4,000자까지 표시하며 생략을 알린다. 이미지는 50 MiB·1억 픽셀, PDF는 100 MiB, HTML은 2 MiB까지 미리본다. HTML의 직접 참조 로컬 리소스는 개당 10 MiB·합계 32 MiB·100개로 제한한다. 제한에 걸린 파일도 다운로드 경로는 유지한다.

Mac Chrome의 실제 조작과 배포 정책 확인을 수행했다. Windows·Edge, Mac의 실제 권한 취소·복구, 초기 연결의 정확한 시간 및 변경 전 비교, 장시간 메모리 검증은 아직 완료하지 않았다. 서버를 끈 시험에서 HTML 실행 프레임은 연결에 실패했지만 소스·다운로드를 계속 사용할 수 있었다. 이를 오프라인 HTML 실행 성공으로 집계하지 않는다.
