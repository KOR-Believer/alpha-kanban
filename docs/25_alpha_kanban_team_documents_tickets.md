구현 범위:

- 공용 메타데이터 읽기/쓰기와 ID 유효성·중복 판정을 추가한다. 유효 ID는 이동/이름 변경 시 보존하고 명시적 복제에만 새 ID를 발급한다.

- 원문 UUID가 없거나 잘못됐을 때 추측 연결하지 않는다. 최초 변환 계획의 ID를 재개 때 재사용하고 재실행 시 새 변경이 없게 한다.
- 파일 ID·기존 딥링크·최근 문서·보드 순서·문서 선택의 보존 여부를 대조한다.

제외 범위:

- 전용 ID 링크 문법 강제, 과거 날짜·작성자·완료 기록 추정, 전체 문서 무확인 발급

완료 기준:

- [ ] ID 없는 레거시 문서에만 ID가 추가되고 기존 ID·티켓 의미·사용자 본문은 보존된다.

검증:

- [ ] 로컬 기존 ID/딥링크·캐시/순서 보존 또는 명시적 재연결 검증

- apps/web/src/browser/MarkdownResources.tsx와 repository.ts.localResource는 절대경로·file URL·프로젝트 경계 밖·파일 부재를 오류로 표시하며 위치 연결을 제공하지 않는다. 폴더 핸들을 저장하는 IndexedDB는 있지만 원본 앞 경로와 내 폴더를 대응시키는 기록은 없다.
- root 하위 repo 발견·Git 식별은 현재 제공하지 않는다. clone 폴더명과 깊이가 다를 때 원본 경로 문자열만으로 원래 repo를 확정할 수 없으며, 같은 repo의 여러 checkout도 구분해야 한다.

구현 범위:

- 정상 링크 해석 → 저장된 대응 재사용 → Git 정보 기반 repo 자동 연결 시도 → 필요한 최초 repo 선택 또는 수동 폴더 지정의 흐름을 하나의 resolver·저장 계약·UI로 제공한다. OS 절대경로·로컬 file URL·문서 상대경로를 다루고 HTTP(S)/메일 링크·문서 내부 앵커는 유지한다. 폴더 선택·권한 요청은 사용자 연결 동작에서만 수행하며 자동 탐색을 기다리거나 통과해야만 수동 연결할 수 있게 만들지 않는다.
- 명시적으로 연결한 root 아래에서 workspace 직속 repo와 하네스 하위 여러 깊이의 repo를 발견한다. 하네스 자체가 repo여도 중첩 repo를 계속 찾고 가장 가까운 작업 트리를 파일의 repo 경계로 삼는다. clone 이름·깊이는 식별자로 쓰지 않으며 기존 칸반 프로젝트 등록·소유자 경계를 바꾸지 않는다.
- 허용된 폴더 안의 .git 디렉터리/파일·설정에서 remote 식별 정보와 checkout 핸들을 대응시킨다. SSH/HTTPS·여러 remote·별칭·fork·gitdir/commondir 처리 범위를 fixture로 정하고 모호하거나 허용 범위 밖 설정이 필요하면 수동 연결로 넘긴다. Git 명령·네트워크를 실행하거나 파일 push를 요구하지 않고 설정 원문·인증 정보를 연결표에 저장하지 않는다.
- 원본 경로→repo 대응이 저장돼 있거나 접근 가능한 출처의 Git 정보로 원본 repo가 확인됐을 때만 자동 연결을 시도한다. 출처 없는 옛 경로·파일명·후보 하나만으로 원본 repo를 추측하지 않는다. 최초에는 원본 repo 앞 경로와 발견 목록의 repo를 선택해 매핑할 수 있으며 폴더 직접 지정도 제공한다.
- 확인한 repo에 대해 대상 checkout이 하나로 정해지고 내부 경로의 파일이 존재하면 연다. 복수 clone/worktree는 선택한 checkout을 보존하고 접근 실패를 이유로 다른 checkout으로 자동 대체하지 않는다. 파일 부재는 미해결로 표시하며 다른 repo의 동명 파일로 성공 처리하지 않는다.
- 수동 연결은 원본 폴더 앞 경로와 내 디렉터리를 지정하고 남은 하위 경로의 파일을 확인한 뒤 저장한다. Git 정보가 없는 폴더도 지원하고 단일 파일 선택으로 상위 대응을 추측하거나 없는 파일을 생성하지 않는다.
- 기존 storage.ts의 IndexedDB에 출발 문서 프로젝트·정규화한 원본 경로 접두사·대상 디렉터리 핸들을 저장하고 repo 방식은 확인된 식별 정보·선택 checkout을 함께 둔다. 같은 앞 경로에 공통으로 재사용하고 대상 PC의 절대경로 문자열이나 Markdown·YAML·agent 설정 파일을 요구하지 않는다.
- 상대경로는 출발 문서 위치를 반영하고 접두사는 경로 구성요소 경계로 비교한다. 더 구체적인 경로를 우선하며 같은 키 재지정은 사용자 선택으로만 수행한다. 대상이 승인한 연결 폴더 밖으로 나가거나 프로젝트별 연결이 섞이지 않게 한다. 대상 Markdown은 대상 연결의 문서 식별로 열고 다른 파일은 다운로드하며 원문·소유자·티켓 상태·작업 배정·이동 변환 범위를 유지한다.
- repo 목록을 캐시하고 링크마다 root 전체를 재탐색하지 않는다. 탐색 제외·깊이/개수 상한·취소·부분 실패·명시적 새로고침·재사용 시 유효성 확인을 설계한다. 미완료 탐색을 부재나 후보 유일성의 증거로 삼지 않으며 탐색 중에도 수동 연결을 제공한다.
- 연결 재지정·해제·권한 재승인을 제공하고 권한/폴더/파일/IndexedDB 실패를 구분한다. 취소 시 기존 연결과 파일을 보존한다. 같은 사이트·브라우저 프로필에서 재실행·앱 업데이트 후 연결을 재사용하되 권한과 대상을 재확인하며 다른 PC/브라우저 또는 사이트 데이터 삭제 후에는 별도 연결한다. 기존 IndexedDB·PWA·드래프트를 보존하고 공유 UI·한영 번역을 사용한다.
- 격리 검증에서 A: 수동 지정만 사용과 B: repo 자동 발견·자동 연결 시도 후 최초 선택·수동 연결을 비교할 수 있게 한다. resolver·저장 스키마는 공유하되 실험별 연결표·탐색 캐시는 분리한다. 공개 제품의 영구 모드 선택이나 원격 통계를 추가하지 않으며 비교 결과는 AKD-09에서 확인한다.
