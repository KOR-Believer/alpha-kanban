- 현재 스킬에는 공유/개인 설정 분리·ownerFolders 작성 위치 판정·외부 worktree의 개인 설정 상속이 없고 브라우저에는 경로 소유자·필터가 없다. 소유자 기반을 ID·형식 규약과 분리해 먼저 완료해야 한다.

구현 범위:

- 산출물은 docs/team_documents_contract.md다. 아래 완료 기준은 설정·소유자·상속·번호·인계의 문서 계약을 검토하는 기준이며 실제 기능 검증은 후속 AKD-02/11 등에서 수행한다.
- 기본 작성·수정은 .ak.config·.ak.user·사용자 확인·@폴더·owner 없이 기존 docs 위치와 번호 규칙을 유지한다. 공통 도구는 설정 부재를 기본 결과로 반환하고 최초 플랜 작성에 팀/개인 질문을 추가하지 않는다. 일반 폴더의 owner 없음은 정상이며 무설정 작성·수정 검증은 페이즈 1의 AKD-11/02가 맡는다.
- .ak.config는 커밋 가능한 공통 설정으로 documents.ownerFolders를, .ak.user는 Git에서 제외하는 개인 설정으로 user를 담는다. 제한된 Git config 구문으로 각각 [documents] ownerFolders와 [user] id를 표기한다. 중복 키·include·미지원 키를 거부하고 두 파일을 범용 병합하지 않는다. 공유 파일의 user·개인 파일의 ownerFolders 등 역할이 다른 항목은 위치 오류로 보고 해당 값으로 판정하지 않는다.
- 신규 기본 배치는 repo .ak.config > 지정 workspace .ak.config > 기본값 false로 ownerFolders를 판정한다. 항목 부재만 건너뛰고 repo의 false는 workspace의 true보다 우선한다. true와 유효 사용자인 경우에만 새 사용자 폴더를 자동 생성·선택하며 미설정/false는 기존 위치·번호를 유지한다. .ak.user 존재·인원수·발견한 @폴더로 자동 활성화하지 않는다.
- ownerFolders가 true인데 사용자가 없으면 사용자 지정이 필요한 결과를 반환하고 해당 신규 작성을 보류한다. 정책/사용자 오류는 누락과 구분한다. 명시적 작성 대상과 기존 문서 위치를 우선하고 활성화/해제만으로 기존 문서·owner를 바꾸지 않는다. 기존 @문서의 소유권·열람·명시적 대상 편집과 CLI 이동/인수는 이 신규 기본 배치 정책과 별개다.
- docs/@사용자 직계 폴더만 소유자로 해석하고 하위 상속·일반/기존 폴더의 미지정·식별자 유효성과 충돌 규칙을 정의한다. 폴더 소유자는 경로에서 읽고 현재 사용자는 설정에서 읽는다.
- 문서의 owner는 마지막으로 확인·반영한 소유자이고 현재 폴더 소유자·.ak.user의 작업자·최초 작성자·UUID와 구분한다. 소유자별로 작성하는 새 plan/tickets/inventory만 제목 아래 문서 공통 헤더에 Owner: @alice 한 줄을 기록한다. 기본 작성에는 이 줄이나 빈 메타데이터를 넣지 않는다. 헤더 범위·중복/잘못된 값·현재 파서 보존 계약을 정하고 YAML front matter나 UUID를 선행 조건으로 두지 않는다.
- 초기 도입 시 @사용자 폴더 미사용을 기준으로, @폴더의 owner 없음은 레거시 편입·소유자 등록 대상, 다른 owner는 이동·인수 정합화 대상으로 분류한다. owner 일치는 경로·링크 무결성을 증명하지 않으며 일반 폴더는 기록된 owner만으로 배정하지 않는다. 손상·잘못된 값은 누락과 구분한다.

현재 문제:

- apps/web/src/browser/MarkdownResources.tsx와 repository.ts.localResource는 절대경로·file URL·프로젝트 경계 밖·파일 부재를 오류로 표시하며 위치 연결을 제공하지 않는다. 폴더 핸들을 저장하는 IndexedDB는 있지만 원본 앞 경로와 내 폴더를 대응시키는 기록은 없다.
- root 하위 repo 발견·Git 식별은 현재 제공하지 않는다. clone 폴더명과 깊이가 다를 때 원본 경로 문자열만으로 원래 repo를 확정할 수 없으며, 같은 repo의 여러 checkout도 구분해야 한다.

구현 범위:

- 정상 링크 해석 → 저장된 대응 재사용 → Git 정보 기반 repo 자동 연결 시도 → 필요한 최초 repo 선택 또는 수동 폴더 지정의 흐름을 하나의 resolver·저장 계약·UI로 제공한다. OS 절대경로·로컬 file URL·문서 상대경로를 다루고 HTTP(S)/메일 링크·문서 내부 앵커는 유지한다. 폴더 선택·권한 요청은 사용자 연결 동작에서만 수행하며 자동 탐색을 기다리거나 통과해야만 수동 연결할 수 있게 만들지 않는다.
- 명시적으로 연결한 root 아래에서 workspace 직속 repo와 하네스 하위 여러 깊이의 repo를 발견한다. 하네스 자체가 repo여도 중첩 repo를 계속 찾고 가장 가까운 작업 트리를 파일의 repo 경계로 삼는다. clone 이름·깊이는 식별자로 쓰지 않으며 기존 칸반 프로젝트 등록·소유자 경계를 바꾸지 않는다.
- 허용된 폴더 안의 .git 디렉터리/파일·설정에서 remote 식별 정보와 checkout 핸들을 대응시킨다. SSH/HTTPS·여러 remote·별칭·fork·gitdir/commondir 처리 범위를 fixture로 정하고 모호하거나 허용 범위 밖 설정이 필요하면 수동 연결로 넘긴다. Git 명령·네트워크를 실행하거나 파일 push를 요구하지 않고 설정 원문·인증 정보를 연결표에 저장하지 않는다.
- 원본 경로→repo 대응이 저장돼 있거나 접근 가능한 출처의 Git 정보로 원본 repo가 확인됐을 때만 자동 연결을 시도한다. 출처 없는 옛 경로·파일명·후보 하나만으로 원본 repo를 추측하지 않는다. 최초에는 원본 repo 앞 경로와 발견 목록의 repo를 선택해 매핑할 수 있으며 폴더 직접 지정도 제공한다.

구현 범위:

- 전체보드는 연결 프로젝트, 프로젝트보드는 열린 티켓 문서에서 통합 검색한다. 번호·제목·본문과 임의의 티켓 Markdown을 검색하고 본문 일치 부분을 표시한다. 아직 읽는 중인 전체보드는 결과가 늘어나는 상태를 알린다.
- 같은 파일의 분석을 재사용하고 파일 확인을 제한 병렬화하며 부분 결과 갱신을 묶는다. 초기 로딩과 화면 응답성을 합성 fixture로 비교한다.
