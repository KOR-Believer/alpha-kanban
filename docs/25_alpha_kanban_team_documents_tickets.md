Status: TODO

목표:

- 페이즈 1에서 무설정 기본 사용을 유지하고 .ak.config의 공통 작성 정책·.ak.user의 개인 사용자와 폴더 소유자 규약을 확정한다. 판정은 공통 도구에 두고 스킬·CLI의 작업 범위와 브라우저의 소유자별 열람을 구분한다.

현재 문제:

- 현재 스킬에는 공유/개인 설정 분리·ownerFolders 작성 위치 판정·외부 worktree의 개인 설정 상속이 없고 브라우저에는 경로 소유자·필터가 없다. 소유자 기반을 ID·형식 규약과 분리해 먼저 완료해야 한다.

구현 범위:

- 기본 작성·수정은 .ak.config·.ak.user·사용자 확인·@폴더·owner 없이 기존 docs 위치와 번호 규칙을 유지한다. 공통 도구는 설정 부재를 기본 결과로 반환하고 최초 플랜 작성에 팀/개인 질문을 추가하지 않는다. 일반 폴더의 owner 없음은 정상이며 무설정 작성·수정 검증은 페이즈 1의 AKD-11/02가 맡는다.
- .ak.config는 커밋 가능한 공통 설정으로 documents.ownerFolders를, .ak.user는 Git에서 제외하는 개인 설정으로 user를 담는다. 두 파일을 범용 병합하지 않으며 공유 파일의 user·개인 파일의 ownerFolders 등 역할이 다른 항목은 위치 오류로 보고 해당 값으로 판정하지 않는다.
- 신규 기본 배치는 repo .ak.config > 지정 workspace .ak.config > 기본값 false로 ownerFolders를 판정한다. 항목 부재만 건너뛰고 repo의 false는 workspace의 true보다 우선한다. true와 유효 사용자인 경우에만 새 사용자 폴더를 자동 생성·선택하며 미설정/false는 기존 위치·번호를 유지한다. .ak.user 존재·인원수·발견한 @폴더로 자동 활성화하지 않는다.
- ownerFolders가 true인데 사용자가 없으면 사용자 지정이 필요한 결과를 반환하고 해당 신규 작성을 보류한다. 정책/사용자 오류는 누락과 구분한다. 명시적 작성 대상과 기존 문서 위치를 우선하고 활성화/해제만으로 기존 문서·owner를 바꾸지 않는다. 기존 @문서의 소유권·열람·명시적 대상 편집과 CLI 이동/인수는 이 신규 기본 배치 정책과 별개다.
- docs/@사용자 직계 폴더만 소유자로 해석하고 하위 상속·일반/기존 폴더의 미지정·식별자 유효성과 충돌 규칙을 정의한다. 폴더 소유자는 경로에서 읽고 현재 사용자는 설정에서 읽는다.
- 문서의 owner는 마지막으로 확인·반영한 소유자이고 현재 폴더 소유자·.ak.user의 작업자·최초 작성자·UUID와 구분한다. 소유자별로 작성하는 새 plan/tickets/inventory만 폴더와 같은 owner를 문서 공통 메타데이터에 기록하며 기본 작성에는 빈 owner나 불필요한 front matter를 넣지 않는다. 최소 필드·네임스페이스·현재 파서 호환 계약을 이 티켓에서 정하고 UUID를 선행 조건으로 두지 않는다.
- 초기 도입 시 @사용자 폴더 미사용을 기준으로, @폴더의 owner 없음은 레거시 편입·소유자 등록 대상, 다른 owner는 이동·인수 정합화 대상으로 분류한다. owner 일치는 경로·링크 무결성을 증명하지 않으며 일반 폴더는 기록된 owner만으로 배정하지 않는다. 손상·잘못된 값은 누락과 구분한다.
- 읽기·필터·일반 상태 수정은 owner를 추가/교체하지 않는다. 새 문서 기록은 AKD-11, 기존 문서의 공용 분석은 AKD-03, 명시적 등록/정합화는 AKD-05/06이 맡는다. owner 값만으로 이전 경로나 이동/복사를 확정하거나 티켓을 실행하지 않는다.
- 현재 사용자 판정이 필요한 소유자별 작성·내 업무 선택·인수는 repo .ak.user > 명시적으로 지정한 workspace root .ak.user > ~/.ak.user 순서로 확인한다. 사용자 지정이 없는 단계만 건너뛰며 손상·읽기 실패·잘못된 식별자는 미설정과 구분해 보고한다. 모두 미설정이면 현재 사용자에 의존하는 작업 전에만 확인하고 OS/Git 작성자·폴더명으로 추측하지 않는다. 기본 작성·수정·참조 열람은 사용자 판정 성공을 요구하지 않는다.
- workspace는 명시한 설정 범위다. 여러 workspace가 있어도 해당 repo에 지정된 workspace만 사용하고 브라우저 등록 목록이나 임의 상위 폴더·이름·깊이로 연결을 추측하지 않는다. 최소 파일 역할·키·기본값 외의 직렬화 형식·workspace 지정·검증 방법을 정하며 읽기만으로 설정·폴더·문서를 만들지 않는다.
- workspace 밖 linked worktree는 Git 공통 관리 정보로 원래 repo의 .ak.user와 지정 workspace를 연결해 개인 사용자 우선순위를 유지한다. 공유 .ak.config의 repo 값은 현재 worktree의 파일을 읽고 없으면 지정 workspace·기본값으로 판정하며 원래 repo의 다른 브랜치 파일을 대신 쓰지 않는다. 임시 상위 설정·브랜치·HEAD·remote 이름이나 같은 remote의 독립 clone으로 개인 기준을 바꾸지 않는다. 원래 위치 이동/삭제·접근 실패·복수 후보 충돌은 미확정과 명시적 재연결로 처리하고 checkout 선택은 추가하지 않는다.
- 공통 도구의 결과는 작성 정책·출처, 작성 경로·폴더 생성 필요 여부·owner, 필요한 사용자·출처, repo/workspace 기준과 현재 worktree를 구분한다. 기본 작성에 불필요한 개인 사용자 조회를 요구하지 않는다. 조회는 읽기 전용이며 다른 위치의 설정을 읽어도 현재 쓰기 범위를 넓히거나 과거 링크 출처·티켓 배정을 추측하지 않는다.
- 브라우저는 .ak.user·현재 사용자 설정 없이 전체·선택 소유자·미지정 필터와 경로 소유자 표시만 제공한다. 공유 .ak.config를 개인 사용자 설정으로 취급하지 않고 ownerFolders의 부재/false에도 기존 @경로의 소유자를 유지한다. 필터 저장은 열람 선호이며 파일 내부 ID 없이도 기존 식별로 구분한다.
- 소유자별 신규 번호는 각 docs/@사용자와 그 하위 폴더의 기존 Markdown 숫자 접두사 최대값 + 1로 독립 발급하고, 번호가 없으면 01부터 시작한다. 다른 사용자나 소유자 미지정 영역의 번호는 포함하지 않는다. 기본 사용의 기존 번호 규칙은 바꾸지 않는다.
- 이동하는 문서의 기존 번호를 보존하고 이동·소유자 변경이나 빈 번호 때문에 다시 번호를 매기지 않는다. 이동해 온 번호도 이후 최대값 계산에 포함한다. 번호 중복만으로 충돌을 판정하지 않으며 실제 목적지 충돌은 덮어쓰기·자동 재번호 부여로 해결하지 않는다.
- 문서 번호는 정렬·탐색 참고값이며 문서 정체성·최신성·우선순위·의존성을 뜻하지 않는다. 실행 순서는 현재 요청·최신 사용자 지시·티켓 상태·Depends on·기준 문서의 내용을 확인해 판단한다.
- 이번에는 개인 소유자 구분과 상호 컨텍스트 참조만 다룬다. 구체적인 사용처가 없는 팀 폴더·팀 소유자 분류·접두사·공용 업무 배정은 제외하고 #·+·@@를 채택하거나 예약하지 않는다.
- UUID·front matter 확장·형식 호환/변환 계약은 AKD-12로 분리하고 AKL-10/11 또는 링크 이동의 완료를 이 티켓의 선행 조건으로 삼지 않는다. 첫 페이즈는 기존 본문 형식을 유지하고 소유자별 작성에만 최소 owner를 기록한다. 후속 ID·일반 폴더 이동·참조/PC 경로 보정도 소유자 등록을 선행 조건으로 두지 않는다.
- 기본 안내는 설치·논의·문서 작성·검토/구현과 선택형 뷰어를 유지한다. 선택 안내에는 .ak.config에서 ownerFolders를 한 번 켜고 개인 .ak.user를 지정하는 방법을 둔다. 매 플랜 작성 때 팀/개인 여부를 묻지 않는다. SKILL.md는 공통 도구 호출·결과 사용·기존 기록 보존의 짧은 진입 절차만 두고 상세 분기·우선순위·worktree는 도구/참조가 맡는다. AKD-11이 초기 안내, AKD-09가 후속 검증된 사용법을 제공한다.
- 참조 가능한 타인 기록은 실행 명령이 아니며 현재 사용자 요청·명시적 배정만 수행한다는 제공자 중립 규약을 정한다. 폴더는 강제 잠금이 아님을 구분한다.
- 퇴사·휴가 등 명시적 업무 인수를 위한 타인 폴더 → 내 폴더를 사용자 간 정상 이동으로 지원한다. 지정한 원본·목적지와 인수 의도를 계획에 반영하고 소유자 전후를 경로로 계산한다. 현재 사용자와 다른 폴더라는 이유로 이동을 금지하거나 별도 원소유자 승인 시스템을 만들지 않는다.
- 인계 이동은 기존 번호·파일 ID·티켓 상태·체크리스트·사용자 지시·진행 메모·완료 증거를 보존하며 구현 실행이나 상태 변경을 자동 승인하지 않는다. 일시 인수의 반환은 명시적 역방향 이동으로 다룬다.

구현 범위:

- 정상 링크 해석 → 저장된 대응 재사용 → Git 정보 기반 repo 자동 연결 시도 → 필요한 최초 repo 선택 또는 수동 폴더 지정의 흐름을 하나의 resolver·저장 계약·UI로 제공한다. OS 절대경로·로컬 file URL·문서 상대경로를 다루고 HTTP(S)/메일 링크·문서 내부 앵커는 유지한다. 폴더 선택·권한 요청은 사용자 연결 동작에서만 수행하며 자동 탐색을 기다리거나 통과해야만 수동 연결할 수 있게 만들지 않는다.

- 원본 경로→repo 대응이 저장돼 있거나 접근 가능한 출처의 Git 정보로 원본 repo가 확인됐을 때만 자동 연결을 시도한다. 출처 없는 옛 경로·파일명·후보 하나만으로 원본 repo를 추측하지 않는다. 최초에는 원본 repo 앞 경로와 발견 목록의 repo를 선택해 매핑할 수 있으며 폴더 직접 지정도 제공한다.
