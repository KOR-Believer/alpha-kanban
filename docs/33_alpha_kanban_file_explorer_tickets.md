### AFE-03. 필요한 폴더부터 여는 파일 트리와 프로젝트 파일 검색

Status: DONE
Progress: 100%
Completed at: 2026-11-13T20:30:46+09:00
Repository:

- `alpha-kanban/apps/web`

Priority: P1
Type: Feature
Depends on:

- AFE-02

목표:

- 허용된 프로젝트의 실제 폴더 구조를 빠르게 탐색하고, 펼치지 않은 위치의 파일도 이름과 경로로 찾는다.

현재 문제:

- 기존 발견 결과에는 Markdown만 있으며 모든 일반 파일 본문을 읽는 방식으로 탐색을 추가하면 초기 로딩과 권한 처리가 무거워진다.

구현 범위:

- browser의 파일 목록 계층과 문서 패널에 폴더 직계 항목·지연 자식 로딩·펼침 상태·키보드 탐색을 추가한다. 목록은 본문이나 크기를 일괄 읽지 않는다.
- 기존 관리·의존성·빌드 디렉터리 제외, 명시적 숨김 문서 루트와 연결 경계를 지킨다. Git 추적·ignore 정보를 브라우저가 아는 것처럼 표시하지 않는다.
- 프로젝트 전체 파일명·경로 검색은 미탐색 폴더도 제한된 동시성으로 조사하고 취소·부분 실패·진행 상태를 표시한다. 프로젝트 전환 시 이전 탐색을 중단한다.
- 작업 문서의 기존 본문 검색과 프로젝트 전체 확장 경로를 연결한다. Markdown 본문 색인을 재사용하고 상태바 검색은 현재 보기를 따른다.
- 검색 결과의 트리 위치를 확인하고 기존 탐색 상태로 돌아갈 수 있게 한다. 갱신·파일 소실·권한 복구 뒤 목록 캐시를 실제 상태와 맞춘다.

제외 범위:

- 코드·HTML·PDF·이미지 본문 전체 색인, 숨김·시스템 폴더 전면 탐색, 임의 파일 쓰기.

완료 기준:

- [x] 폴더를 펼칠 때 직계 목록만 읽고 일반 파일도 유형과 함께 표시한다.
- [x] 미탐색 폴더의 파일을 찾고 검색 중·일부 실패·정상 빈 결과를 구별하며 취소 후 작업이 남지 않는다.
- [x] 기존 작업 필터·본문 검색·Markdown 개수와 트리 상태가 서로 섞이지 않는다.

검증:

- [x] 깊은 폴더·반복 이름·접근 실패·선택 후 삭제·중복 연결·읽기 전용 합성 폴더를 탐색한다.
- [x] Markdown 500개 이상과 다양한 파일을 섞어 목록·검색의 본문 읽기 횟수, 취소, 입력 응답을 계측한다.
- [x] 포인터·키보드로 펼침·선택·검색·결과 위치 확인과 상태바 검색 연결을 확인한다.

사용자 지시:

진행 메모:

- 2026-11-13: 파일 트리는 기존 작업 목록과 별도 표시지만 가능한 목록·Markdown 검색 자료는 공유하는 방향으로 계획했다.
- 2026-11-13: 직계 항목만 읽는 트리와 프로젝트 전체 파일명·경로 검색을 추가했다. 기존 Markdown 본문 색인을 재사용하며 취소·재시도·부분 오류·트리 위치 확인과 키보드 탐색을 제공한다. 520개 합성 파일의 목록·이름 검색에서 본문 읽기 0회, 동시성·연결 경계·파일 교체 보호를 자동 검사했다. 실제 Chrome 배포 빌드의 507개 Markdown에서 파일 보기 첫 전환 441ms, 검색 재시도 612ms를 관찰했고 두 구간 모두 50ms 이상 긴 작업은 0회였다. 시간은 자동 조작 대기까지 포함한 단일 측정이며 변경 전 비교값은 아니다.
