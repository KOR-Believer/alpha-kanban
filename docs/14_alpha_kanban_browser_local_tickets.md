현재 문제:

- 문서 읽기가 HTTP API에 묶여 있고 프로젝트·파일 식별자가 절대경로에 의존한다.

구현 범위:

- ticketMarkdown.ts와 문서 묶음 분석에서 Node 의존성을 분리하고 기존 서버와 브라우저가 같은 분석 계약을 사용한다.
- 초기 지원·검증 대상은 데스크톱 Chrome으로 한정하고 File System Access API와 권한 상태를 확인한다. 미지원 환경을 안내하되 Edge 등 다른 Chromium 브라우저를 별도 지원 보장이나 필수 검증 대상으로 추가하지 않는다.
- App.tsx, AllProjectsBoard.tsx, allProjectsData.ts의 데이터 접근을 공통 연결 계층으로 모으고 브라우저 폴더 읽기를 연결한다.
- IndexedDB에 폴더 참조와 브라우저 내부 ID 등록부를 마련한다. 프로젝트 분류와 문서 식별자를 분리해 루트 중복 등록이나 분류 변경으로 같은 문서·카드·저장 잠금 대상이 중복되지 않게 한다.
- 폴더 참조의 동일성·포함 관계와 상대경로로 프로젝트를 식별하고 등록 루트 바로 아래 분류와 더 구체적인 중첩 루트 우선 규칙을 유지한다. 동일성을 확인할 수 없는 재생성·이동 폴더는 이름만 보고 연결하지 않는다.
- 선택한 프로젝트 내부의 Markdown만 탐색하고 숨김·의존성·빌드 디렉터리를 제외한다. docs 외 문서도 지원하되 기존 설정의 절대경로·범위 밖 docRoots를 자동으로 따라가지 않는다. 권한 취소·미지원·일부 프로젝트 접근 실패를 명확히 처리한다.
- 한 파일 읽기 결과에서 본문·해시·수정 시각을 함께 생성하고 기존 여섯 문서 정렬과 묶음 규칙을 재사용한다. 최근 수정순은 묶음 내 모든 파일의 lastModified 최댓값을 사용한다.
- 프로젝트 보드의 문서 등장 순서와 DONE 정렬 조건을 유지한다. 전체보드 수동 순서와 합치거나 여러 tickets 파일의 진행률을 새로 합산하지 않는다.
- 전체보드는 티켓 파일만 등록·본문 읽기를 수행하고 읽힌 프로젝트부터 표시한다. 최초 등록의 문서 간 전수 비교를 없애되 경로 변경·중첩 연결에서 기존 문서 ID를 유지한다.
- 프로젝트 화면은 저장된 문서 ID로 선택 문서를 먼저 열고 사이드바를 따로 읽는다. 목록 지연·실패가 열린 문서·선택·초안을 숨기지 않게 한다.
- 두 보드는 공통 스크롤과 고정 상태 제목줄을 사용한다. 컬럼별 스크롤, 제목 위로 비치는 카드와 중복 상단 테두리를 제거한다.
- 기존 서버 버전과 프로젝트 선택줄·시작 화면 헤더·프로젝트 행을 공유한다. 이름·경로·문서 상태를 갖는 가로 선택줄과 최근 프로젝트 우선 배치를 유지하고 언어 선택을 소형 컨트롤로 맞춘다.
- 최근/다른 프로젝트의 좌우 목록 재편은 AKL-08의 시안 승인 후 AKL-09에서 진행한다. 이 티켓의 초기 접힌 목록 구현과 검증 이력은 후속 디자인 승인으로 간주하지 않는다.
- 사이드바의 두 줄 헤더 안에서 이름·파일명·경로 검색과 필터 팝오버를 제공한다. 일반 Markdown 제외와 전체 티켓이 완료된 세트 제외를 독립 적용·기억하고, 단독 여부 필터와 종류별 칩은 넣지 않는다.

구현 범위:

- 저장 직전 최신 파일과 읽은 해시를 비교하고 충돌·권한 철회·쓰기 실패 때 입력과 카드 상태를 보존한다.

- 쓰기 전 원문·예정 결과·사유를 로컬 복구 항목으로 보관하고 정상 확인 후 정리한다. 복구 항목 저장에 실패하면 원본 쓰기를 시작하지 않는다. 실패·중단·확인 불가 시 입력과 복구본 다운로드를 제공하며 저장 여부 확인 없이 사용자 지시를 재전송하지 않는다.

- 상태와 사유 저장 후 전체보드 순서 저장만 실패하면 원본을 되돌리거나 사유를 다시 append하지 않고 순서만 재시도하도록 결과를 구분한다. 순서 저장 구현은 AKL-03에서 연결한다.

제외 범위:

- 외부 AI 프로세스 제어, 무조건 덮어쓰기, 임의 자동 병합·상세 병합 편집기, 문서 DB 원장화

- [x] 오래된 문서로 저장하면 쓰기를 중지하고 사유·지시 초안을 잃지 않는다.
