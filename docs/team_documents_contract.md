# 기본 사용·선택적 문서 소유자 규약

작성일: 2026-11-01
수정일: 2026-11-03

이 문서는 [팀 문서 계획](24_alpha_kanban_team_documents_plan.md)의 AKD-01 결과다. 설정과 소유자 판정의 계약을 정하며, 기능 구현이나 기존 문서 변환의 완료를 뜻하지 않는다. 구현·검증 진행은 [티켓](25_alpha_kanban_team_documents_tickets.md)에서 관리한다.

## 1. 파일 형식과 책임

설정 파일은 `[섹션]` 아래 `키 = 값`을 적는다. 파일명은 `.ak.config`와 `.ak.user`다. 문서에는 제목 아래 `Owner: @alice` 한 줄을 쓴다. 두 용도에 같은 직렬화 형식을 강제하지 않는다.

공유 가능한 `.ak.config`:

```text
[documents]
    ownerFolders = true
```

Git에서 제외하는 `.ak.user`:

```text
[user]
    id = @alice
```

| 항목 | 의미와 허용 위치 |
| --- | --- |
| `documents.root` | `.ak.config`의 프로젝트 상대 문서 보관 경로. 생략 시 `docs` |
| `documents.ownerFolders` | `.ak.config`의 신규 기본 배치 정책. 명시적인 `true` 또는 `false` |
| `user.id` | `.ak.user`의 사용자 식별자. 계획에서 말하는 논리 값 `user`의 파일 표기 |
| 문서의 `Owner:` | 마지막으로 확인·반영한 문서 소유자. 현재 작업자나 Git 작성자가 아님 |

- 설정은 UTF-8, 선택적 BOM, LF/CRLF를 허용한다. 섹션·키 대소문자는 Git config처럼 구분하지 않고, 값의 대소문자는 보존한다. 공백·빈 줄·주석과 인용 문자열은 Git config 구문을 따른다.
- 지원하는 키는 위 표의 세 설정 항목이다. 섹션 없는 대입, 하위 섹션, `include`/`includeIf`, 여러 줄 값, 값 없는 boolean은 지원하지 않는다. boolean은 `true`/`false`만 받으며 Git의 다른 boolean 약어는 채택하지 않는다.
- 같은 키가 두 번 나오면 값이 같아도 오류다. 파일 내 마지막 값 선택이나 두 파일의 범용 병합은 하지 않는다. 공유 파일의 `user.id`, 개인 파일의 `documents.root`·`documents.ownerFolders`는 위치 오류다. 그 밖의 키는 미지원 설정으로 보고한다. 다른 파일이나 기본값으로 조용히 대체하지 않는다.
- 파일 또는 키의 부재만 다음 우선순위로 넘어간다. 빈 값·잘못된 구문/타입·읽기 실패는 부재가 아니다. 기본 새 문서 작성에서는 공유 파일 전체 구문과 키를 검증한다. 기존 경로의 소유권·문서 정리·CLI 범위 판정은 필요한 `root`만 읽으며, 무관한 ownerFolders 오류나 개인 사용자 설정으로 작업을 막지 않는다. 이미 결정된 값보다 낮은 우선순위의 파일은 읽을 필요가 없다.
- `.ak.config`의 홈 범위는 없다. `.ak.user`는 repo/workspace에서 Git 제외 규칙을 확인해 개인 파일로 유지한다. 조회 도구는 설정이나 제외 규칙을 자동 생성·수정하지 않는다.
- 파일 구문과 Alpha Kanban의 스키마 검증을 구분한다. 공통 도구가 이를 구현하며 스킬 본문에 파싱 규칙을 복사하지 않는다. 기본 사용에 새 설정 파일이나 사용자 등록을 선행 절차로 요구하지 않는다.

Git config는 섹션과 키, 주석, 인용 문자열을 제공한다. 이 규약은 그 구문을 사용하되 설정 병합과 include 동작은 별도로 제한한다. [Git config 문서](https://git-scm.com/docs/git-config#_configuration_file)

## 2. 설정 기준과 workspace 연결

| 기준 | 위치 |
| --- | --- |
| 현재 문서 작업 루트 | 실행 중인 현재 Git worktree. 다른 worktree를 쓰기 대상으로 선택하지 않음 |
| repo 공유 정책 | 현재 worktree 루트의 `.ak.config` |
| repo 개인 사용자 | 일반 저장소는 그 루트, linked worktree는 확인된 원래 main worktree 루트의 `.ak.user` |
| 지정 workspace | 해당 Git 공통 저장소의 로컬 설정 `alphaKanban.workspaceRoot`가 가리키는 폴더 |
| 홈 사용자 | 앞 단계에 사용자 지정이 없을 때만 OS의 실제 홈에 있는 `.ak.user` |

workspace 연결은 Git 공통 관리 디렉터리의 `config`에 단일 `alphaKanban.workspaceRoot` 값으로 저장하는 계약이다. 공유 `.ak.config`나 사용자 식별자만 담는 `.ak.user`에 PC 경로를 섞지 않는다. 이 값은 Git commit으로 전달되지 않으며 같은 저장소의 linked worktree가 공유한다. 별도 clone에는 다시 명시해야 한다.

- 연결 값은 존재하고 읽을 수 있는 디렉터리의 절대경로다. 문자열의 `~`·환경 변수·셸 코드를 확장하지 않는다. 공백·한글 경로를 지원하고 쉘 명령 문자열 조립에 사용하지 않는다.
- 정확한 공통 `config` 파일만 읽고 include, 전역 Git 설정, `config.worktree`에서 이 연결 값을 가져오지 않는다. 동일 키가 여러 개면 충돌이다. 공유/개인 설정 우선순위와 Git 자체의 설정 병합을 혼용하지 않는다.
- 연결 없음은 workspace 단계를 생략한다는 뜻이다. 존재하는 연결이 손상되었거나 목적지가 사라진 경우에는 필요한 workspace 판정을 미확정으로 반환한다. 임의 상위 폴더, 같은 이름의 폴더 또는 다른 등록 workspace로 대체하지 않는다.
- workspace는 명시한 설정 범위다. 디렉터리 깊이로 추측하지 않으며, 브라우저의 여러 root/project 연결 목록을 agent의 설정으로 가져오지 않는다. workspace 연결을 읽어도 문서 쓰기 범위는 넓어지지 않는다.
- 설정 연결의 생성·변경·해제는 명시적인 설정 작업이다. 문서 조회·스킬 호출·workspace 브라우저 등록이 이를 자동 저장하지 않는다. 새 연결 관리 UI나 별도 설정 명령의 구현은 이 문서에서 추가하지 않는다.

### Git으로 원래 repo를 확인하는 순서

1. 지정한 현재 위치에서 Git의 `--show-toplevel`, 절대 git-dir, git-common-dir을 읽는다. `.git`을 디렉터리라고 가정하거나 경로 문자열에서 `.git`을 잘라 루트를 만들지 않는다. 호출 위치를 다른 저장소로 바꾸는 `GIT_DIR`/`GIT_WORK_TREE` 등의 환경 재지정은 사용하지 않는다.
2. 실제 경로로 비교한 git-dir과 common-dir이 같으면 현재 working tree 루트가 개인 설정 기준이다. 다르면 `git worktree list --porcelain -z`의 main 항목을 후보로 읽는다. 공백으로 자르거나 브랜치·HEAD·remote로 선택하지 않는다.
3. 후보에 다시 Git 조회를 수행해 실제 working tree 루트가 후보와 일치하고 common-dir이 현재 저장소와 같은지 확인한다. bare 항목, 사라진 경로, 접근 실패, 다른 저장소는 개인 설정 기준으로 채택하지 않는다.
4. 확인한 main 루트의 `.ak.user`와 공통 config의 workspace 연결만 상속한다. linked worktree 루트에 별도로 놓은 `.ak.user`는 이 우선순위의 repo 값이 아니다. 출처 결과에 실제 개인 설정 기준을 표시한다.
5. 다른 branch의 공유 `.ak.config`를 상속하지 않는다. 현재 worktree에 그 파일/키가 없으면 지정 workspace, 그다음 false를 사용한다.

Git은 main worktree를 목록의 첫 항목으로 제공하며 `--porcelain -z`는 경로 내 특수 문자를 구분할 수 있다. 이동된 main worktree의 연결 수리는 별도 Git 작업이다. 판정 도구가 자동으로 `repair`하지 않는다. [Git worktree 문서](https://git-scm.com/docs/git-worktree), [Git 경로 조회 문서](https://git-scm.com/docs/git-rev-parse)

| 상황 | 판정과 지원 한계 |
| --- | --- |
| 일반 `.git` 디렉터리, workspace 밖 linked worktree의 `.git` 파일 | 현재 공유 정책 + 확인된 main의 개인 사용자 + 지정 workspace |
| 같은 HEAD 또는 detached HEAD | 위와 같음. branch/HEAD는 사용자 선택 근거가 아님 |
| 같은 remote의 별도 clone | 독립 설정 범위. 다른 clone의 사용자/연결을 찾지 않음 |
| 원래 repo 이동·삭제·권한 상실, Git 연결 손상 | 관련 상속이 필요한 작업만 미확정. Git 연결/접근을 명시적으로 복구한 뒤 재조회. 홈 사용자로 우회하지 않음 |
| `--separate-git-dir`의 main에서 실행 | 현재 working tree 루트와 공통 저장소가 확인되면 현재 루트를 개인 설정 기준으로 사용 |
| `--separate-git-dir`의 linked worktree, bare 원본 등에서 main 후보가 실제 working tree로 검증되지 않음 | 개인 설정 상속 미지원/미확정. 관리 디렉터리 옆 파일이나 임의 checkout을 읽지 않음 |
| Git 저장소가 아닌 명시된 프로젝트 폴더 | 기존 기본 작성·수정 유지. 프로젝트 루트의 설정을 사용할 수 있으나 Git 기반 workspace 연결·worktree 상속은 없음 |
| Git 조회 자체가 불가능하거나 `.git`이 손상됨 | 기존 명시적 파일 편집·열람은 유지. 필요한 repo/worktree 상속을 성공했다고 보고하지 않음 |

main 후보 확인 실패는 `.ak.user` 파일 부재와 다르다. 반대로 확인한 main 루트에 `.ak.user`만 없는 경우는 정상적인 다음 단계 진행이다. 불필요한 상속 조회를 기본 사용의 장애물로 만들지 않는다.

## 3. 작성·편집 판정표와 도구 결과

공유 정책은 **현재 repo > 지정 workspace > false**, 필요한 개인 사용자는 **원래 repo > 지정 workspace > 홈** 순서다. 명시적 대상이나 기존 파일 위치가 있으면 이를 먼저 사용한다.

| 요청과 조건 | 경로·Owner 결과 | 사용자 조회 |
| --- | --- | --- |
| 새 기본 작성, 모든 설정 없음 | 기존 작성 위치·번호 규칙. Owner·빈 메타데이터 없음 | 불필요 |
| 새 기본 작성, 홈 `.ak.user`만 있음 | 위와 같음. 팀/개인 질문과 자동 @폴더 없음 | 불필요 |
| repo 정책 없음, workspace 정책 없음/false | 위와 같음 | 불필요 |
| repo false, workspace true | repo false 채택. 기존 기본 배치 유지 | 불필요 |
| repo true 또는 repo 미지정·workspace true, 사용자 유효 | 현재 worktree의 `docs/@사용자/`, 폴더와 같은 Owner. 필요한 폴더 생성 계획 반환 | 필요 |
| 위 true, 모든 단계 사용자 미설정 | 해당 기본 작성은 사용자 지정 필요. 경로를 추측하거나 사용자 없는 곳에 대신 작성하지 않음 | 미설정 |
| 필요한 정책/사용자/상속 기준이 손상·충돌·접근 불가 | 해당 판정이 필요한 작업 보류, 오류 출처 보고. false/다른 사용자로 대체하지 않음 | 실패를 부재와 구분 |
| 명시한 일반 폴더에 새 문서 | 명시한 위치, Owner 없음. ownerFolders true여도 자동 재배치 없음 | 불필요 |
| 명시한 `docs/@alice/`에 새 문서 | 명시한 위치, `Owner: @alice`. 내 설정과 같아야 한다는 조건 없음 | 불필요 |
| 기존 일반/@문서 읽기·본문/상태/지시 수정 | 위치·기존 Owner·그 밖의 기록 보존. 설정 변경/제거와 독립 | 불필요 |
| “내 업무” 범위를 선택하거나 “내 폴더”로 인수 요청 | 현재 사용자를 확인해 범위를 제시. 티켓 실행은 별도의 현재 요청에 따름 | 필요 |

명시적인 새 폴더 작성 요청은 ownerFolders의 자동 배치와 구분한다. 기본 작성으로 새 @폴더를 만드는 조건은 true이지만, 사용자가 지정한 폴더 작성·기존 폴더 편집을 false가 금지하지 않는다. 폴더가 있어도 그 안의 미완료 티켓을 자동 실행하지 않는다.

공통 조회 도구는 다음 정보를 구조화해 반환한다. 정확한 명령·필드명·종료 코드는 AKD-11에서 기존 ticket-md와 충돌 없이 정한다.

| 결과 | 필수 의미 |
| --- | --- |
| 작업 종류·대상 | 기본 신규/명시 신규/기존 편집/사용자 필요 작업과 지정한 대상 |
| 정책 | 값·출처 또는 불필요/미확정. 기본 false와 오류를 구분 |
| 사용자 | 유효 식별자·출처 또는 불필요/미설정/오류. 불필요를 미설정 경고로 표시하지 않음 |
| 경로와 메타데이터 | 대상 경로·필요한 폴더 생성 여부·경로 소유자·새 문서에 쓸 Owner. 기존 문서에는 보존 결과 |
| 설정 기준 | 현재 worktree·Git 공통 관리 위치·개인 설정 루트·지정 workspace. 확인 실패 사유 포함 |
| 번호 | 적용할 기존 기본 규칙 또는 해당 사용자 하위의 최대값과 다음 번호 |
| 진단 | 오류 종류·출처·해당 요청의 진행 가능 여부. 관련 없는 설정 실패를 편집 전체 실패로 확대하지 않음 |

조회는 어떤 설정·폴더·문서도 쓰지 않는다. 실제 신규 문서는 요청받은 agent가 결과와 템플릿으로 작성한다. 설정이나 목적지·최대 번호가 바뀌었다면 작성 직전에 재판정한다. 이 확인은 다른 PC/agent를 배제하는 분산 잠금이 아니다.

## 4. 경로 소유자와 식별자

- 프로젝트 기준 `docs` 안에서 파일의 부모부터 올라가며 가장 먼저 만나는 `@사용자` 디렉터리를 소유자 경계로 삼는다. 일반 하위 폴더는 상속하고 중첩된 `@사용자` 폴더는 새 경계다. 파일명의 `@`나 Git/OS 이름으로 소유자를 만들지 않는다. 웹·메타데이터·스킬·CLI는 같은 공통 판정 함수를 사용한다.
- 식별자는 `@` 다음에 문자 또는 숫자로 시작하고 이후 Unicode 문자·숫자·결합 문자, `.`, `_`, `-`를 허용하는 단일 경로 요소다. 빈 값·공백·슬래시/역슬래시·제어문자·끝의 `.`은 허용하지 않는다. 전체 UTF-8 길이는 240바이트 이하로 제한한다. `@alice`, `@alice.dev`, `@홍길동`은 유효하다.
- 비교에 Unicode NFC를 사용하되 기존 폴더·본문을 자동 정규화하지 않는다. 대소문자는 임의로 바꾸지 않는다. 같은 범위에 대소문자·Unicode 표현만 다른 이름이 함께 있거나 대상 파일시스템에서 충돌하면 자동 작성·인계 판정을 멈추고 실제 경로를 보고한다. 서로 다른 문서를 합치거나 다른 표기의 폴더로 조용히 연결하지 않는다.
- 가장 가까운 `@` 폴더가 빈 `@`, `@@name` 등 잘못된 식별자이면 유효한 소유자가 없는 오류로 분류하며 바깥 소유자로 되돌아가지 않는다. 읽을 수 있는 Markdown은 그대로 유지한다. 정상적인 소유자 미지정과 구분하며 기존 폴더를 자동 개명하지 않는다.

| 프로젝트 상대경로 | 경로 소유자 |
| --- | --- |
| `docs/@alice/01_search_plan.md` | `@alice` |
| `docs/@alice/research/02_search_tickets.md` | `@alice` |
| `docs/@bob/archive/@alice/03_notes.md` | `@alice`. 가장 가까운 사용자 폴더 |
| `docs/01_search_plan.md`, `docs/research/02_notes.md` | 미지정 |
| `docs/research/@alice/03_notes.md` | `@alice` |
| `docs/@/04_notes.md`, `docs/@bob/@@name/05_notes.md` | 유효한 소유자 없음. 바깥 소유자 대입 금지 |
| `docs/@bob/@notes.md` | `@bob`. 파일명은 소유자 경계가 아님 |

문서 보관 폴더는 `.ak.config`의 `[documents] root`로 지정하며 기본값은 `docs`다. 설정 파일은 repo 루트에 놓는다. 항목별로 현재 repo → 명시적으로 연결한 workspace → 기본값을 적용하고, 상속된 상대경로도 현재 repo 기준으로 해석한다. `root`와 `ownerFolders`는 독립적이며 기존 문서를 이동하지 않는다. 위 표의 `docs`는 기본값 예시다.

브라우저는 기존 프로젝트 연결 기준에서 설정된 문서 보관 폴더가 보이는 범위의 소유자를 판정한다. repo/하네스 루트 연결이나 workspace에서 발견한 해당 프로젝트를 기준으로 하며, `docs` 자체 또는 그보다 깊은 연결에서 보이지 않는 부모를 복원하지 않는다. 그런 연결에서도 일반 열람·편집은 유지하되 이 규약의 소유자 인식을 보장하지 않는다. 필요하면 `.ak.config`와 문서 보관 폴더가 보이는 프로젝트를 다시 연결한다. 브라우저 workspace 상속은 등록된 workspace의 직접 하위 프로젝트에 한정하며 같은 프로젝트를 직접 연결해도 핸들 동일성으로 유지한다. 홈·개인 사용자 파일·접근권한 밖의 native Git workspace 경로는 읽지 않는다. 설정 오류는 소유자 판정만 미확정으로 두고 일반 렌더링·상태 수정을 막지 않는다. 문서 발견 범위는 기존 프로젝트 전체이며 `root`로 제한하지 않는다.

프로젝트 사이드바는 전체·미지정·단일 소유자 필터를 프로젝트별로 저장한다. 전체 보드는 검색 가능한 소유자 다중 선택 하나로 같은 @이름을 프로젝트와 무관하게 모은다. 선택한 이름과 미지정은 OR로 결합하고 선택 없음은 전체다. 프로젝트 필터와는 AND로 결합하며 전체 보드 선택 목록은 프로젝트별 필터와 독립적으로 저장한다. 서로의 선택을 읽거나 덮어쓰지 않는다. `.ak.user`·현재 사용자·ownerFolders 판정과 무관하며 다른 이름을 동일인으로 등록하지 않는다. ID 없는 문서도 기존 식별을 사용하며 연결/경로 변경 시 재발견과 드래프트 보호는 AKD-02가 검증한다. 필터 조작은 파일 쓰기·배정·실행이 아니다.

## 5. 문서 상단 Owner 한 줄

```markdown
# 검색 기능 구현 계획

Owner: @alice
작성일: 2026-11-01

## 목표와 이유

검색 기능의 작업 범위를 정리한다.
```

- 새 소유자 문서의 표준 표기는 `Owner: @alice`다. 소유자 없는 기본 문서에는 이 줄을 생략한다. 별도 YAML 파일, 필수 YAML front matter, 빈 owner, 티켓별 반복 owner를 만들지 않는다.
- 인식 위치는 문서의 첫 H1 제목 다음에 이어지는 **단일 행 `필드명: 값`과 빈 줄로 구성된 헤더 구간**이다. 일반 문장·목록·코드·다음 제목이 나오면 구간이 끝난다. 기존의 작성일·수정일 등 헤더 값은 보존한다.
- 헤더의 들여쓰기 없는 정확한 `Owner:` 필드 한 개만 읽는다. 값은 따옴표 없는 유효한 사용자 식별자다. 같은 구간의 중복 필드, `owner:` 등 비표준 대소문자 표기, 빈 값, 잘못된 식별자는 오류이며 누락·마지막 값·현재 사용자로 대체하지 않는다.
- 본문·티켓 필드·인용·코드 예제에 등장하는 `Owner:`는 문서 메타데이터가 아니다. 기존 front matter가 있으면 그 내부 필드를 Owner로 채택하지 않으며 원문을 보존한다. 헤더 경계나 기존 front matter가 손상되면 owner 변환을 보류한다.
- Owner는 마지막으로 확인·반영한 문서 소유자다. 현재 경로 소유자, 현재 작업자, 최초 작성자, 문서 ID, 실행 허가와 각각 다르다. 소유자 표시는 경로를 따른다.
- 문서 ID의 기본 후보는 UUID로 유지한다. AKD-12는 같은 문서 헤더의 별도 필드로 확장하는 방향에서 키·검증·중복·보존 규약을 정한다. 첫 페이즈에 UUID나 형식 버전, 추가 title 필드를 발행하지 않는다.

| 현재 경로 | 기록된 Owner | 분석 결과 / 쓰기 |
| --- | --- | --- |
| `docs/@alice/` | 없음 | 레거시 편입·소유자 등록 후보. 읽기만으로 추가하지 않음 |
| `docs/@alice/` | `@bob` | 이동·인수 정합화 후보. 과거 경로나 이동인지 복사인지 추측하지 않음 |
| `docs/@alice/` | `@alice` | 소유자 기록 일치. 링크 정상·이동 완료를 보증하지 않음 |
| 일반/기존 루트 | 없음 | 정상적인 미지정. 필수 이행 대상 아님 |
| 일반/기존 루트 | 유효한 값 있음 | 경로는 미지정. 기록을 보존하고 그 값으로 배정하지 않음 |
| 어느 경로든 | 손상·중복·잘못된 값 | 메타데이터 오류. 누락으로 간주해 덮어쓰지 않음 |

신규 기록은 AKD-11, 기존 문서의 공용 분석은 AKD-03, 이동·참조를 포함한 명시적인 등록·정합화 적용은 AKD-05/06의 책임이다. AKD-17은 웹 문서 정리와 CLI `migrate.targets[].reconcileOwner`에도 Owner 기록 교정을 제공한다. 누락 또는 유효한 불일치 값만 가장 가까운 폴더에 맞추고 미리보기 후 명시적으로 적용한다. 폴더를 확정하지 못하면 Owner를 보존하면서 가능한 ID 발급·섹션 정리는 진행한다. 손상·중복 헤더 보호는 유지한다. 열람·필터·일반 상태 수정·앱/스킬 업데이트는 Owner를 바꾸지 않으며 ownerFolders를 꺼도 기록은 그대로다.

## 6. 번호와 명시적 업무 인계

새 번호는 가장 가까운 사용자 폴더와 일반 하위 폴더의 Markdown 숫자 접두사 최대값 + 1이다. 중첩된 모든 `@` 폴더는 계산에서 제외하며, 같은 사용자명이어도 별도 물리 폴더이면 독립 번호 범위다. 숫자 접두사는 기존 `숫자_` 판정을 재사용한다. 숫자가 없으면 `01`, 100 이상은 자릿수를 줄이지 않는다. 대상 범위 탐색 실패나 정확히 표현할 수 없는 최대값은 불완전한 계산으로 보고 발급을 보류하며 반올림하거나 누락하지 않는다. 기본 사용의 기존 번호 규칙은 그대로다.

| 사례 | 결과 |
| --- | --- |
| @alice에 번호 없음, @bob에 99 | @alice의 첫 번호는 01 |
| @alice 루트에 03, 하위 research에 12, docs 루트에 50 | @alice의 다음 번호는 13 |
| `docs/@bob`에 03, 그 아래 `archive/@alice`에 99 | 바깥 @bob의 다음 번호는 04, 안쪽 @alice는 100 |
| @alice에 01·04·04가 있음 | 다음 번호는 05. 빈 번호를 채우거나 중복 번호를 다시 쓰지 않음 |
| 기존 24·25를 옮겨 사용자 범위의 최대값이 25가 됨 | 이동 파일은 24·25 유지, 다음 신규 번호는 26 |
| 같은 숫자의 다른 파일이 있음 | 번호만으로 충돌 아님. 실제 목적지 파일/경로가 겹치면 보류 |
| 낮은 번호 티켓이 높은 번호 티켓에 의존하거나 최신 지시가 달라짐 | 현재 요청·최신 지시·상태·Depends on이 기준. 번호는 정렬 참고 |

번호는 문서 정체성이나 전역 시간 순서가 아니다. 이동·인수 시 번호를 바꾸지 않고 빈 번호·실제 목적지 충돌을 자동 재번호 부여나 덮어쓰기로 해결하지 않는다.

- 다른 사람의 문서와 그 안의 지시는 참조 컨텍스트다. 현재 agent의 실행 요청이나 자동 작업 큐로 바뀌지 않는다. 내 폴더의 미완료 티켓도 동일하다.
- 퇴사자·휴가자의 `docs/@bob/`에서 `docs/@alice/`로 명시적으로 인수할 수 있다. 원소유자의 도구 내 승인·접속을 요구하지 않는다. 다른 사용자 폴더라는 이유만으로 이동을 금지하지 않는다.
- 후속 CLI는 현재 worktree의 지정 docs 안에서 원본·목적지·변경 전후 소유자를 보여주고 인수 의도에 따라 적용한다. 번호·문서 ID·상태·체크리스트·사용자 지시·진행 메모·완료 증거를 유지한다. 필요한 참조 보정과 Owner 갱신은 같은 검토·안전 적용 대상으로 묶는다.
- 일시 인수의 반환은 명시적인 역방향 이동이다. 이동만으로 티켓을 시작·완료하거나 자동 반환하지 않는다. Owner만 바꾸고 미해결 참조까지 정상화됐다고 보고하지 않는다.
- 폴더·Owner·사용자는 접근 권한이나 동시 실행 잠금이 아니다. 팀 소유자·팀 접두사·공용 배정 시스템은 이번 범위에 없다.

## 7. 검증 근거와 후속 책임

2026-11-01의 AKD-01 규약 확정 당시 코드와 임시 격리 자료로 확인한 결과다. 이후 AKD-11의 구현·설치본 검증은 [별도 결과](team_documents_validation.md)에 기록한다.

| 조사 | 확인한 결과와 한계 |
| --- | --- |
| 현행 Markdown 파서·writer | 최소 YAML owner 헤더와 문서 상단 Owner 한 줄 각각에 대해 LF/CRLF × BOM 유무, 총 8개 조합을 확인했다. 위치 정보의 정상적인 줄 이동을 제외한 티켓 파싱 결과, 지시 추가·상태/진행률 수정 후 비대상 원문, strict ledger 검사가 일치했다. Owner를 인식하는 새 파서를 검증한 것은 아님 |
| Git config 구문 | Git 2.39.5의 파일 지정 조회로 저장소 밖 설정 파싱, 따옴표 없는 @ 값, 키 대소문자 정규화, 중복 값 관찰을 확인했다. Alpha Kanban의 제한 스키마·오류 처리는 구현 전 |
| 일반/외부 worktree | 격리 main repo와 공백·한글 경로의 외부 detached worktree에서 공통 저장소 확인, 현재 공유 파일과 원래 개인 파일의 분리, common config의 workspace 연결을 확인했다 |
| 설정 격리 | include와 worktree config의 동명 값이 정확한 공통 config 조회에 들어오지 않고, 독립 clone이 로컬 workspace 연결을 상속하지 않음을 확인했다 |
| 원래 repo 이동 | main 경로 이동 직후 linked worktree의 Git 조회 실패와 명시적인 Git repair 후 회복을 확인했다. 접근 실패나 삭제를 성공으로 처리하는 근거로 사용하지 않음 |
| 특수 Git 구성 | 별도 git-dir의 목록 첫 경로가 실제 main working tree가 아닌 관리 디렉터리인 경우를 확인했다. bare 원본과 함께 main 후보 재검증이 필요한 지원 한계로 기록 |
| 문서 계약 검토 | 앞의 설정·상속·Owner·번호 표와 인수/반환 조건을 AKD-01 완료 기준에 대조했다. 실제 브라우저 연결·OS 권한·Windows 동작·설치 agent 실행 검증은 수행하지 않음 |

- AKD-02: ID 없는 일반/@문서의 경로 소유자·두 보드/사이드바 필터·일반 편집 보존. 지원하는 프로젝트 연결 범위와 연결 변경 후 결과를 검증한다.
