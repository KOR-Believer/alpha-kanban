# Git 근거 링크로 당시 정책과 코드 열기 계획

## 목표와 이유

플랜이나 인벤토리에 ‘환불 기한은 승인일부터 7일’이라는 결정과 근거 링크가 있다. 이후 정책이 10일로 바뀌어도 그 링크를 누르면 칸반 안에서 당시의 7일 조항이나 이를 구현한 코드 줄을 읽을 수 있어야 한다. 작성 때 쓴 PC와 다른 PC에서도 해당 커밋을 보유한 저장소를 연결하면 된다.

Markdown 본문과 링크 이름만 읽어도 결정의 이유와 근거 위치를 알 수 있게 한다. 스킬이 없는 사람이나 에이전트도 대상 repo에서 `git show <전체 SHA>:<당시 경로>`로 원문을 확인할 수 있다. 작업 기록은 일반 편집기에서도 읽힌다는 [프로젝트 소개](../README.md)의 원칙을 따른다. [실행 티켓](37_alpha_kanban_git_revision_links_tickets.md)

## 영향 범위

- `skills/implementation-ledger/`의 짧은 작성 지침, 상세 참조와 동봉할 읽기 전용 도구. 스킬과 웹이 한 문법을 쓰도록 입력·출력 예제를 공유한다.
- `apps/web/src/browser/`의 repo 연결과 Git 파일 읽기, `apps/web/src/components/`의 Markdown 리더·코드 미리보기, 프로젝트 내 탐색과 권한 복구.
- 문서 이동·경로 보정 CLI의 고정 링크 보존, 배포용 스킬 번들의 도구 포함 여부, 오프라인 PWA 자산과 실제 브라우저 스모크.

## 계획을 세울 때 확인한 상태

- HTTP(S) 본문 링크는 외부 탭에서 열리고, 로컬 링크는 연결한 폴더에서 현재 파일을 찾는다. URL 필터도 로컬 파일용 예외만 둔다. [Markdown 링크 처리](../apps/web/src/browser/MarkdownResources.tsx)
- 브라우저는 허용된 폴더의 `.git` 정보를 읽어 remote 후보를 찾고, 사용자가 선택한 checkout 연결을 프로젝트별 IndexedDB에 보관한다. 이 코드는 과거 커밋의 본문을 읽는 기능까지 제공하지 않는다. [기존 연결 규칙](browser_link_connections.md) · [repo 탐색 코드](../apps/web/src/browser/gitDiscovery.ts)
- 일반·연결 Markdown은 공통 리더를 쓴다. 소스 파일에는 기존 읽기 전용 미리보기와 크기 제한이 있다. Git 파일 읽기 후보인 `isomorphic-git`은 커밋과 경로를 받는 `readBlob`을 제공한다. 실제 폴더 핸들 및 큰 pack과의 조합은 검증할 대상이다. [공통 리더](../apps/web/src/components/MarkdownDocumentReader.tsx) · [파일 미리보기](../apps/web/src/components/files/FilePreview.tsx) · [readBlob](https://isomorphic-git.org/docs/en/readBlob)

## 할 일과 선택한 방향

### 1. 작성자가 실제로 본 판본만 인용한다

| 작성 상황 | 기록 |
| --- | --- |
| 지금 작업할 파일로 안내 | 일반 Markdown 링크를 쓴다. |
| 정책·코드를 읽고 결정하거나 검증 | 대상 파일이 속한 repo에서 실제로 읽은 판본의 전체 커밋 SHA, 해당 트리의 경로, 선택한 절 또는 줄 범위를 기록한다. 링크를 담는 플랜 자체는 미커밋이어도 된다. |
| 대상 파일을 새로 만들었거나 인용한 내용이 작업 폴더에만 있음 | 근거 링크를 기본 생략하고 작성은 계속한다. 결론에 영향을 주면 확인이 필요한 사실을 본문에 쓴다. 사용자가 초안 공유를 요청한 경우에만 현재 초안 링크로 표시한다. |
| 대상 커밋이 아직 내 PC에만 있음 | 그 커밋으로 작성할 수 있다. 다른 PC에서 보려면 같은 커밋이 필요하다. 장기 재현이 필요한 중간 판본은 작성자가 공유 브랜치나 태그로 보존할 수 있다. squash·rebase·배포 뒤 근거 링크를 최종 SHA로 일괄 갱신하지 않는다. |

도구는 대상 repo의 작업 파일과 선택한 커밋의 파일 내용을 대조한다. stage에만 올린 변경도 구분하고 무관한 파일의 수정은 작성에 영향을 주지 않는다. 줄 번호와 절은 같은 판본에서 확인한다. 마지막 수정 커밋이나 blame의 줄 번호를 섞지 않는다. 이미 특정 커밋의 파일을 읽고 분석한 경우에는 그 판본을 직접 인용한다. 새 YAML 필드, 날짜·blob 값의 중복 기록, Git 쓰기 작업은 필요하지 않다.

### 2. 일반 Markdown 안에 근거를 남긴다

모든 결정 근거에는 `web+akgit:/<전체 SHA>/<당시 경로>?repo=<호스트/저장소>#<줄·절>` 링크를 쓴다. repo 힌트는 대상 저장소의 remote에서 자격 증명을 제외하고 얻을 수 있을 때만 넣는다. 알려진 GitHub·GitLab에 같은 커밋이 공유된 근거가 있을 때는 해당 서비스의 HTTPS 고정 링크를 바로 옆에 병기한다. 로컬의 remote-tracking ref는 마지막 동기화 시점의 증거다. 작성 도구는 네트워크로 원격 상태를 바꾸지 않는다. [GitHub 고정 링크](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files) · [GitLab 고정 링크](https://docs.gitlab.com/user/project/repository/files/#create-permalinks)

두 주소는 스킬에 동봉한 함수가 동일한 판본에서 생성한다. 작성자는 대상 파일과 줄·절을 지정한다. 인라인·참조형 모두 일반 Markdown이며 공식 칸반 도메인을 경유하지 않는다. 아래 주소는 예시다.

```md
환불 기한은 승인일부터 7일이다. [환불 정책 §3][policy] · [웹 원문][web]

[policy]: web+akgit:/89abcdef0123456789abcdef0123456789abcdef/policies/refund.md?repo=github.com%2Fexample%2Fteam-policy#환불-기한
[web]: https://github.com/example/team-policy/blob/89abcdef0123456789abcdef0123456789abcdef/policies/refund.md#환불-기한
```

칸반은 인접한 두 링크의 repo·SHA·경로·위치가 일치하면 기본 링크 하나로 보여준다. 열린 판본이나 연결이 필요한 화면에서 웹 원문을 선택할 수 있다. 두 대상이 다르면 각각 보인다. 외부 앱이 OS에 주소를 전달할 수 있도록 설치형 PWA에 `web+akgit`를 등록한다. 외부 뷰어에서는 각자의 Markdown 링크 정책이 적용된다.

remote는 로컬 repo 후보를 좁히는 단서다. 연결 정보는 각 PC에 두고 문서에는 개인 절대경로나 자격 증명을 남기지 않는다. 원격이 없는 교차 repo 링크도 연결한 후보에서 커밋과 파일이 실제로 확인돼야 열린다. 짧은 해시는 표시용이다. 일반 웹 주소·브랜치·PR 링크까지 고정 링크로 해석하지 않는다.

### 3. PWA에서 기록 당시의 파일을 연다

- 사용자가 고정 링크를 열 때 Git 읽기 모듈을 불러온다. 허용된 repo 및 명시적으로 연결한 checkout에서 커밋의 트리와 파일을 조회한다. 네트워크나 checkout 없이 읽는 것이 기본이다. 연결이 모호하면 폴더를 선택하고, 저장한 연결도 사용할 때 권한과 대상을 다시 확인한다.
- 처음 여는 링크는 출발 프로젝트의 연결 폴더에서 원격 주소가 일치하는 복제본을 먼저 찾는다. 저장소 선택 창은 얕은 폴더부터 결과를 누적하며 한 번의 처리 분량을 넘겨도 이어서 찾는다. 끝까지 확인한 작업공간에 일치하는 복제본이 하나면 자동으로 열고, 중지·권한·깊이 제한으로 확인하지 못한 범위가 있거나 복제본이 여러 개면 사용자가 고른다.
- 실제 폴더의 읽기 전용 어댑터로 일반 Git 객체, `.pack`과 인덱스, worktree의 공유 Git 디렉터리를 검증한다. 권한 경계·취소·메모리/읽기 한계를 둔다. `.git`이 허용 범위 밖이면 repo 연결을 안내하고, 복제본에 커밋·파일이 없으면 그 이유를 표시한다. 원격 고정 링크가 있을 때만 사용자가 웹 원문을 선택할 수 있다.
- 기존 리더에서 `기록 당시`와 짧은 SHA를 표시하고 코드 줄 또는 Markdown 절로 이동한다. `현재 파일 보기`는 별도 동작으로 둔다. 현재 파일이 이동·삭제됐거나 당시 절을 찾을 수 없으면 해당 상태를 표시한다. 페이지 주소·새 탭·뒤로 가기와 기존 초안 보호를 유지하고 과거 파일은 읽기 전용으로 연다.

### 4. 과거 문서에서 한 단계 더 읽는다

정책 커밋 A의 `policies/refund.md`에 `[상세 기준](./details.md)`와 `![절차](./steps.png)`가 있으면 두 대상 모두 **정책 repo의 A**에서 찾는다. 다른 폴더의 하위 문서로 이동하면 기준 디렉터리는 그 문서 위치로 바뀌고 repo와 커밋은 계속 A다. 명시적인 다른 고정 링크는 그 링크의 repo와 커밋을 따른다. 로컬 일반 문서의 상대 링크는 기존 방식으로 연다.

이미지는 기존 허용 형식·크기·외부 이미지 동의 규칙을 따른다. 누락·경계 밖·지원하지 않는 대상에는 이유를 표시한다. 문서 이동·PC 경로 보정에서도 과거 커밋에 해당하는 경로와 참조형 링크 정의를 보존한다. 현재 파일의 이동이 옛 트리 경로까지 바꾸면 근거가 깨진다. [기존 문서 참조 처리](../packages/shared/src/documentReferences.mjs)

## 성공을 확인할 방법

1. 두 개의 합성 repo에 인용 당시 7일과 현재 10일을 준비한다. 동봉 도구가 만든 웹 고정 링크와 `web+akgit:` 링크를 PWA에서 눌러 실제 옛 조항·코드 줄을 확인한다. 현재 보기에서만 10일이 나온다.
2. 같은 이름의 파일이 서로 다른 clone에 있는 경우, 원격 없는 repo, 연결 권한 만료, 기록이 빠진 clone, 허용 범위 밖 worktree, 현재 삭제된 파일을 다룬다. `.pack`으로 묶은 clone과 오프라인 재열기에서 원문을 확인하고 큰 pack의 시간·메모리·UI 반응을 측정한다.
3. 과거 문서의 상대 링크와 그림은 A, 별도 고정 링크는 B를 표시한다. 잘못된 절·없는 파일은 최신판으로 대신 열리지 않는다. 이동 CLI 실행 전후 고정 링크의 원문이 같아야 한다.
4. 스킬과 PWA 없이 일반 Markdown 뷰어에서 근거가 읽히는지 확인한다. 스킬 없는 에이전트에는 Markdown과 repo만 주고, 본문에 적지 않은 당시 판정 조건까지 `git show`로 찾아오는지 기록한다. 자동 검증과 실제 브라우저·에이전트 관찰을 구분한다.

## 파일별 판본 보기와 비교

근거 링크를 누르면 인용한 판본을 먼저 읽는다. ‘당시 환불 기한이 며칠이었지?’에는 그 화면에서 바로 답이 보여야 한다. 스크롤하는 동안에도 `기록 당시`, 짧은 커밋 해시, 파일 경로를 확인할 수 있도록 본문 위에 판본 표시줄을 둔다. 아이콘과 문구를 함께 써서 라이트·다크 테마에서 모두 현재 파일 화면과 구별할 수 있게 한다.

`현재와 비교`를 누르면 왼쪽은 **링크에 기록한 커밋의 파일**, 오른쪽은 **연결한 저장소의 디스크에 저장된 현재 파일**을 보여준다. 오른쪽에는 미커밋 수정도 포함된다. 링크에 줄이나 절이 있으면 당시 판본에서 그 위치를 찾는다. 현재 파일이 사라지면 당시 원문을 계속 읽을 수 있게 하고, 읽기 권한이 끊긴 경우에는 권한 복구를 안내한다.

| 파일 | 기록 당시 보기 | 현재와 비교 |
| --- | --- | --- |
| 코드·텍스트 | 해당 판본의 소스와 인용한 줄을 표시한다. | 기존 줄 단위 diff를 재사용해 두 쪽의 줄 번호, 추가·삭제를 나란히 보여준다. |
| Markdown·칸반 문서 | 일반 Markdown은 본문을, 플랜·인벤토리·티켓·스모크·실행 기록은 각 문서 유형의 읽기 화면을 사용한다. 과거 티켓의 상태나 스모크 결과를 읽을 때는 그 판본에 있는 데이터만 쓴다. | 양쪽 Markdown **원문**을 비교한다. 당시 보드나 시트로 돌아가도 판본이 유지된다. |
| 이미지 | 해당 판본의 그림 한 장을 연다. | 비교를 열 때 두 그림을 같은 배율로 나란히 보여준다. 파일 크기와 두 그림의 픽셀 수를 함께 고려해 표시 가능한 쪽만 불러오고, 미리보기 한계를 넘은 쪽에는 사유와 확인 가능한 파일 정보를 표시한다. |

브라우저 검증에서는 당시 환불 문구 7일과 현재 문구 10일을 비교한다. 코드에는 커밋하지 않은 수정값을 저장해 두고 비교 오른쪽에 그 값이 나오는지 확인한다. 상태가 다른 티켓과 색이 다른 이미지도 두 판본에서 확인한다. 현재에서 삭제한 파일은 당시 내용이 계속 보이는지, 한쪽 이미지가 너무 크면 해당 쪽에 사유가 표시되고 다른 쪽은 여전히 보이는지 확인한다. [기존 원문 diff](../apps/web/src/components/CodeDiff.tsx) · [파일 미리보기 기준](../apps/web/src/components/files/previewModel.ts)

부모 커밋과의 비교는 ‘이 커밋에서 환불 기한을 14일에서 7일로 줄였나?’를 검토할 때 쓴다. 다른 파일만 고친 커밋에서 환불 정책을 인용했다면 부모와 비교한 결과는 비어 있다. 근거 링크의 첫 비교는 당시 판본과 현재 작업 파일로 한정한다.
