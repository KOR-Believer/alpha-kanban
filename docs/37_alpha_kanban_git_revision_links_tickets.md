목표:

- 정책이나 코드를 근거로 결정을 내릴 때, 스킬을 쓰지 않는 동료도 그 파일의 당시 내용을 찾을 단서를 남긴다.

현재 문제:

- 일반 경로는 파일이 바뀌면 최신 내용을 연다. 문서를 작성하는 저장소와 근거 파일이 속한 저장소가 다를 수도 있다.

구현 범위:

- 일반 링크와 판본을 고정할 결정 근거를 구별하는 짧은 스킬 지침, 상세 예시, 동봉할 읽기 전용 작성 도구를 마련한다. 대상 repo에서 전체 커밋 SHA, 그 트리의 경로와 줄·절을 확인한다.
- 동봉 함수로 모든 근거에 `web+akgit:`를 생성한다. 인식한 GitHub·GitLab remote에서 커밋 공유 근거가 확인되면 같은 판본의 HTTPS 웹 원문을 바로 옆에 병기한다. 링크 이름에 사람이 읽을 출처·위치를 남긴다. 브라우저와 스킬이 함께 검증할 인라인·참조형 예시를 만든다.

제외 범위:

- 기존 링크의 일괄 변환, 초안을 고정하기 위한 자동 커밋·푸시·태그 생성.

완료 기준:

- [x] 다른 repo의 파일을 인용하면 그 repo의 커밋이 나온다. 경로와 줄·절은 같은 커밋의 원문과 일치한다.
- [x] 근거가 새 파일·미커밋 변경에만 있으면 고정 링크를 생략한다. 링크를 담을 플랜이나 다른 파일에 수정이 있어도 근거 파일이 확인되면 작성할 수 있다.
- [x] 원격 없는 커밋도 머지 전부터 기록할 수 있다. `git show <전체 SHA>:<당시 경로>`로 링크에 적힌 판본을 다시 꺼낼 수 있다.

검증:

- [x] 합성 repo 두 개에서 확정판·staged 변경·작업 폴더 변경·untracked 파일을 나누어 검사한다. 직접 읽은 과거 커밋도 인용해 본다.
- [x] 한글·공백·예약 문자가 있는 경로, 줄 하나·구간·절, GitHub·GitLab·웹 주소를 모르는 remote의 링크를 검증한다. 브랜치 링크와 짧은 해시는 고정 링크 판정에서 빠져야 한다.

사용자 지시:

- 2026-11-20: 결정 근거가 된 판본을 남기고, 미커밋 초안은 평소에는 링크하지 않는다.
- 2026-11-20: 근거는 web+akgit 링크와 확인된 웹 고정 주소를 병기하며, 두 주소를 LLM의 추측 없이 함수로 생성한다.

진행 메모:

- 2026-11-21: 동봉 CLI로 서로 다른 Git 저장소에서 인용문을 생성했다. 공유 이력이 있는 GitHub·GitLab 커밋, 로컬 전용 커밋, 별도 remote, 삭제된 옛 경로, 한글·예약 문자·중복 제목을 대조했다. 미커밋·staged·untracked 근거는 고정하지 않고, 플랜만 수정 중인 경우는 작성할 수 있었다.

목표:

- 동료가 다른 이름·위치에 복제한 repo에서도 PWA가 당시의 파일을 읽게 한다.

현재 문제:

- 기존 Git 탐색은 폴더와 remote 후보를 찾는다. 작업 폴더에서 지워진 파일을 커밋에서 꺼내는 읽기 경로가 필요하다.

구현 범위:

- 기존 repo 연결·권한 복구 흐름을 재사용한다. remote 정보는 후보를 좁히는 데 쓰고, 허용받은 repo에서 커밋과 당시 경로를 검증한다. 후보가 모호하면 사용자가 고른 연결을 프로젝트별로 재사용한다.
- 폴더 핸들에 붙일 읽기 전용 Git 어댑터를 검토한다. `isomorphic-git`을 후보로 loose object, pack 인덱스와 delta, 연결된 worktree의 공용 Git 디렉터리를 실제 폴더로 검증한다.
- Git 읽기는 링크를 열 때 시작한다. 큰 pack의 읽기·메모리 범위와 취소를 시험하고, 권한 부족·커밋 누락·경로 누락·지원 한계의 결과를 구분한다.

제외 범위:

- 네트워크 fetch, checkout, Git 명령 서버, 브라우저에서 repo·작업 파일에 쓰기.

완료 기준:

- [x] 폴더 이름이나 경로만 같은 다른 repo를 선택해도 잘못된 파일을 열지 않는다. 연결을 다시 쓸 때도 권한·커밋·경로가 확인된다.
- [x] 한 번 고른 저장소는 로컬 폴더의 링크 연결 목록에 출발 프로젝트와 함께 표시된다. 사용자가 해제를 확인하면 그 프로젝트의 연결만 지운다.
- [x] 느슨한 객체와 pack에 들어 있는 동일 판본에서 같은 파일 바이트가 나온다. worktree의 공용 Git 디렉터리가 권한 밖이면 필요한 위치를 안내한다.
- [x] 누락된 객체와 제한을 넘는 읽기에는 이유가 남고, 취소 후 다른 문서를 계속 읽을 수 있다.

검증:

- [x] 같은 경로에 서로 다른 내용을 넣은 두 repo, remote 없는 repo, 같은 commit의 복수 clone, 일반·연결 worktree에서 검사한다.
- [x] 합성 repo의 `git show` 결과를 브라우저가 읽은 바이트와 대조한다. pack 저장소의 읽기 시간·반응성·메모리 또는 대용 지표를 기록하고 권한 회수·취소를 재현한다.

사용자 지시:

- 2026-11-21: 후보 저장소를 선택하면 PWA에서 판본을 계속 열 수 있는데, 로컬 폴더의 링크 연결 목록에는 선택한 폴더가 보이지 않는다.
- 2026-11-21: 저장소 선택 창은 탐색 분량을 넘기면 읽던 위치부터 자동으로 이어가고 발견한 후보를 누적한다. 원하는 시점에 중지하거나 후보를 선택할 수 있어야 한다.

진행 메모:

- 2026-11-21: macOS Chrome 157에서 loose·pack·delta 원문을 git show와 바이트 단위로 대조했다. 연결 worktree를 단독 허용했을 때는 공용 Git 폴더를 안내하고, 두 위치가 포함된 작업공간에서는 판본이 열렸다. 4,197,249바이트 합성 pack을 처음 연 한 차례 측정은 194ms였고 이때 50ms 이상 메인 스레드 작업은 관찰되지 않았다. 읽기 한도 초과와 취소도 별도 검증했다. 브라우저 Git 객체 읽기는 SHA-1 저장소를 지원한다.
- 2026-11-21: 로컬 폴더에서 기존 Git 저장소 선택도 출발 프로젝트별로 표시하고 해제할 수 있게 했다. Chrome에서 탐색이 끝나지 않은 상태의 후보 선택, 저장소 재사용, 새로고침 뒤 표시, 해제 취소와 한 프로젝트만 해제 후 재연결을 검증했다.
- 2026-11-21: 출발 작업공간의 remote가 일치하면 커밋·경로를 검증해 열고, 저장소 선택 창은 후보를 누적하며 탐색한다. Mac Chrome에서 실제 링크 한 번으로 당시 정책이 열렸다. 격리 브라우저에서는 빈 폴더 3,020개와 복제본 두 개로 탐색 중지 후 첫 후보 유지, 재탐색 중 두 번째 후보 추가, 선택한 복제본에서 당시 원문 열기를 검증했다. 자동 검사로 3종 처리 분량의 연속 탐색과 깊이 제한·중복 복제본의 자동 연결 차단을 확인했다.

목표:

- 근거 링크를 눌러 당시 조항이나 소스 줄을 읽고, 필요할 때 현재 파일도 열 수 있게 한다.

현재 문제:

- 본문의 웹 링크는 외부 탭을 열고, 현재 파일을 여는 것만으로는 옛 결정이 어떤 문장에 근거했는지 확인하기 어렵다.

구현 범위:

- 지원하는 HTTPS 커밋 링크와 `web+akgit:`를 규칙으로 해석한다. PWA의 프로토콜 핸들러로 외부 호출을 받고, 인접한 칸반·웹 원문 쌍은 대상과 줄·절이 모두 일치할 때만 링크 하나로 표시한다. 일반 웹 링크·브랜치 링크와 기존 로컬 탐색은 각각의 동작을 유지한다.
- 공통 Markdown 리더와 소스 미리보기에 읽기 전용 판본을 연결한다. `기록 당시`와 짧은 SHA, 코드 줄 범위 또는 Markdown 절을 표시하고 `현재 파일 보기`를 제공한다.
- 페이지 주소에는 프로젝트 범위의 판본 식별자를 담고 새 탭·새로고침·뒤로 가기와 기존 초안 보호를 잇는다. 폴더 재연결과, 실제 웹 고정 링크가 있을 때의 웹 원문 열기를 제공한다.

제외 범위:

- 현재판과의 diff, 옛 경로가 사라졌을 때 동명 파일을 추측해 여는 기능.

완료 기준:

- [x] 현재 10일인 정책 링크가 기록 당시의 7일 조항으로 열린다. 사용자가 현재 보기를 택하면 10일을 보고 뒤로 가기로 7일 판본에 돌아온다.
- [x] 현재 파일이 삭제돼도 옛 파일이 있으면 읽을 수 있다. 절·줄을 찾을 수 없으면 같은 판본에서 그 상태를 표시한다.
- [x] 새 탭·새로고침에서도 판본과 위치가 유지된다. Git 객체나 권한이 없을 때 현재 파일이 옛 근거인 것처럼 표시되지 않는다.

검증:

- [x] 일반 Markdown과 연결한 Markdown 양쪽에서 인라인·참조형 근거 링크를 연다. 줄·절, 권한 만료, 현재 파일 누락, 다른 일반 HTTP(S) 링크를 확인한다.
- [x] 작업 중인 티켓 초안을 둔 채 열기·뒤로 가기·새 탭을 실행하고 기존 보존·확인 동작을 검증한다.

사용자 지시:

- 2026-11-20: 정책이나 소스의 당시 내용을 PWA 파일 뷰어 안에서 읽는다.
- 2026-11-20: PWA에서는 같은 근거의 두 주소를 링크 하나로 표시한다.
- 2026-11-21: 저장소 선택은 읽던 문서 위의 모달에서 진행하고 일반 로컬 링크와 같은 UI를 사용한다. Git 판본 열람은 일반 Markdown과 본문 바깥 여백을 맞춘다.

진행 메모:

- 2026-11-21: 일반·연결 Markdown에서 같은 판본과 위치의 인라인·참조형 두 주소가 한 링크로 보였다. 다른 위치를 가리키는 링크는 각각 남았다. 옛 환불 7일 → 현재 10일 → 뒤로 가기, 삭제된 파일, 없는 절·커밋, 새 탭·새로고침을 확인했다. 티켓 초안 보존과 이탈 확인은 라우터 회귀 테스트로 확인했다.
- 2026-11-21: 경로 연결과 Git 근거 링크가 저장소 검색·직접 선택 모달을 공유한다. Chrome에서 모달 취소 후 출발 문서의 주소·방문 기록·키보드 포커스 유지, 폴더 선택 후 한 번의 페이지 이동, 뒤로·앞으로·새 탭·직접 주소를 확인했다. 1280px·850px에서 일반 문서와 기록 당시 문서의 본문 테두리 위치와 바깥 패딩이 일치했다.
- 2026-11-21: 두 단으로 표시하는 문서의 바깥 스크롤바 예약 공간을 제거했다. Chrome 1280px에서 일반·연결·Git 판본 문서의 오른쪽 여백은 20px였고 일반·판본 문서의 좌우가 일치했다. 850px에서는 바깥 영역과 본문을 각각 스크롤할 수 있었다. 같은 티켓을 보드 → Markdown → 보드로 전환해 보드의 스크롤바 공간이 유지되는 것도 확인했다.

### ARL-04. 옛 문서의 상대 링크와 그림을 같은 커밋에서 읽는다

목표:

- 과거 정책을 읽는 도중 상세 문서와 그림을 눌러도 그때 함께 보던 자료를 읽을 수 있게 한다.

현재 문제:

- 옛 Markdown의 상대 경로를 현재 폴더에서 풀면 한 화면에 서로 다른 시점의 정책과 그림이 섞일 수 있다.

구현 범위:

- 상대 문서·이미지·문서 안의 절은 지금 열린 Markdown이 속한 repo와 커밋에서 해석한다. 다음 문서에서는 그 문서의 상위 폴더를 상대 경로 기준으로 삼는다. 다른 판본을 명시한 링크는 그 링크가 지정한 대상을 연다.
- repo 밖 경로, 없어진 자료, 지원하지 않는 이미지와 외부 이미지에는 기존 접근·표시 규칙을 적용한다. 현재 작업 파일에서 시작한 상대 링크는 현재 폴더를 기준으로 유지한다.
- 문서 이동·PC 경로 보정 CLI가 근거 링크 및 참조 정의의 옛 경로·fragment를 바꾸지 않는지 확인한다. 현재 경로를 가리키는 일반 링크의 보정은 계속 작동해야 한다.

제외 범위:

- 옛 repo 전체 파일 트리 열람, 다른 repo의 최신판을 자동으로 대신 표시하는 기능.

완료 기준:
