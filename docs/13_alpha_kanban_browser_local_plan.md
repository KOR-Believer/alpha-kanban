## 목표

- 사용자는 저장소 clone이나 Node 서버 실행 없이 HTTPS 웹사이트에서 자신의 폴더를 선택해 칸반을 사용한다.
- 원본 로컬 Markdown을 직접 읽고 수정한다. 문서를 서버나 별도 DB로 옮겨 원본과 동기화하는 구조는 만들지 않는다.
- 프로젝트별·전체 보드, 문서 묶음과 뷰어, 사유 입력, 수동 지시, 상세창 크기 조절, 한국어/영어 전환을 유지한다.
- AI 작업은 외부 도구에서 수행하고 Markdown으로 결과를 교환한다. 웹앱 사용을 특정 AI 실행기에 종속시키지 않는다.
- 호환 문서가 없는 첫 사용자에게 Start 화면에서 스킬 준비와 문서 생성 흐름을 안내한다.
- 외부에 공유할 `/intro`에서 제품의 역할과 실제 문서 작업 흐름을 설명하고, 반복 사용자는 `/`에서 소개를 다시 거치지 않고 프로젝트를 연다.

## 현재 상태

조사 기준은 2026-10-16의 `kiseong/pr-1-review` 작업트리다. 기여자 확인 대상인 `bc25227`과 이후 미커밋 변경을 구분하며, 아래는 구현 완료 선언이 아니라 코드에서 확인한 사실이다.

- `apps/web/src/main.tsx`는 React와 TanStack Router 기반 CSR이다. SSR에서 CSR로 바꾸는 작업이 아니라 파일 입출력을 브라우저로 옮기는 작업이다.
- `apps/web/src/App.tsx`와 `AllProjectsBoard.tsx`는 HTTP API로 프로젝트, 문서, 보드 순서, 티켓 저장을 처리한다. 프런트엔드만 그대로 배포하면 동작하지 않는다.
- `apps/server/src/markdown/ticketMarkdown.ts`의 분석·상태 변경·사용자 지시 추가는 문자열 처리다. `files.ts`의 Node 파일 접근과 분리해 재사용할 수 있다.
- `files.ts`는 해시·수정 시각을 확인하고 임시 파일을 교체한다. `pathLock.ts`는 같은 서버 프로세스 안의 요청만 직렬화하며 외부 편집기를 잠그지는 않는다.
- `markdownFileEvents.ts`는 750ms 주기 조회와 SSE로 변경을 알린다. 브라우저에서도 주기 조회와 창 복귀 시 재확인을 조합할 수 있다.
- `packages/shared/src/index.ts`는 절대경로를 파일 정보에 요구한다. `allProjectsData.ts`는 절대경로로 중복 문서와 카드 순서를 식별한다. 웹 전환에서는 가짜 절대경로 대신 별도 식별 규칙이 필요하다.
- `documentSetSorting.ts`의 여섯 정렬 계산은 이미 브라우저에서 실행된다. 서버가 만드는 문서 묶음·수정 시각·진행률을 같은 의미로 공급하면 재사용할 수 있다.
- 전체보드 수동 순서는 제어 저장소의 `.alpha-kanban/state.json`에 저장하고 문서 정렬 옵션·언어·상세창 설정은 localStorage에 저장한다. 원본 Markdown의 순서와 화면의 수동 순서는 별개다.
- `apps/web/src/features.ts`는 채팅 진입점을 숨긴다. Codex 실행·채팅 API와 기존 로그는 아직 남아 있으므로 UI 미노출을 서버 제거 완료로 해석하지 않는다.
- 동봉 스킬에는 최신 사용자 지시, 재오픈, 사용자 DONE과 에이전트 검증의 구분 규칙이 있다. 개인 설치본과 자동 동기화되지는 않는다.

## 결정 및 구현 방향

### 1. 정적 웹과 로컬 원본

```text
HTTPS 정적 웹앱
  -> 사용자가 폴더 선택과 권한 허용
  -> 브라우저에서 문서 분석과 칸반 표시
  -> 사용자 조작을 같은 로컬 Markdown에 저장

외부 AI 도구 <-> 같은 로컬 Markdown
```

- 공유 문서 로직과 파일 접근 계층을 분리한다. 기존 Node 연결과 새 브라우저 연결은 같은 문서 계약을 사용하고, 화면마다 파일 접근 코드를 중복 구현하지 않는다.
- 웹 실행에는 API 서버나 Node가 필요 없어야 한다. 개발·빌드 도구와 외부 AI 또는 선택적 mjs 도구의 실행 환경은 별개이며, 그 차이를 안내한다.
- 1차 지원·검증 대상은 데스크톱 Chrome으로 확정한다. File System Access API를 사용하며 착수 시 필요한 API와 권한 동작을 확인한다. Edge 등 다른 Chromium 브라우저는 별도 지원 보장이나 필수 검증 대상으로 두지 않는다. 미지원 환경에는 명확한 안내를 제공하며 파일 다운로드를 원본 직접 저장처럼 표현하지 않는다.

### 2. 폴더 권한과 프로젝트 식별

- 사용자가 직접 고른 폴더만 접근한다. 웹에서 임의의 절대경로나 홈 디렉터리를 열 수 있다고 가정하지 않는다.
- 등록 루트 바로 아래 폴더를 프로젝트로 묶고, 겹치는 루트는 더 구체적인 쪽을 우선한다. 경로 문자열 길이가 아니라 폴더 참조의 동일성·포함 관계를 검사한다.
- 폴더 참조와 브라우저 내부 ID, 상대경로를 사용한다. 표시용 프로젝트 분류와 문서의 고유 식별자를 분리해 같은 문서가 다른 등록 루트로 발견되어도 카드·저장 잠금·수동 순서의 대상이 중복되지 않게 한다. 기본 폴더 등록부는 AKL-01에서 마련한다.
- 폴더를 다시 선택했을 때 동일한 참조인지 확인하고 ID를 재사용한다. 삭제 후 재생성·이동·이름 변경으로 동일성을 확인할 수 없으면 명시적인 재연결을 요구하며 파일명이나 내용이 같다는 이유로 연결하지 않는다.
- 탐색할 문서 폴더는 허용한 프로젝트 내부의 상대경로로 한정한다. 기존 `defaultDocRoots`의 절대경로나 프로젝트 밖 경로는 자동으로 따라가지 않으며 별도 폴더 선택이 필요하다.
- 브라우저 1차 구현은 선택한 프로젝트 내부의 `.md`를 탐색하되 숨김·의존성·빌드 폴더를 제외한다. 루트의 README와 docs 외 문서도 읽을 수 있으며 기존 Node의 docRoots 설정을 자동 이식하지 않는다. 최대 5,000개, 파일당 10 MiB, 깊이 30의 탐색 제한과 본문 캐시 64 MiB 제한을 적용하고, 본문 캐시에서 빠진 파일도 메타데이터·묶음 진행률을 별도 유지한다.
- 전체보드는 같은 폴더 범위에서 `_tickets.md`만 등록하고 본문을 읽는다. 프로젝트 보드의 일반 Markdown 탐색은 유지한다. 문서 ID는 경로 색인과 기존 파일 참조를 탐색당 한 번 확인해 재사용하며 새 파일마다 전체 문서와 비교하지 않는다. 먼저 읽힌 프로젝트부터 표시하고 전체 읽기 완료 전에는 카드 순서 변경을 막는다.
- 프로젝트 화면의 선택 문서는 저장된 ID로 먼저 읽고 사이드바 목록은 별도로 탐색한다. 목록의 지연·실패가 열린 문서·상세창·초안을 숨기거나 선택을 바꾸지 않게 한다.
- 프로젝트 선택줄과 시작 화면의 제목·프로젝트 행은 기존 서버 버전과 같은 UI 컴포넌트를 사용한다. 가로 선택줄의 이름·경로·문서 상태와 폴더 연결·권한을 유지한다. 최근 프로젝트 최대 5개와 접힌 다른 프로젝트는 AKL-01의 초기 구현이며, 시작 화면의 후속 목표는 AKL-08에서 승인한 전체 폭·좌우 목록 배치로 대체한다.
- 사이드바 헤더는 기존 두 줄 높이를 유지한다. 첫 줄은 문서 이름·파일명·경로 검색과 필터 팝오버, 둘째 줄은 정렬이다. 언어 선택은 로컬 폴더 버튼과 같은 소형 컨트롤 크기를 사용한다.
- 프로젝트 보드와 전체보드는 컬럼별 스크롤 대신 보드 전체 스크롤을 사용하고 상태 제목줄을 고정한다. 스크롤 영역의 위 여백으로 카드가 비치거나 상단 테두리가 중복되지 않게 한다.
- 기존 localhost의 설정과 절대경로 기반 URL은 배포 도메인으로 자동 승계되지 않는다. 최초 폴더 재연결을 안내하고 다른 PC에서도 같은 URL만으로 문서가 열린다고 약속하지 않는다.
- 읽기 권한과 쓰기 권한을 구분하고 거부·취소·철회·삭제·이동·브라우저 데이터 초기화에서 재연결할 수 있게 한다. 기억된 폴더 참조를 영구 권한으로 간주하지 않는다.
- 폴더 미선택, 등록부 복원 중, 권한 재승인 필요, 읽기 가능, 쓰기 가능, 실제 경로 없음 상태를 구분한다. 복원 중이거나 일부 탐색이 실패했다고 URL을 초기화하거나 첫 문서로 이동하지 않는다.

### 3. 문서와 티켓 정렬 유지

정렬은 보기 설정이다. 정렬 옵션이나 전체보드의 위아래 버튼을 바꿔도 Markdown을 수정하거나 수정 시각을 갱신하지 않는다. 상태·진행률 변경과 사유·수동 지시 저장은 원본 파일에 반영한다.

| 항목 | 유지할 동작 |
| --- | --- |
| 문서 묶음 | 같은 프로젝트·디렉터리·slug 단위. 묶음 내부는 Plan, Tickets, Inventory, 일반 Markdown 순서 후 번호·상대경로로 정렬 |
| 문서 번호순 | 기본 오름차순. 묶음의 최소 번호를 사용하고 내림차순은 최대 번호 사용. `1_A_plan, 2_A_tickets, 3_B_plan, 4_B_tickets, 5_A_inventory`는 양 방향 모두 A 묶음이 먼저 |
| 최근 수정순 | 묶음 전체 파일의 `File.lastModified` 최댓값, 기본 내림차순. 대표 파일만 보거나 앱에서 읽은 시각·문서 작성일·Git 커밋 시각으로 대체하지 않음 |
| 종류순 | 대표 문서의 종류 기준. Tickets, Plan, Inventory, 일반 Markdown 순서 |
| 진행률순 | 현재처럼 묶음의 첫 tickets 문서 상단 완료/전체 개수 비율 사용. 여러 tickets 파일 합산으로 변경하지 않음 |
| 이름순·폴더순 | 기존 자연수 비교와 동률 보조 순서 유지. 비교 언어 정책 변경은 이번 이전의 필수 범위가 아님 |
| 정렬 값 누락 | 비교 가능한 문서 뒤에 배치하고 기존 번호·폴더·이름 보조 순서 유지 |
| 프로젝트 보드 | 기본은 티켓 본문 등장 순서. DONE 전체에 유효한 Completed at이 있을 때만 최신 완료순; 하나라도 없거나 잘못되면 DONE 전체의 문서 순서 유지 |
| 전체보드 수동 순서 | 위아래 버튼과 같은 열 드래그는 브라우저에만 저장. 프로젝트 필터별 별도 순서가 아닌 전체보드 공통 순서를 유지하고 프로젝트 보드 순서에는 적용하지 않음 |

- 최근 수정순은 파일 시스템의 수정 시각이라는 기존 의미를 유지한다. 별도 날짜 필드를 문서에 심지 않으며 외부 편집·파일 복사·Git 작업에 따라 바뀔 수 있다.
- 본문 해시가 같아도 수정 시각이 달라지면 최근 수정순의 메타데이터는 갱신한다. 저장 충돌 확인은 수정 시각만 믿지 않고 내용 해시를 사용한다.
- 문서 필터 팝오버에는 일반 Markdown 제외와 100% 완료된 세트 제외를 독립 체크박스로 둔다. 검색과 활성 조건을 모두 만족하는 묶음만 표시하고, 단독 여부나 종류별 칩은 추가하지 않는다. 필터는 이미 읽은 목록에만 적용하며 폴더 재탐색·파일 쓰기·선택 변경을 일으키지 않는다.
- 완료 제외는 묶음에 속한 모든 티켓 파일의 완료/전체 개수가 확인되고 전체 티켓 수가 0보다 크며 모두 완료일 때만 적용한다. 읽기 실패·누락·불일치 값은 완료로 추정하지 않는다. 이 판정은 기존 첫 티켓 파일의 진행률 배지와 정렬 기준을 바꾸지 않는 별도 값으로 제공한다.
- 제외 조건은 브라우저 보기 설정으로 즉시 저장하고 검색어는 프로젝트 전환 시 비운다. 필터 때문에 목록에서 빠져도 열린 문서와 티켓 초안은 유지한다. 검색 결과가 없을 때 조건 초기화를 제공한다.
- 수동 순서가 없는 새 카드는 안정적인 프로젝트·문서·티켓 기본 순서로 뒤에 배치한다. 일시적으로 접근할 수 없는 문서의 순서 항목은 삭제하지 않는다.

### 4. 저장과 외부 변경

- 현재의 티켓 수정 규칙을 재사용한다. 상태·진행률·Completed at·상단 집계·사용자 사유는 한 번의 문서 저장으로 반영하고 수동 지시는 사용자 지시란에만 추가한다.
- 한 번 얻은 파일 버전에서 본문·해시·수정 시각을 함께 만든다. 현재 `files.ts`처럼 본문과 해시용 본문을 별도로 읽는 경로는 그대로 복제하지 않는다. 읽는 도중 교체되어 실패하면 다시 읽거나 변경 안내로 처리한다.
- 같은 파일 안의 중복 티켓 ID·중복 필드 등 수정 대상이 모호한 문서는 쓰기를 거부한다. 다른 티켓·알 수 없는 본문·기존 체크박스·개행·UTF-8 BOM을 보존하고 기록 시각은 사용자 PC의 로컬 오프셋을 포함한다.
- 읽은 내용의 해시를 보관하고 저장 직전 최신 파일과 비교한다. 달라졌으면 저장을 중지하고 작성 중인 사유·지시를 유지한 채 갱신하게 한다. 오래된 문서 전체를 그대로 덮어쓰지 않는다.
- 여러 탭의 저장은 동일 문서 ID를 기준으로 같은 출처의 잠금으로 직렬화한다. `createWritable()`의 `close()` 완료와 결과 재읽기 전까지 성공으로 표시하지 않으며 실패 시 카드와 입력을 보존한다.
- 외부 AI와 편집기는 같은 잠금에 참여하지 않는다. 해시 비교와 임시 저장으로 모든 경쟁 상태가 사라진다고 보장하지 않고, 검사 직후 외부 쓰기가 발생하는 위험과 실패 복구를 검증한다.
- 최소 복구안은 쓰기 전 원문·예정 결과·사유를 로컬 복구 항목으로 보관하고, 성공 확인 후 정리하는 것이다. 복구 항목 저장에 실패하면 원본 쓰기를 시작하지 않는다. 확인되지 않은 저장은 재읽기·복구본 다운로드로 해결하고 사유를 무조건 재전송하지 않는다. 앱이 읽지 못한 외부 중간 버전까지 복구된다고 보장하지 않는다.
- Markdown 저장과 IndexedDB의 카드 순서 저장은 별도 작업이다. 상태와 사유 저장 후 순서만 실패하면 상태를 되돌리거나 사유를 다시 append하지 않고 순서 저장만 재시도한다.
- 열린 문서 위주의 주기 조회, 창 복귀 시 확인, 수동 새로고침을 제공한다. 전체 폴더의 과도한 재귀 스캔을 피하고 새 파일·삭제·이름 변경도 재탐색한다.
- 전체보드와 프로젝트 사이드바의 15초 갱신은 이미 발견한 파일의 메타데이터를 확인하며 변경 없는 본문은 다시 읽지 않는다. 폴더 재탐색은 직전 완료 후 60초가 지나거나 수동 새로고침·연결 변경·참조 삭제·이동 시 수행한다. 첫 읽기의 프로젝트 진행 수와 백그라운드 변경 확인을 구분하고, 백그라운드 갱신 동안 기존 카드는 유지한다.
- 프로젝트의 열린 문서는 목록 탐색과 독립적으로 15초·창 복귀·자체 저장 알림에 본문을 확인한다. 관찰을 시작할 때 다른 기존 문서들을 변경 이벤트로 발행하지 않는다. 명시적으로 목록을 무효화한 뒤 이전 탐색의 늦은 결과를 새 캐시로 등록하지 않는다.
- 변경 파일의 메타데이터·분석 결과를 두 보드와 문서 목록에서 공유한다. 제한된 병렬 읽기와 메타데이터 색인으로 중복 읽기를 줄이고, 기존 750ms 전체 내용 검사나 전체보드 전체 재조회 주기를 그대로 복제하지 않는다. 읽기 실패를 삭제로 확정하지 않는다.
- 편집 중 외부 변경은 상태·사유 초안을 유지하고 갱신 안내로 처리한다. 읽기 화면의 갱신과 편집 화면의 보호 정책을 두 보드, 포커스 복귀, 다른 탭 알림에 동일하게 적용한다.
- 파일이 외부에서 교체되면 필요한 폴더 참조와 상대경로로 다시 찾는다. 백그라운드나 닫힌 탭에서 항상 감시된다고 약속하지 않는다. FileSystemObserver는 필수 의존성으로 삼지 않는다.

### 5. 보조 상태와 화면 복원

| 데이터 | 브라우저 실행의 저장 위치 | 이전·복원 원칙 |
| --- | --- | --- |
| 티켓 상태·완료 시각·사유·지시 | 원본 Markdown | 유일한 원장. DB 캐시를 원본 위에 덮어쓰지 않음 |
| 폴더 참조·프로젝트/문서 ID 등록부 | IndexedDB | 폴더 동일성 확인 후 재사용. 권한은 별도 확인 |
| 최근 프로젝트·마지막 프로젝트·전체보드 수동 순서 | IndexedDB | 서버 state.json 대신 브라우저 프로필별 보조 상태. 탭 간 저장 직렬화와 변경 알림 |
| 프로젝트별 문서 정렬·전체보드 필터·사이드바 제외 조건 | localStorage | 프로젝트별 정렬에는 브라우저 내부 ID 사용. 사이드바 제외 조건은 공통 보기 설정이며 접근 실패로 설정을 지우지 않음 |
| 언어·자동 열기·사이드바 폭·상세창 모드/크기 | localStorage | 보기 설정 유지. 자동 열기 설정 변경 자체로 즉시 이동하지 않음 |
| 문서 색인·화면 캐시 | IndexedDB 또는 메모리 | 재생성 가능. 실제 원본 확인 없이 저장 기준으로 사용하지 않음 |
| 진행 중 저장·실패한 입력 복구 항목 | 메모리와 IndexedDB | 정상 확인 후 정리하며 원본이나 무기한 문서 백업으로 사용하지 않음 |

- 전체보드 순서는 같은 API 서버를 쓰는 브라우저들의 공통 상태에서 각 브라우저 프로필의 상태로 바뀐다. 프로젝트 보드 수동 순서나 여러 PC 설정 동기화는 새로 도입하지 않는다.
- 같은 사이트의 여러 탭은 파일·설정 변경 알림을 공유하고 관련 캐시를 갱신한다. 순서 변경은 저장 시 최신 목록을 기준으로 반영하거나 오래된 변경을 거부해 전체 배열 덮어쓰기 유실을 막는다.
- 최초 웹 접속은 폴더 재연결을 기본으로 한다. localhost 설정 자동 승계, 다른 프로필/PC 이전, 설정 내보내기·가져오기는 MVP 필수 범위가 아니다. 원본 Markdown은 마이그레이션하지 않는다.
- 사이트 데이터 삭제·브라우저 저장소 실패 시 원본 파일은 보존되고 보기 설정은 초기화될 수 있음을 안내한다. 보조 상태 저장 실패를 원본 파일 손상이나 저장 성공으로 혼동하지 않는다.
- 로컬 파일 조회는 네트워크 연결 여부로 대기하지 않도록 React Query 실행 설정을 분리한다. 앱을 이미 연 상태의 파일 접근과 앱 자체의 완전한 오프라인 최초 실행/PWA는 구분한다.

### 6. 첫 화면과 AI 도구 안내

#### 디자인 선행과 승인

- AKL-08은 Open Design 데스크톱 앱의 시안 작업이다. 먼저 MCP 연결과 사용 가능한 기능을 확인하고, 사용할 수 없으면 computer use로 해당 앱을 조작한다. 둘 다 불가능하면 제한을 보고하며 앱 설치·재설치나 실제 서비스 코드 변경으로 대신하지 않는다.
- 실제 앱 코드를 수정하지 않는 별도 디자인 작업물로 전체 폭, 최근/다른 프로젝트의 좌우 배치와 내부 스크롤, 간결한 등록 폴더 영역, 설치·시작 안내를 제안한다. shadcn b1 토큰과 기존 컴포넌트의 크기·색·선·간격을 참고하며 폐기한 DESIGN-notion.md를 사용하지 않는다.
- 프로젝트가 많은 상태, 최근 기록 없음, 연결 폴더 없음, 권한 재연결 상태와 좁은 화면을 시안에 포함한다. 테스트용 이름과 데이터를 사용하고 실제 프로젝트 파일이나 개인 설정을 디자인 도구로 가져오지 않는다.
- 산출물은 다시 열 수 있는 Open Design 작업물 위치 또는 내보낸 시안, 주요 화면 캡처, 적용할 배치·동작의 짧은 설명이다. 생성 완료와 사용자 승인은 구분한다. 승인한 시안 식별자와 수정 의견을 기록한 뒤에만 AKL-09를 실행한다.
- AKL-14는 같은 접근 방식으로 `/intro` 소개 랜딩을 별도 Open Design 프로젝트에 만든다. AKL-08의 시작 화면 작업물을 덮어쓰지 않으며 소개 시안의 검토·승인을 따로 기록한 뒤 AKL-15의 앱 적용 여부를 결정한다.

#### 시작 화면의 배치와 용어

- `/`의 Start가 가용 가로폭 전체를 사용하는 프로젝트 시작 화면으로 남는다. 위쪽에는 프로젝트 열기·워크스페이스 등록·새 프로젝트와 기존 언어/자동 열기 설정을 간결하게 배치한다. 소개 랜딩은 `/intro`로 분리하고 첫 방문 여부로 강제 이동시키지 않는다.
- 최근 프로젝트 최대 5개와 나머지 프로젝트를 좌우의 같은 높이 목록으로 나누고 제목은 고정한 채 각 목록 내부만 스크롤한다. 두 목록에서 같은 프로젝트를 중복 노출하지 않으며 최근 기록이 없다고 임의의 프로젝트를 최근으로 표시하지 않는다. 좁은 화면은 두 목록을 탭으로 전환한다. 검색 입력과 정렬 선택은 36px로 맞추고 문서 있음/없음 배지는 강조색/중립색으로 구분한다.
- 등록된 워크스페이스는 간결한 목록이나 관리 진입점으로 제공한다. 화면을 거대한 카드나 중첩 카드로 채우지 않고 기존 ak-scroll-area와 공통 UI 기반을 유지한다. 목록의 길이로 설치 안내가 끝없이 아래로 밀리지 않게 한다.
- 사용자 표현은 '워크스페이스 등록'으로 바꾸고 '프로젝트들이 모여 있는 상위 폴더를 등록하면 바로 아래 폴더들을 프로젝트로 자동 탐색해 추가합니다'라고 설명한다. 프로젝트 하나만 여는 동작과 구분하며 복사·업로드·무제한 재귀 탐색으로 오해하게 하지 않는다.
- 이 용어 변경은 UI 경계에 한정한다. 내부 root/project 역할, 폴더 참조·ID·권한, 더 구체적인 중첩 루트 우선 규칙과 기존 설정은 유지한다. 설정 변경이 즉시 프로젝트 이동을 일으키지 않게 한다.
- 목록 표시·스크롤·언어 전환으로 새 전체 탐색이나 파일 쓰기를 시작하지 않는다. 기존 Node 모드의 실행 경로와 공통 컴포넌트 사용도 보존한다.

#### 별도 소개 랜딩

- 같은 정적 앱의 `/intro`를 외부 공유용 소개 페이지로 둔다. 별도 배포나 도메인은 만들지 않는다. `/`와 기존 `/all`, `/w/:id` 동선 및 마지막 프로젝트 자동 열기의 다음 루트 진입 적용을 유지한다. `/intro` 직접 진입은 자동 열기 설정과 무관하게 소개를 표시한다.
- 첫 화면에서 Alpha Kanban 이름, 읽을 수 있는 칸반 예제, 시작 화면으로 이동하는 주요 동작을 보여준다. AI 채팅에서 작업하고 칸반에서 계획과 진행 상황을 확인하는 역할을 설명한다.
- 외부 AI와 사양 논의, plan/tickets 및 선택적 inventory 생성, 칸반에서 계획·진행 확인, AI 채팅에서 계속 작업하기를 소개한다. 모든 작업을 AI 채팅만으로 진행해도 된다. 상태 이동·수동 지시 기록은 필요할 때만 쓰며, 사용했다면 AI에 바뀐 문서를 다시 읽도록 요청한다.
- 폴더 권한과 업로드 여부 등 실제 이용에 필요한 정보만 안내한다. 과거 서버 POC와 비교하거나 호환 Markdown 지식을 요구하지 않는다. 버전 준비·검증 대기·미착수 사유 같은 오너 보고는 티켓에만 남기고 무조건적인 보안 보장이나 미검증 기능 지원을 선언하지 않는다.
- 시작 화면에는 짧은 사용 흐름과 소개·설치 안내 진입점만 남긴다. 자세한 설명과 예시는 `/intro`에서 제공하되 설치·버전 정보는 AKL-13과 같은 원본을 사용한다. 아직 공개되지 않은 태그·설치 문서 주소·버전은 배포 완료처럼 표시하지 않는다.
- 한국어 기본, 영어 전환, 데스크톱과 좁은 화면을 제공한다. 실제 앱의 시작 버튼은 /로 이동하며 기존 자동 열기 설정과 무관하게 명시적인 프로젝트 선택을 유지한다. 소개 진입으로 프로젝트 조회·파일 권한·AI 실행을 시작하지 않는다.
- 승인 시안의 책갈피 프로젝트를 현재 shadcn 테마의 마크업 데모로 적용한다. 보드와 Markdown 발췌는 하나의 데이터에서 생성한다. 개인 프로젝트 캡처는 사용하지 않고 기존 앱 내부 보드도 재디자인하지 않는다. 공개 배포·DNS는 별도 승인 범위다.

#### 설치와 문서 작업 안내

- 빈 프로젝트도 정상 시작점이다. 외부 AI와 사양을 논의해 플랜 초안을 만들고, 이번 구현에 영향을 주는 열린 질문을 먼저 논의한 뒤 합의한 범위·완료 기준으로 티켓을 생성하거나 갱신하도록 안내한다. 이후 AI에 구현을 요청하고 폴더를 연결해 칸반에서 검토한다. 필요 시 inventory를 더하며 AI 채팅만으로 작업을 이어갈 수도 있다.
- 문서가 없는 프로젝트에는 독서 기록 앱을 예로 든 넓은 7단계 안내를 제공한다. 아이데이션 대화, 플랜·티켓 초안, 사람이 초안 검토, 관련 열린 질문의 반복 논의, 결정사항으로 문서 갱신, 최종 문서 재검토, 티켓 순차 구현 요청을 구분한다. 실제 요청문은 복사 가능하게 두고 사람의 검토 항목은 별도로 표시한다. 시작·소개 화면의 간단한 요약은 유지하며, 복사는 AI 실행이나 문서 저장을 하지 않는다.
- 일반 Markdown만 있고 플랜·티켓·인벤토리가 없는 프로젝트도 안내를 기본으로 표시한다. 일반 문서는 사이드바에서 직접 선택하거나 문서 링크로 진입했을 때 열고, 계획 문서가 있으면 그중 첫 문서를 자동 선택한다. 판단은 검색·필터 전 전체 문서 목록을 기준으로 하며 명시적으로 연 문서를 목록 갱신이나 언어 전환으로 닫지 않는다.
- 사이드바 하단의 고정된 사용 안내 진입점으로 문서를 읽은 뒤에도 안내로 돌아올 수 있다. 계획 문서가 있는 프로젝트에서도 제공하며 문서 검색·필터의 영향을 받지 않는다. 명시적으로 연 안내는 /w/:id?view=guide에 반영해 새로고침 후에도 유지하고, 다음 문서 선택이나 프로젝트 전환 전까지 자동 문서 선택을 중지한다. 기존 검색·정렬 두 줄의 높이는 유지한다.
- 동봉 implementation-ledger는 구현 요청 시 선택한 티켓·현재 지시와 연결된 플랜의 미결정 사항을 확인한다. 이번 작업의 목표·범위·사용자 동작·완료 기준에 영향을 주고 자체 조사로 해결할 수 없는 사용자 판단만 해당 구현 전에 묻는다. 기존 답변·명시적 위임은 재확인하지 않고, 관련 없는 질문이나 후속 작업의 질문은 유지한 채 독립 작업을 진행할 수 있다. 문서의 모든 질문 해소를 강제하지 않으며 개인 전역 스킬은 변경하지 않는다.
- 'Codex에 전달할 설치 요청 복사'를 기본 동작으로 두고 GitHub 원본 보기와 인라인 설치 안내를 제공한다. ZIP은 수동 설치의 보조 수단으로 내린다. 선택적 npx 설치 명령은 Node가 필요한 별도 방법이며 웹앱 이용의 전제가 아니다.
- 설치 요청과 필요 시 INSTALL.md에는 공식 출처, 검증된 배포 태그/커밋, 전체 스킬 폴더 설치, 기존 설치본 비교·보존 조건을 포함한다. 아직 공개하지 않은 파일 주소나 작업 브랜치가 배포 완료된 것처럼 안내하지 않는다.
- 설치 자료는 SKILL.md뿐 아니라 references·assets·scripts·변경 이력·버전 정보를 함께 제공한다. 설치 안내와 다운로드 manifest는 같은 배포 정보를 사용하고, 웹사이트가 개인 AI 설정 폴더를 자동 설치·검사하거나 AI를 실행하지 않는다고 명시한다.
- 버전 계약 완료 후 검증된 배포 스킬 버전·지원 문서 형식·변경 내용을 연결한다. 별도 확인하지 않은 개인 설치 버전을 추정하지 않는다. 준비 상황은 AKL-10~13에 남기며 제품에 준비 중/검증 대기 문구를 붙이지 않는다.
- 한국어·영어 안내를 같은 의미로 제공하고 빈 프로젝트에서도 다시 찾을 수 있게 한다. 호환 문서 소지 여부를 공개 안내의 전제로 삼지 않으며, 웹에서 지시를 저장하는 것은 선택 기능이자 Markdown 수정이지 AI 자동 전송이 아니다.
- 공통 문서 계약은 유지하되 실제 지원 여부는 도구별로 구분한다. 현재 Codex용 동봉본 기준이며 Claude는 AKL-07에서 포팅·실행 검증 후 지원 표시를 변경한다.

### 7. 웹 실행 정리와 배포

- 정적 호스팅은 Cloudflare Pages로 확정한다. 2026-10-18 사용자 결정으로 정식 주소는 `https://kanban.giveit2.me`이며 사이트 루트에 배포한다. `<project>.pages.dev`와 preview는 검증용으로 구분한다. Node API 서버, Pages Functions나 Workers 실행 코드는 도입하지 않는다. 개발·빌드 환경의 Node 사용과 사용자에게 서버 실행을 요구하는 것은 구분한다.
- 단순 정리: 웹 빌드에서 health 호출과 서버 상태 표시, Codex 진입점·호출, SSE 연결을 제거한다. 웹 실행 명령도 API 기동 대기를 요구하지 않는다. 대체 health 서비스는 만들지 않는다.
- 문서·프로젝트·설정 조작은 공통 연결 계층의 브라우저 구현을 사용한다. Node 내장 모듈을 번들에 넣거나 HTTP API를 흉내 내는 서버를 추가하지 않는다.
- 설치된 Git·Codex CLI 실행은 웹 범위에서 제외한다. 허용한 루트 아래 새 폴더 만들기는 별도 권한으로 가능하지만 git init을 수행한 것처럼 표시하지 않는다.
- 기존 shadcn 토큰, 내부 스크롤, 상세창 설정, 언어 선택과 입력 보존 규칙을 유지한다. 웹 환경에 맞는 변경은 AGENTS와 안내에 함께 기록한다.
- Cloudflare Pages의 기본 SPA 처리를 사용하도록 최상위 `404.html`을 만들지 않는다. 정적 파일이 없는 경로도 앱으로 진입시켜 /, /intro, /all, /w/:id와 query/hash의 직접 진입·새로고침을 지원한다. `/intro` 라우트는 적용됐으며 실제 공개 호스팅의 회귀 검증은 배포 단계에서 한다. 경로형 라우팅을 유지하며 해시 라우팅 전환이나 GitHub Pages용 우회 처리는 추가하지 않는다.
- 선택 문서·티켓·표시 모드를 유지하되 문서 경로 대신 로컬 문서 ID를 URL에 사용한다. 현재 `?file=docs/...`는 새로고침 시 호스팅 서버에 전달되므로 그대로 유지하지 않는다. 권한 복원 전에는 주소를 유지하고 재연결로 이어간다. URL만으로 다른 PC의 로컬 폴더 권한이 전달되지는 않는다.
- 커스텀 도메인은 `kanban.giveit2.me`로 확정하고 연결·검증 후 정식 PWA 설치를 안내한다. 로컬 구현·preview에는 도메인 연결을 요구하지 않으며 앱에 운영 호스트명을 고정하지 않아 같은 루트 경로로 검증할 수 있게 한다. 현재 요청에서는 Cloudflare 프로젝트 생성·배포·DNS 변경·도메인 연결을 하지 않는다.
- 기존 localhost/`pages.dev`에서 `kanban.giveit2.me`로 접속 주소가 바뀌면 사이트 출처가 달라져 IndexedDB의 폴더 참조·보조 상태와 localStorage 설정이 자동 승계되지 않는다. 로컬 Markdown 원본은 그대로 두고 폴더 재연결과 보기 설정 재지정을 안내한다. 정식 설치와 이후 업데이트의 출처는 유지하며 도메인 연결이나 리다이렉트만으로 저장소가 이전된다고 설명하지 않는다. 자동 이전 도구는 이번 범위에 넣지 않는다.
- 문서의 상대 링크·이미지는 허용한 폴더 안에서 해석하며 웹 호스팅 경로로 잘못 요청하지 않는다. 범위 밖 파일은 추가 연결을 요구하고 외부 이미지는 명시적 요청 전 자동 로드하지 않는다. 원시 HTML·실행 가능한 리소스는 허용하지 않는다.
- 문서·경로·사용자 지시를 분석 도구나 오류 수집 서버로 전송하지 않는다. 외부 스크립트 의존을 제한하고 콘텐츠 보안 정책을 적용한다. 정적 웹 배포라는 이유만으로 개인정보 보호가 자동 보장된다고 표현하지 않는다.
- 검증 완료 전 기존 Node 실행 방식과 사용자 데이터는 유지한다. 실제 공개 배포와 기존 서버 구현 삭제는 별도 승인 사항이다.

### 8. 스킬 버전과 문서 호환성

| 구분 | 관리할 의미 | 담당 |
| --- | --- | --- |
| 스킬 버전 | 지침·템플릿·보조 도구의 개정 번호와 변경 이유 | AKL-10 |
| 문서 형식 버전 | plan/tickets/inventory의 구조·필드·상태·사용자 기록 의미 | AKL-10, AKL-11 |
| 웹앱 지원 범위 | 읽기 가능한 형식과 안전하게 수정 가능한 형식 | AKL-11 |
| 배포 출처·내용 해시 | 정확히 어느 배포물인지, 설치 이후 개인 수정이 있는지 | AKL-12 |

- 스킬의 문장·작업 지침만 개선되면 문서 형식을 불필요하게 올리지 않는다. 필수 필드·상태 의미 등 호환성에 영향을 주는 변경은 문서 계약 변경으로 관리한다. 스킬과 웹앱 버전 번호를 억지로 일치시키지 않는다.
- 동봉 SKILL.md의 metadata와 함께 배포되는 계약 자료에 스킬 버전, 지원 읽기/수정 형식, 신규 문서의 기본 형식, 공식 확인 출처를 명시한다. 필드명·초기 버전·문서 내 버전 표기법은 현재 문서 fixture를 기준으로 AKL-10에서 확정한다. 기존 문서의 메타데이터를 이번 계획 작업에서 일괄 삽입하지 않는다.
- 변경 이력과 기계가 읽는 배포 manifest에 변경 이유, 대상 이전 버전 범위, 업데이트 권고/호환성 때문에 필요한 경우, 문서 변환 필요 여부와 절차, 배포 태그/커밋 및 내용 해시를 담는다. 공통 계약에서 웹·도구·안내 정보를 만들거나 일치 검증해 서로 다른 버전 선언이 배포되지 않게 한다.
- 버전 표기가 없는 기존 문서는 현행 구조로 확인되는 경우에만 레거시 형식으로 처리한다. 일반 Markdown이나 손상 문서를 무조건 구버전으로 인정하지 않는다. 새로운 필드와 기존 사용자 지시 형식도 원문을 보존하며 처리한다.
- 새 웹앱과 동봉 작성 도구는 지원하는 이전 형식의 읽기·수정을 유지한다. 미지원 새 형식은 원문 열람과 안내를 제공하되 구조적 저장을 차단한다. 프롬프트 지침에만 의존하지 않고 공통 writer와 ticket-md/check-ledger의 판단을 테스트로 맞춘다.
- 새 스킬을 설치했다는 이유만으로 기존 프로젝트 문서를 최신 형식으로 바꾸지 않는다. 지원하는 기존 문서는 그 형식으로 수정하고, 지원하지 않는 형식이면 필요한 업데이트나 명시적 변환을 안내한다. 신규 문서도 확인되지 않은 웹앱 지원 범위를 추정해 최신 형식을 강요하지 않는다.
- 업데이트 확인과 적용을 분리한다. 설치·업데이트 요청 또는 형식 불일치 때 공식 배포 정보와 비교하며 매 작업마다 원격 확인하지 않는다. 오프라인·조회 실패는 '최신 여부 미확인'이지 '최신'이나 '호환'이 아니다. AI에 주입되는 설치 요청도 이 구분을 지킨다.
- 설치/업데이트는 정확한 배포물과 전체 파일을 먼저 확인하고 기존 설치본의 출처·해시·수정 여부를 비교한다. 개인 수정 또는 출처 불명 설치본은 자동 덮어쓰기하지 않는다. 승인된 교체에도 백업과 실패 복구를 제공하고 다운로드/검증 실패 전에 기존 폴더를 지우지 않는다.
- 개인 전역 스킬은 본 작업의 변경·테스트 대상이 아니다. 임시 HOME/CODEX_HOME 등 격리 경로의 테스트 설치본만 사용한다. 자동 자기 업데이트, 원격 설치 스크립트의 무조건 실행, 기존 문서 자동 변환은 도입하지 않는다.

### 후속 티켓 순서

- AKL-11: 공통 parser/writer와 보조 도구에서 구버전 보존과 미지원 형식 저장 차단을 검증한다.
- AKL-12: 버전 고정 배포 자료와 안전한 설치·업데이트를 마련한다.
- AKL-13: 승인된 화면에 설치 요청 복사, 작업 흐름, 버전·호환성 안내를 연결한다.

- AKL-15: 승인된 소개 랜딩을 같은 앱의 `/intro`에 적용하고 시작 화면과 연결한다. 시안 생성만으로 착수하지 않는다.

AKL-01과 AKL-05의 초기 구현·검증 이력은 유지한다. 후속 계획이 생겼다는 이유로 기존 상태를 완료하거나 진행률을 올리지 않으며, 신규 티켓도 구현 완료와 구분한다.

## 검증 계획

- 공통 분석·수정 함수는 기존 정상·레거시 문서 fixture와 개행·다른 티켓 보존 회귀 테스트로 검증한다.
- 여섯 문서 정렬의 양 방향, 묶음 내부 순서, 누락·동률 값, DONE 완료 시각 누락, 전체보드 필터 안의 수동 순서를 이전 전후 같은 fixture로 비교한다. 보기 조작만으로 Markdown 내용·수정 시각이 바뀌지 않아야 한다.
- 폴더 동일성·중첩·권한 상태·부분 실패, 저장 충돌과 입력 보존, 여러 탭 및 외부 수정은 자동 테스트와 실제 로컬 파일 검증을 구분해 기록한다.
- 원문과 해시의 일치, 파일 교체, 저장 완료 직후 재읽기 실패, Markdown 저장 성공 후 순서 저장 실패를 별도로 검증한다. 실패 복구나 재시도로 사용자 지시가 중복되지 않아야 한다.
- 문서 수·크기와 탭 수를 기록하며 파일 읽기 횟수·동시성·갱신 시간을 측정한다. 단일 문서 수정 때문에 매번 모든 본문을 다시 읽지 않아야 한다.
- 데스크톱 Chrome과 API 서버가 없는 별도 정적 실행 환경에서 폴더 선택부터 원본 저장·재연결·경로 복원까지 확인한다. API를 mock한 테스트만으로 서버 없는 실행을 통과 처리하지 않는다.
- Cloudflare Pages의 SPA 처리 조건에 맞춘 산출물과 직접 진입·새로고침 동작을 검증한다. 실제 Pages 공개와 `kanban.giveit2.me` 연결 후 확인은 별도 승인된 배포 단계로 구분하고 미실행 상태를 통과로 기록하지 않는다.
- 앱을 연 뒤 네트워크를 끊어 로컬 조회가 대기하지 않는지 확인하고, 직접 진입 요청·문서 링크·이미지에 실제 로컬 경로나 내용이 실리지 않는지 검사한다.
- 본인 PC 외 사용자 환경에서 Chrome·OS 버전, 실행 버전과 결과를 기록한다. 비주얼 확인은 사용자 주도이며 Edge 등 타 브라우저나 모바일 스모크를 필수 완료 조건으로 추가하지 않는다.
- AI 설치 검증은 기존 개인 스킬을 덮어쓰지 않는 격리된 테스트 범위에서 한다. 형식 검사 통과와 실제 AI 호출 결과를 별도로 기록한다.
- 시안의 재열기 위치와 캡처, 사용자 승인 여부를 남긴다. 시안 생성이나 자동 UI 검사 통과를 디자인 승인으로 대신하지 않는다.
- 버전별 문서 fixture로 읽기뿐 아니라 상태·지시 수정 후의 다른 필드·티켓·개행 보존을 확인한다. 미지원 형식·버전 없음·손상·잘못된 버전 표기와 두 실행 모드/보조 도구의 판정을 비교한다.
- 격리된 설치 경로에서 최초 설치, 동일 버전, 새 버전, 개인 수정, 출처 불명, 네트워크/검증 실패와 교체 중 실패 복구를 검사한다. 버전 안내·manifest·ZIP·GitHub 설치 대상의 출처와 계약이 일치해야 한다.

## 미결정 사항

- 없음. 시작 화면과 소개 랜딩은 후속 지시에 따라 실제 적용했다. 최신 결정은 실제 캡처가 아닌 마크업 데모이며 내부 보드 재디자인은 적용하지 않는다. 남은 버전 계약·공유 이미지·호스팅 검증은 각 티켓의 구현/검증 작업이다.

Open Design 접근 확인, 버전 필드 설계와 설치 경로 검증은 각 티켓의 조사·설계 작업이다. 선택을 위한 시안이 나오기 전에 사용자에게 세부 치수나 설치 구현을 결정하도록 요구하지 않는다. 상세 병합 편집기와 설정 이전 도구는 이번 MVP에 포함하지 않는다.
