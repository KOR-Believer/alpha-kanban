### AKP-02. 인터넷 없이 앱을 다시 열고 로컬 문서를 사용하기

Status: IN_PROGRESS
Progress: 75%
Repository:

- `alpha-kanban/apps/web`
- `alpha-kanban/scripts`

Priority: P1
Type: Feature
Depends on:

- AKP-01

목표:

- 온라인 준비를 마친 사용자가 인터넷을 끊고 브라우저를 종료한 뒤에도 앱을 다시 열어 로컬 문서를 읽고 수정한다.

현재 문제:

- 문서 처리는 로컬이지만 앱 파일은 호스팅에서 받아야 한다. 일부 폰트만 로드한 탭의 오프라인 사용으로 미방문 화면과 한글 글자의 재실행을 보장할 수 없다.

구현 범위:

- 검증된 Workbox 계열 도구와 현재 Vite의 호환성을 확인해 고정 /sw.js와 명시적인 앱 자산 목록을 구성한다. 일반 개발 서버에서는 등록하지 않는다.
- HTML·필수 JS/CSS 청크·아이콘·지원 폰트 묶음·안내·한 버전의 동봉 스킬 자료를 완결된 배포 단위로 확보한다. 크기·용량 부족·다운로드 실패를 처리하고 준비 전 성공 안내를 하지 않는다.
- 오프라인 Start·소개·전체보드·프로젝트·문서/티켓 직접 링크, 폴더 접근·검색·필터·정렬·사유/수동 지시 저장·로컬 상대 리소스를 지원한다. 기존 폴더 권한 재허용과 파일 저장 보호를 유지한다.
- SPA 탐색과 자산 요청을 구분하고 sw.js·최신 배포 정보·복구 페이지는 앱 fallback과 오래된 캐시에서 제외한다. CSP의 동일 출처 자산 통신·워커 실행 허용 범위를 최소 조정한다.
- 프로젝트 원문을 서비스 워커 캐시에 복제하지 않는다. 외부 이미지·AI·GitHub·미다운로드 OS 클라우드 파일은 오프라인 보장 대상이 아니며 실패가 로컬 작업을 막지 않게 한다.

제외 범위:

- 최초 접속부터 인터넷 없는 설치, 원격 AI·외부 사이트의 오프라인 제공, 상시 폴더 감시·백그라운드 편집

완료 기준:

- [x] 네트워크를 차단한 격리 Chrome을 종료·재실행해 미방문 앱 경로와 동봉 폰트 자산을 사용할 수 있다.
- [ ] 실제 로컬 폴더의 문서 열기·상태 변경·지시 추가·외부 변경 충돌·복구 흐름이 오프라인에서 동작한다.
- [x] 자산 확보 실패·손상 파일·SPA HTML 대체 응답이 기존 정상 앱 캐시와 사용자 데이터를 삭제하지 않는다.
- [ ] 실제 Chrome의 CacheStorage 용량 부족에서도 이전 정상 앱을 유지한다.
- [x] 로컬 파일 핸들로 읽고 저장하며 검증 시나리오에서 Markdown·사용자 지시 업로드와 API 호출이 없다.
- [ ] 실제 OS 폴더의 상대 리소스와 외부 리소스 오프라인 실패를 확인한다.

검증:

- [x] 완결된 캐시 목록·손상 자산·HTML fallback 거절·복구 자산 재다운로드·CSP 및 정적 빌드 검사
- [x] OPFS 파일 핸들을 사용하는 Chrome 오프라인 종료/재실행·미방문 경로·지시 저장 및 네트워크 기록

- 2026-10-18: Workbox 완결 precache와 자산 무결성 검사를 구현했다. 현재 스킬 ZIP 하나와 동봉 폰트를 보관하며 개발 서버에는 등록하지 않는다. Chrome 종료 후 오프라인 경로 진입·OPFS 저장, HTML로 바뀐 JS 거절을 확인했다. 실제 OS 폴더·CacheStorage 용량 부족 검사는 남아 있다.

Status: IN_PROGRESS
Progress: 75%
Repository:

Priority: P1
Type: Feature

목표:

현재 문제:

- 현재 앱에는 배포 확인·워커 전환 제어가 없다. 스킬 번들 해시만으로 웹앱 버전이나 문서 호환성을 판단할 수 없다.

구현 범위:

- 현재 웹앱 버전/빌드 ID와 정적 배포 정보를 분리해 비교한다. 온라인 시작·간격을 둔 복귀/재연결·활성 창 약 30분·수동 확인을 제안 기본값으로 두고 중복·실패 호출을 제한한다.
- 발견·다운로드 중·준비 완료·보류·확인 실패를 구분하며 사용자 확인 후 적용한다. 모든 창을 닫은 다음 실행에는 준비된 버전이 적용될 수 있다. 오프라인 최신 여부 미확인을 편집 금지로 바꾸지 않는다.
- 모든 관련 탭/설치 창의 초안과 저장 상태를 확인하고 전환 동안 새 쓰기를 차단한다. 저장 종료/재읽기 검증, 응답 없는 창, 사용자 저장·취소 결정과 초안 복원을 처리한다.
- 새 워커가 이전 코드의 열린 창을 무조건 장악하거나 controllerchange만으로 강제 새로고침하지 않게 한다. 부분 다운로드 실패는 이전 배포를 유지하고 전환 후 소유 구자산만 정리한다.
- 웹앱·스킬·문서 형식·저장 구조의 버전을 구분한다. 스킬/형식 안내는 AKL-10~13의 계약을 재사용하고 그 구현 전에는 알 수 없는 값을 추정하지 않는다. 이 연결 부분은 기존 티켓 완료가 선행되어야 하며 기본 웹앱 업데이트와 분리해 검증한다.
- 사용자에게 현재 버전·업데이트·실제 변경 사항·복구 동작만 안내한다. 개발 상태 설명이나 개인 설치 스킬의 자동 판정·업데이트를 넣지 않는다.

제외 범위:

- 개인 스킬 설치/덮어쓰기, 새 호환성 계약 중복 정의, 푸시 알림 서버, 종료된 앱의 정시 실행 보장

- [x] 업데이트 확인·준비·나중에·적용·다음 시작 상태를 구분하며 불완전한 다운로드 시 이전 정상 버전을 유지한다.
- [x] 초안·파일 저장 중·두 탭과 설치 창·응답 없는 창의 업데이트를 조율하고 기존 내용과 설정을 보존한다.
- [x] 최신 배포 정보를 앱 캐시 밖에서 조회하고 오프라인 로컬 작업을 허용한다.
