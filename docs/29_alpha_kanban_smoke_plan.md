## 목표와 이유

사람이나 Computer Use / browser use 에이전트가 실제 앱을 조작하며 확인할 스모크 기준을 TC(Test Case)로 정리한다. 최초 개발과 이후 회귀 검증에서 같은 사용자 흐름을 다시 수행하고, TC의 현재 정의와 각 실행에서 관찰한 결과를 구분해 무엇을 어떤 환경에서 확인했는지 Markdown으로 남긴다.

자동 테스트 코드는 기존 개발·회귀 검증에서 계속 관리한다. 이 문서는 그 테스트 목록을 옮겨 적는 용도가 아니며, 자동 테스트의 통과로 실제 앱 조작과 관찰을 대신 판정하지 않는다.

화면은 스프레드시트처럼 회차별 시트를 바꿔 보는 형태다. `스모크` 시트에는 결과가 없는 공통 TC 목록을, 각 회차 시트에는 실행 당시 기준과 결과·메모를 보여 준다. 회차끼리 비교하는 화면은 별도로 제공한다.

계획과 Local Codex 시안을 바탕으로 문서 규약, 읽기, 편집·비교, 안내·실사용 검증 순으로 구현한다. 각 단계의 범위와 완료 기준은 해당 티켓을 따른다. 개인 설치 스킬 교체와 커밋·배포는 별도 요청으로 진행한다.

## 영향 범위

- `packages/shared/src/index.ts`, `packages/shared/src/documents.ts`: 새 문서 유형과 TC·회차의 식별 및 해석 계약.
- `apps/web/src/components/documents/`, `apps/web/src/App.tsx`: 기존 문서 묶음에서 스모크 진입, 회차별 시트와 별도 비교 보기.
- `apps/web/src/browser/`: 연결된 문서 탐색, 원본 읽기, 회차 연결, 확정한 편집 범위의 저장 안전장치.
- `apps/web/src/components/MarkdownDocumentReader.tsx`, 기존 Markdown·표·폼 래퍼: 메모와 상세 기준 표시.
- `skills/implementation-ledger/`: 스모크·실행 기록의 문서 양식과 작성·검증 지침. 사용자의 개인 설치 스킬은 별도 대상이다.
- `apps/web/src/i18n/messages.ts`, 의미 기반 스타일 토큰과 문맥별 안내: 한영, 라이트·다크, 좁은 화면 및 키보드 탐색.

## 확인한 현재 상태

- `markdownFileTypeSchema`와 `inferMarkdownFileType`은 기존 네 유형과 스모크·실행 기록을 구분한다. 공통 읽기 모델은 당시 기준·결과·메모·정정 기록과 원문 범위를 보존하며, 브라우저와 동봉 형식 검사기가 같은 해석을 사용한다.
- 문서 목록·유형 필터에 스모크·실행 기록을 연결했다. 현재 열람은 공통 Markdown 읽기를 유지하며, 전용 시트 UI는 ASM-03에서 구현한다.
- 스모크·실행 기록의 템플릿과 `check-smoke.mjs`를 동봉한다. 기존 스킬 진입 지침은 그대로 두고 작성·수행 안내의 진입 연결은 ASM-07에서 다룬다.
- 새 문서의 Document-ID와 선택적인 Owner, 문서 상대경로, 저장 안전장치, 공통 Markdown 읽기 규칙이 이미 있다. 새 유형도 이 기반을 사용한다.
- 기존 티켓 진행률과 테스트 결과는 의미가 다르다. 스모크 결과를 개발 티켓 상태나 기존 완료율에 자동 합산하지 않는다.

## 할 일과 선택한 방향

### 1. 공통 TC와 실행 기록을 분리한다

- 스모크 문서 하나에 반복 실행할 TC 목록을 둔다. 이 문서에는 실행 결과를 저장하지 않는다.
- 스모크 문서 하나와 여러 실행 기록 문서를 1:n으로 연결한다. 각 회차는 별도 Markdown 문서이며, 화면에서는 하단 시트 탭 하나로 표현한다.
- 플랜과 함께 작성한 스모크는 같은 문서 묶음에서 `계획 · 티켓 · 인벤토리 · 스모크`로 접근한다. 플랜 없이 통합 테스트 지시로 만든 스모크도 단독으로 사용할 수 있다.
- 이후 다른 작업에서 회귀 검증이 필요하면 기존 TC를 다시 실행한다. 다른 플랜용으로 TC 정의를 복사해 별도로 관리하지 않는다.
- 플랜의 완료와 TC의 유효성은 별개다. 플랜이 끝나도 해당 TC를 계속 실행할 수 있다.
- 실행 기록은 어떤 스모크 문서와 어떤 TC 개정판을 실행했는지 명시한다. 경로나 화면상 회차 이름만으로 관계를 추정하지 않는다.

#### 수행·판정 원칙

- TC는 사람이 읽고 그대로 따라 할 수 있는 사전조건, 앱에서의 조작 순서, 관찰 가능한 기대 결과로 작성한다. 특정 에이전트나 좌표·선택자 문법에 종속시키지 않는다. 사람, Computer Use 에이전트, browser use 에이전트가 같은 기준을 사용할 수 있어야 한다.
- 수행자는 해당 회차에 기록한 실제 대상 앱·빌드·환경에서 화면을 열고 조작한 뒤 결과를 확인한다. browser use의 요소 탐색·클릭·입력·화면 내용 읽기도 사용할 수 있다. 확인할 조작을 내부 상태 주입이나 API 호출로 우회한 결과는 그 조작의 통과 근거가 아니다.
- 코드 검토, 빌드, 단위·통합·E2E 자동 테스트의 성공 요약, 가상 DOM·가짜 핸들 검사만으로 TC를 통과 처리하지 않는다. 자동 테스트 결과는 참고 근거로 남길 수 있지만, 해당 TC의 실제 수행·관찰 기록을 대신하지 않는다.
- 통과는 해당 TC의 필수 절차를 수행하고 기대 결과를 실제로 확인했을 때만 기록한다. 실제 결과가 기대와 다르면 실패와 관찰 내용을 남긴다. 시작하지 않은 항목은 미실행, 권한·환경·도구 제약으로 확인하지 못한 항목은 진행 불가와 미확인 부분·사유를 남기며 통과나 임의의 제외로 바꾸지 않는다.
- 화면 배치·잘림·시인성은 렌더링된 화면으로, OS 폴더 선택·권한·재시작 동작은 해당 실제 환경에서 확인한다. DOM에 요소가 있다는 사실이나 합성 환경의 결과로 이 확인을 대신하지 않는다. 필요한 캡처·증거와 실제 관찰 내용을 남겨 판정 근거를 다시 볼 수 있게 한다.
- 칸반은 TC와 실행 기록을 관리·표시한다. 외부 에이전트는 사용자의 수행 지시에 따라 TC를 읽고 앱을 조작한 뒤 실행 기록을 작성할 수 있다. 문서 열람이나 회차 추가만으로 테스트 또는 에이전트를 실행하지 않는다.

### 2. TC의 개정·폐기와 실행 결과를 구분한다

- TC에는 문서 내 안정적인 ID를 둔다. 식별은 스모크 Document-ID와 TC ID의 조합으로 하며, 폐기한 TC ID는 재사용하지 않는다.
- 사전조건·실행 절차·기대 결과의 의미가 바뀌면 TC 개정 번호와 변경 이유를 기록한다. 동일 의미의 오타·표현 교정만으로는 번호를 올리지 않으며, 같은 개정 번호라도 보존된 기준이나 공통 조건이 다르면 차이를 표시한다.
- 더 이상 유효하지 않은 TC는 폐기 이유와 원래 정의를 남긴다. 폐기는 과거 실행 결과를 지우는 작업이 아니다.
- 새 회차는 그때 선택한 유효 TC와 해당 개정판을 기준으로 시작한다. 이전 회차의 통과 결과를 복사하지 않고 모두 미실행에서 출발한다.
- 진행 중인 회차를 포함해, 생성 후 원본 TC가 바뀌어도 해당 회차의 목록·기대 결과를 조용히 바꾸지 않는다.
- 과거의 통과는 당시 TC 개정판·대상 빌드·환경에서의 관찰이다. 현재 개정판이나 새 빌드가 통과했다는 뜻으로 표시하지 않는다.
- 실패만을 이유로 기대 결과를 바꾸지 않는다. 제품 요구가 달라졌는지, 구현이 기준을 어겼는지 판단한 뒤 TC 개정 또는 결함 기록으로 구분한다.

#### 회차 종료와 사용자 정정

- 회차는 사용자가 명시적으로 종료한다. 실패·진행 불가·미실행이 남아 있어도 종료할 수 있으며, 종료할 때 TC 결과를 통과나 제외로 바꾸지 않는다. 미실행이 남으면 남은 항목과 종료 사유를 기록한다.
- 회차의 진행 중·종료 여부와 TC 결과 집계를 구분한다. 종료된 회차를 전체 통과로 표시하지 않는다.
- 사용자는 종료된 회차도 별도 재개 절차 없이 결과를 정정할 수 있다. UI에서 결과를 바꿀 때 현재 결과와 변경 날짜·변경 전후·사용자 메모를 함께 저장하고, 기존 관찰·증거·변경 기록은 보존한다. 과거 수행 기준은 이 정정으로 바꾸지 않는다.
- 수정 기록의 기본 표시는 `사용자 수정`이다. 소유자 구분을 사용하는 환경에서 실제 수정자의 사용자 ID를 확인할 수 있으면 `@alphago 수정`처럼 표시한다. 문서 소유자나 `@` 폴더 이름으로 수정자를 추정하지 않으며, 확인할 수 없으면 기본 표시를 사용한다.
- 에이전트는 사용자의 정정을 읽고 현재 결과를 존중하되, 자신의 재수행·검증 결과로 보고하지 않는다. 실제로 확인하지 못한 부분은 그대로 구분한다.
- 새 빌드나 다른 환경에서의 재검증은 새 회차로 남기며, 과거 회차의 오기 정정으로 처리하지 않는다.

### 3. 회차별 시트를 기본 화면으로 삼는다

```text
노트 검색 스모크                               [회차 비교]

[현재 시트의 Markdown 메모 · 펼치기]

TC       제목          절차 · 기대 결과       결과       메모
TC-001   검색 결과 정렬 …                     통과       …
TC-002   빈 결과 안내   …                     미실행

[스모크] [1차 · 최초 검증] [2차 · 회귀 검증] [+ 회차]
```

- `스모크` 탭은 현재 TC 정의를 보여 준다. 결과가 없다는 것을 모두 실패하거나 미실행인 회차처럼 표현하지 않는다.
- TC의 사전조건·절차·기대 결과·개정·폐기는 외부 AI/Markdown으로 관리한다. 웹은 회차 생성·종료, 결과 변경, 상단 및 TC별 메모 편집을 제공하며 TC 정의 편집기는 이번 범위에 넣지 않는다.
- 회차 탭은 비슷한 열 구성으로 당시 TC 정의와 결과·개별 메모를 보여 준다. 부분적으로 채운 진행 중 회차도 정상 상태다.
- 표의 기본 열은 TC ID, 제목, 절차·기대 결과 요약, 결과, 메모다. 긴 절차·증거는 행의 상세 영역에서 펼칠 수 있게 한다.
- 하단의 추가 동작은 새 TC 문서가 아닌 새 실행 회차를 뜻한다. 실제 구현에서는 당시 수행 기준과 미실행 결과를 담은 별도 실행 Markdown을 생성한다. 시안에서는 같은 흐름을 메모리 안에서 확인한다.
- 회차의 이름과 날짜·실행 대상·환경을 확인할 수 있게 하되, 모든 식별 정보를 셀마다 반복하지 않는다.
- 시트 탭이 많아지면 가로 스크롤 또는 회차 목록으로 이동할 수 있게 한다. 현재 탭과 추가 동작이 사라지지 않게 한다.
- 기존 앱의 전역 하단 문서 상태바와 회차 탭 줄을 구분한다. 상태바는 프로젝트의 문서 탐색, 회차 탭은 열린 스모크 안의 실행 선택을 맡는다.
- 시트 전환 후에도 각 시트의 메모·결과·스크롤 맥락을 유지한다. 실제 저장과 미저장 입력 전환은 확정한 편집 범위 안에서 기존 초안 보호와 함께 설계한다.

### 4. 각 시트 상단에 자유 Markdown 메모를 둔다

| 위치 | 주된 내용 |
| --- | --- |
| 스모크 시트 | 검증 목적, 공통 사전조건, 테스트 데이터, 공통 주의사항 |
| 회차 시트 | 이번 실행의 목적, 환경 특이사항, 진행·중단·재개 메모, 전체 관찰 |
| TC별 메모 | 실제 관찰, 실패 상황, 증거와 관련 링크 |

- 정해진 보고서 항목을 강제하지 않는다. 제목·목록·링크 등을 자유롭게 쓸 수 있다.
- LLM은 상단 메모를 회차 전체의 작업 맥락으로 읽는다. 메모 속 문장으로 구조화된 TC 결과를 추정하거나 덮어쓰지 않는다.
- TC별 관찰 메모에는 실제로 수행한 조작과 관찰한 결과를 남긴다. 기대 결과를 그대로 반복하거나 자동 테스트 성공만 적어서 실제 수행 기록을 대신하지 않는다.
- TC 결과의 집계는 결과 필드에서 계산한다. 메모와 별도로 수동 관리하는 중복 진행률 표는 만들지 않는다.
- 공통 사전조건이 바뀌어도 과거 실행의 의미가 유지되어야 한다. 실행 당시 기준 보존에는 필요한 공통 맥락도 포함한다.
- 시안에서는 상단 메모를 몇 줄로 미리 보고 펼치는 형태를 검토한다. 원문은 생략 없이 보존한다.

### 5. 회차 비교는 별도 보기로 제공한다

- 기본 화면은 한 회차의 작업에 집중하고, 사용자가 비교할 회차를 선택했을 때 별도 표를 연다.
- 같은 TC ID를 맞춰 결과와 메모를 비교한다. 개정 번호가 다르면 기준이 달라졌음을 함께 표시한다.
- 새로 추가된 TC, 해당 회차에 포함되지 않은 TC, 그때는 유효했지만 현재 폐기된 TC를 구분한다. `회차에 없음`을 실패·미실행·제외 처리 결과와 섞지 않는다.
- 비교 화면에서 현재 TC 내용으로 과거 행을 다시 구성하지 않는다. 과거 결과와 당시 기준을 함께 열 수 있어야 한다.
- 첫 구현은 두 회차 비교로 한정한다. 세 회차 이상을 동시에 비교하는 기능은 이번 범위에 넣지 않는다.

### 6. Markdown 계약과 과거 기준 보존을 설계한다

웹 편집 범위와 과거 기준 보존 방식은 아래 내용으로 확정한다. 정확한 필드·경계·정상/오류 판정은 ASM-01의 문서 규약과 예제를 기준으로 한다.

- 스모크는 `_smoke.md`, 실행 기록은 `_smoke_run.md`를 사용한다. 원본 스모크의 Document-ID로 회차를 연결하며, 회차마다 고유 Document-ID를 발급한다. 파일의 문서 번호와 회차 표시 번호는 별개다.
- 스모크 헤더와 각 TC에는 현재 문서 규약과 어울리는 한 줄 필드를 사용한다. 별도 YAML 파일이나 YAML title을 추가하지 않는다.
- 스모크와 실행 기록 각각의 Markdown 템플릿을 마련한다. 시안의 공통 TC 목록, 회차 식별·환경·진행 상태, 당시 수행 기준, 결과, 상단 메모, 개별 관찰·증거 및 사용자 수정 기록을 어디서 읽고 저장하는지 대응시킨다. 진행 집계처럼 계산 가능한 표시는 별도의 중복 관리 필드로 만들지 않는다.
- TC의 기본 내용은 제목, 한 줄 요약, 사전조건, 실제 앱의 수행 절차, 관찰 가능한 기대 결과다. 실행 기록에는 수행자·수행 방식(사람 / Computer Use / browser use), 실행 대상·환경·일시, TC 개정판, 결과, 실제 관찰·증거와 확인하지 못한 부분·사유를 담는다. 현재 Result와 추가된 LOG 기록을 함께 저장하고 실제 수행·사용자 정정·결과를 바꾸지 않는 메모 기록을 구분한다.
- 결과 값은 `NOT_RUN / PASS / FAIL / BLOCKED / SKIPPED`이며 각각 미실행·통과·실패·진행 불가·제외로 표시한다. TC의 `ACTIVE / RETIRED`와 회차의 `OPEN / CLOSED`는 별도다.
- 실행 기록에는 회차 생성 당시 선택한 TC 정의·개정판과 필요한 공통 사전조건을 함께 저장한다. 원본 TC를 수정·폐기하거나 원본 문서가 없어져도 실행 기록에서 당시 수행 기준을 읽을 수 있어야 한다. 이는 다른 플랜용 TC 사본 관리가 아니라 해당 실행의 근거 보존이다.
- Git 이력 조회를 과거 수행 기준 열람의 필수 조건으로 두지 않는다. 커밋 전 실행, 브라우저 단독 읽기, 원본 변경 및 실행 기록 단독 전달에서도 당시 기준을 해석하는지 확인한다.
- 원본 누락·중복 ID·해석 불가 시 내용을 임의 연결하거나 다시 쓰지 않는다. 읽을 수 있는 Markdown은 계속 보여 주며, 관계나 편집이 불가능한 이유만 해당 동작에서 설명한다.
- 결과·메모·종료·사용자 정정을 UI에서 저장할 때 기존 해시·mtime 검사, 파일별 잠금, 복구 원본, 저장 후 재읽기 및 미저장 초안 보호를 재사용한다. 표를 편집한다고 외부 테스트나 AI를 실행하지 않는다.
- 최초 문서 생성·티켓 추가용 CLI의 신설·확장은 우선 보류한다. 기존 템플릿을 따라 에이전트가 작성하고 보조 도구로 문맥·메타데이터·형식을 검사하는 흐름을 유지한다. 스모크 템플릿과 검증 규칙은 마련하되 형식 검사만으로 수행 내용의 진위를 판정하지 않는다. 웹에서 별도 실행 문서를 만드는 회차 생성 기능은 이 CLI 보류와 별개로 범위에 포함한다.

### 7. 시안부터 단계적으로 검토한다

1. **계획과 시안**: 합성 예제로 스모크 정의, 종료된 최초 회차, 진행 중인 회귀 회차, 새 미실행 회차, 두 회차 비교의 Local Codex 시안을 검토하고 확정한 범위를 기록한다. 실제 파일·프로젝트 권한·스킬·배포에 영향을 주지 않는다.
2. **문서 규약과 템플릿 — ASM-01**: 확정사항을 반영한 스모크·실행 기록 템플릿과 Markdown 예시를 마련한다. 시안 UI의 정보·저장 항목을 대응시키고, 실제 조작·관찰에 따른 수행·판정 지침, TC·회차 식별, 개정·폐기, 당시 기준 보존, 회차 종료, 사용자 정정, 파싱 실패 처리 및 검증 규칙을 구체화한다. 문서 검증기는 형식을 확인하며 실제 TC 수행이나 통과를 증명하지 않는다.
3. **문서 인식과 읽기 — ASM-02·03**: 새 유형의 탐색·문서 묶음 진입·회차 연결·표/Markdown 읽기를 먼저 검증한다. 기존 플랜·티켓·인벤토리·일반 Markdown 회귀를 포함한다.
4. **편집과 비교 — ASM-04·05·06**: 확정한 회차 생성·종료, 결과·메모 편집, 사용자 정정 기록, 두 회차 비교와 저장 보호를 구현한다. 실제 구현 요청 전에는 시안의 조작을 파일 쓰기로 연결하지 않는다.
5. **사용 안내와 실사용 검증 — ASM-07·08**: 실제 가능한 기능에 맞춰 스킬·가이드·투어를 작성하고, 별도 스모크 폴더를 연결한 실제 앱에서 사람 또는 Computer Use / browser use 에이전트가 최초 실행→TC 개정→회귀 실행→과거 확인을 수행한다. 자동 테스트 결과는 별도로 확인하고 실제 조작을 대체하지 않는다.

시안은 내부 컴포넌트를 우선 참고하고, 없는 구성만 기존 토큰에 맞춰 제안한다. 밀도 있는 업무용 표, 한영 글꼴, 라이트·다크, 좁은 보드 영역, 고정 헤더·열 및 키보드 접근을 검토한다. 화면의 가상 기능은 합성 데이터 안에서만 동작한다.

## 성공을 확인할 방법

- 같은 TC를 사람과 Computer Use / browser use 에이전트가 읽고, 실제 앱에서 해야 할 조작과 확인할 결과를 이해할 수 있다. 실행 기록에서 수행자·방식·대상·환경·실제 관찰을 확인할 수 있다.
- 자동 테스트가 통과했어도 실제 조작을 하지 않은 TC는 미실행으로 남는다. 필요한 권한창·환경 등에 접근할 수 없어 수행을 마치지 못한 항목은 진행 불가로 기록하며, 통과로 집계하지 않는다.
- 플랜과 함께 있는 스모크 및 플랜 없는 단독 스모크를 각각 열 수 있다.
- 스모크 탭에는 결과가 없고, 새 회차는 모든 실행 대상이 미실행이다. 회차를 전환하면 각자의 결과·상단 메모·TC별 메모가 보인다.
- 웹에서는 회차 생성·종료와 결과·메모 편집을 할 수 있고 TC 정의는 외부 AI/Markdown으로 관리한다. 스모크·실행 기록 템플릿이 시안의 표시·저장 항목을 담고, 문서 규약으로 각 항목을 읽고 쓸 수 있다.
- 원본 TC 절차·기대 결과·공통 조건을 바꾸고 일부 TC를 폐기해도 이전 회차의 기준·목록·결과가 자동으로 바뀌지 않는다. 원본 문서나 Git 이력이 없는 상태에서도 실행 기록의 당시 기준을 읽을 수 있다.
- 실패·진행 불가·미실행이 남은 회차를 사용자가 명시적으로 종료할 수 있다. 종료해도 기존 결과와 미실행 수가 유지되며 전체 통과로 표시하지 않는다.
- 종료된 회차의 결과를 사용자가 정정하면 현재 결과와 날짜·변경 전후·메모가 함께 저장되고, 기존 관찰·기록 및 당시 기준은 보존된다. 기본 `사용자 수정`과 확인된 수정자 ID에 따른 표시가 구분되며 문서 소유자를 수정자로 대입하지 않는다.
- 두 회차 비교에서 개정판이 다른 결과와 회차에 없는 항목을 구분한다. 이전 통과를 현재 통과로 오인시키지 않는다.
- 실패·진행 불가·제외·미실행을 색상뿐 아니라 문자로 구분하고, 긴 메모를 펼쳐 읽을 수 있다.
- TC가 많거나 문장이 길어도 표 머리글·현재 회차·중요 제어가 접근 가능하다. 1440px 데스크톱, 900px 안팎의 좁은 영역, 다크 모드에서 읽기와 시트 전환을 확인한다.
- 시안 검증과 실제 파일 저장·OS 권한 검증을 구분한다. 실제 저장 구현 때는 외부 파일 변경, 저장 중단, 복구, 초안 전환의 기존 보호를 검증한다.
- 기존 문서 표시·티켓 진행률·소유자 필터·검색·문서 패널 동작을 회귀 검증한다. 스모크 열람만으로 기존 문서에 필드나 결과를 추가하지 않는다.

## 확인·결정이 필요한 사항

- 없음

## 제외 범위

- TC 정의를 다른 플랜으로 복사하여 별도로 관리하는 기능.
- 웹에서 TC 정의를 작성·개정·폐기하는 편집기와 세 회차 이상 동시 비교.
- 최초 문서 생성·티켓 추가용 CLI의 신설·확장. 기존 작성·검증 도구는 유지한다.
- 칸반 앱 안의 테스트 자동 실행기와 외부 에이전트 실행·제어 기능, CI 연결, 스케줄링, 외부 테스트 관리 서비스 연동. 외부에서 사람이나 Computer Use / browser use 에이전트가 TC를 수행하고 기록하는 사용 방식은 포함한다.
- 스프레드시트 수식·매크로·엑셀 파일 입출력. 시트 비유는 회차 탐색과 표 읽기·기록에 사용한다.
- 기존 문서의 자동 변환, 과거 실행 결과 추정, 개인 스킬 교체, 원본 업무 문서를 이용한 실험.
